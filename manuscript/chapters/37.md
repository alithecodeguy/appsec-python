A configuration file contains `DEBUG = True` in a comment, a string and an assignment. Which occurrence should a reviewer inspect? Can you find it without importing the file, and can your report admit when source alone is insufficient?

This chapter builds a small Python AST checker, packages it as a wheel and tests its installed command. It reports exact locations for direct debug writes and gives a separate review result for a dynamic value. The tool is deliberately narrow enough that another engineer can explain its rule and its limits.

You need Python modules, classes, file handling, exceptions, chapter 8's JSON and chapter 12's tests. Chapter 29 showed why a static finding needs a code path. Chapter 35 separated configuration source from loaded runtime settings. Chapter 36 used a tested correction without claiming that the whole deployment had been repaired. We will make those boundaries part of this tool's public interface.

By the end, you will be able to:

- Compare token text with an abstract syntax tree.
- Write an `ast.NodeVisitor` that reports a specific assignment target.
- Explain the difference between a literal match, an unresolved expression and unsupported syntax.
- Package a console entry point and inspect the resulting wheel.
- Test stable JSON, source locations, exit codes and the installed artifact.

The edition targets **CPython 3.12.14** and **Django 6.1.3**. This standalone project ran on **CPython 3.12.14**. Its builder used **pip 26.2.2**, **setuptools 84.2.1** and **wheel 0.48.0**. A fresh installation environment used **pip 25.0.1**. All **18 test methods** passed against the installed wheel, and both installed entry forms were exercised outside the source tree. Django runtime behavior is outside this standalone source-tool exercise.

## Project and rule contract

The command is `casebook-config-check`; the distribution is `casebook-config-check`; the Python import package is `casebook_check`. A command, a distribution name and an import name need not have identical spelling. Keep their mapping explicit.

The checker reads explicitly named local Python files. It parses their contents and never imports or evaluates the target configuration. It does not load Django, query a deployment or read `CASEBOOK_DEBUG` to guess the application's environment. Its normal output is one JSON document containing file identities, observations and scan errors.

**Table T37-01. The authored debug rules**

| Input within the supported target/scope | Result | Supported claim |
| --- | --- | --- |
| `DEBUG = True` | `CBK001`, `literal_true` | This source target receives the literal Boolean `True` |
| `DEBUG: bool = True` | Same literal result | A valued annotated assignment has the same direct target |
| `DEBUG = False` | Counted, no observation | This particular recognized write uses literal `False` |
| `DEBUG = choose_flag()` or another non-Boolean expression | `CBK002`, `unresolved` | The rule does not decide the runtime value |
| `DEBUG \|= True` | `CBK002`, `unresolved` | Evaluating an augmented write requires earlier state/operation semantics |
| Comment or string containing `DEBUG = True` | No recognized write | The text is not that assignment |

These are local rule identifiers, not official advisory or weakness identifiers. A `CBK001` observation does not prove a publicly exposed debug page. It establishes a source fact that a reviewer can connect to the selected configuration and runtime evidence. `CBK002` must not be turned into either “debug enabled” or “safe.”

Supported targets are the bare name `DEBUG` in `Assign`, valued `AnnAssign` and `AugAssign` nodes, outside skipped function, async-function, class and lambda definitions. Module control-flow bodies are traversed without evaluating their guards. Other mechanisms can affect runtime configuration, and the checker does not claim to resolve them.

Save the listings under `examples/ch37/`. They form a separate package project and do not modify earlier Casebook modules.

## 1. Token streams, abstract syntax trees and source locations

### Worked example 1: find the assignment in a supplied module

Start with this small supplied configuration fixture. Predict how many direct debug writes the checker should count, and which location it should report.

Filename: `examples/ch37/fixtures/literal_debug.py`.

```python
# DEBUG = True is an old review note, not an assignment.
TEXT = "DEBUG = True"
DEBUG = True

def local_example():
    DEBUG = True
```

The intended answer is one recognized write at **line 3, column 1**. Line 1 is a comment. Line 2 assigns a string to `TEXT`. Line 6 assigns `DEBUG` in a function body, which this rule skips. The fixture is intentionally unsafe as a source example; do not use it as deployment settings.

A plain text search for `DEBUG = True` finds all four occurrences. That is useful for locating text, but it does not distinguish code structure. A regular expression could add some filtering, yet quoting, comments, multiple targets and multiline expressions soon complicate it.

A **token stream** breaks source into lexical pieces, such as names, strings, comments and operators. An **abstract syntax tree (AST)** represents parsed structure, such as an assignment with targets and a value. The AST is “abstract” because it omits many formatting details that a source editor preserves.

### Worked example 2: the same name in a comment and an assignment

Use the smallest useful sample before looking at the full visitor. Predict which token is a `NAME`, and whether the comment will appear as an assignment in the AST.

Filename: `examples/ch37/inspect_syntax.py`.

```python
"""Inspect a fixed teaching string, not an arbitrary configuration file."""
import ast
import io
import tokenize


SOURCE = '# DEBUG = True\nTEXT = "DEBUG = True"\nDEBUG = True\n'
for token in tokenize.generate_tokens(io.StringIO(SOURCE).readline):
    selected = (token.type in (tokenize.COMMENT, tokenize.STRING)
                or token.type == tokenize.NAME and token.string == "DEBUG")
    if selected:
        print(f"{tokenize.tok_name[token.type]} {token.start[0]}:{token.start[1] + 1} {token.string!r}")
tree = ast.parse(SOURCE)
print(ast.dump(tree.body[-1], include_attributes=False))
```

From the chapter project directory, run:

```bash
python inspect_syntax.py
```

Recorded output on CPython 3.12.14:

```text
COMMENT 1:1 '# DEBUG = True'
STRING 2:8 '"DEBUG = True"'
NAME 3:1 'DEBUG'
Assign(targets=[Name(id='DEBUG', ctx=Store())], value=Constant(value=True))
```

**Table T37-03. Why equal-looking text has different meaning**

| Source occurrence | Token view | Assignment view |
| --- | --- | --- |
| Comment on line 1 | `COMMENT` | No assignment target |
| Quoted text on line 2 | `STRING` | Value assigned to `TEXT`, not `DEBUG` |
| Bare target on line 3 | `NAME`, followed by assignment structure | `Assign` with `Name(id='DEBUG', ctx=Store())` |

`Store()` means the name is a write target. `Load()` would mean reading a name in an expression. The value here is `Constant(value=True)`. The comment is not an executable AST assignment; the string survives as a constant value rather than becoming code.

Python's [`tokenize` documentation](https://docs.python.org/3.12/library/tokenize.html) describes comment tokens and source encoding detection. Its [`ast` reference](https://docs.python.org/3.12/library/ast.html) describes the tree nodes and visitor interface. Our token example uses a fixed valid source string. It does not evaluate that string or a configuration module.

### Locations need a unit

AST line numbers are one-based, but `col_offset` is a zero-based **UTF-8 byte offset**. Our JSON reports one-based **Unicode code-point columns**. A tab counts as one code point, not an expanded editor width. Convert deliberately instead of adding one to every AST offset.

Consider this additional in-memory example:

```python
عنوان = "تمرین"; DEBUG = True
```

The prefix before `DEBUG` has seventeen Unicode code points but twenty-seven UTF-8 bytes. The AST target starts at byte offset `27`; the report should say column `18`. The visitor takes the UTF-8 prefix ending at the AST offset, decodes it and counts code points. A regression test asserts that conversion.

For a chained write such as `FLAG = DEBUG = True`, use the `DEBUG` target's position rather than the whole assignment's starting position. Otherwise the report points at `FLAG`, even though the rule is about `DEBUG`. A useful review tool states its location convention so another report format or editor adapter can convert it correctly.

## 2. AST visitors, aliases, scope and the limits of syntactic matching

A **visitor** selects behavior based on a node's type. `NodeVisitor` calls methods such as `visit_Assign`. `generic_visit` continues into child nodes. Returning without it stops traversal into the selected subtree.

Our visitor records three forms of write. It explicitly skips definitions where a local `DEBUG` would usually be unrelated to the module setting. It still visits module `if`, loop and `try` bodies, because direct assignments can occur there. That traversal is syntactic: it does not prove which branch runs.

**Listing L06. An AST visitor that reports a precise source location**

Filename: `examples/ch37/src/casebook_check/core.py`.

```python
"""Rules over selected direct DEBUG writes, without import or evaluation."""
import ast


MESSAGES = {
    "literal_true": "DEBUG receives literal True; review the loaded configuration.",
    "unresolved": "This rule cannot decide the runtime DEBUG value.",
}


class DebugWrites(ast.NodeVisitor):
    def __init__(self, source):
        self.lines = source.split("\n")
        self.checked_assignments = 0
        self.observations = []

    def record(self, target, value, *, augmented=False):
        self.checked_assignments += 1
        if not augmented and isinstance(value, ast.Constant) and value.value is False:
            return
        classification = ("literal_true" if not augmented
                          and isinstance(value, ast.Constant) and value.value is True
                          else "unresolved")
        # AST columns are UTF-8 byte offsets. Our report uses one-based
        # Unicode code-point columns, with a tab counting as one character.
        line = self.lines[target.lineno - 1]
        column = len(line.encode("utf-8")[:target.col_offset].decode("utf-8")) + 1
        self.observations.append({
            "rule_id": "CBK001" if classification == "literal_true" else "CBK002",
            "classification": classification,
            "line": target.lineno, "column": column,
            "message": MESSAGES[classification],
        })

    def visit_Assign(self, node):
        for target in node.targets:
            if isinstance(target, ast.Name) and target.id == "DEBUG":
                self.record(target, node.value)
        self.generic_visit(node)

    def visit_AnnAssign(self, node):
        if (isinstance(node.target, ast.Name) and node.target.id == "DEBUG"
                and node.value is not None):
            self.record(node.target, node.value)
        self.generic_visit(node)

    def visit_AugAssign(self, node):
        if isinstance(node.target, ast.Name) and node.target.id == "DEBUG":
            self.record(node.target, node.value, augmented=True)
        self.generic_visit(node)

    # These bodies and their decorators/defaults/annotations are outside
    # this deliberately small rule's scope.
    def visit_FunctionDef(self, node):
        return None

    visit_AsyncFunctionDef = visit_FunctionDef
    visit_ClassDef = visit_FunctionDef
    visit_Lambda = visit_FunctionDef


def check_source(source, *, filename="<memory>"):
    tree = ast.parse(source, filename=filename, mode="exec")
    visitor = DebugWrites(source)
    visitor.visit(tree)
    observations = sorted(visitor.observations,
                          key=lambda row: (row["line"], row["column"], row["rule_id"]))
    return visitor.checked_assignments, observations
```

`record` increments the recognized-assignment count even when the value is literal `False`. Boolean checks use `is True` and `is False`. The integer `1` compares equal to `True` in some Python comparisons, but it is not the literal Boolean the rule promises to recognize. It therefore receives an unresolved observation.

`visit_Assign` examines each direct target, supporting a chain such as `FLAG = DEBUG = True`. `visit_AnnAssign` ignores an annotation with no value, because `DEBUG: bool` does not assign one. `visit_AugAssign` reports unresolved rather than pretending to know the earlier value.

The skipped definitions deliberately include their decorators, defaults and annotations. Some of those expressions run during definition, and a function using `global DEBUG` can change module state later. This implementation does not analyze those mechanisms. “Module-oriented scope” is a rule boundary, not a complete model of Python execution.

### An example the rule cannot decide

Filename: `examples/ch37/fixtures/dynamic_debug.py`.

```python
import os as environment
# The value depends on a process environment the checker does not read.
DEBUG = environment.getenv("CASEBOOK_DEBUG") == "1"
```

The target is a direct module name, so the checker recognizes the write at **line 3, column 1**. The value is a comparison involving a call and an attribute. Its runtime result depends on the process environment. The tool returns `CBK002`, `unresolved`.

The import uses an **alias**: `environment` names the imported `os` module. An AST exposes the alias declaration, but this checker does not build a binding table or resolve the attribute call. Even if it recognized `os.getenv`, the target deployment's environment would still be external evidence. Reading the checker's own environment would answer the wrong question.

The test suite sets the checker's `CASEBOOK_DEBUG` to both `0` and `1` and obtains the same source observation. This is intentional. To decide the actual service value, inspect the chosen settings module, helper/environment source, startup configuration and a safe loaded-settings check through the application owner's trusted path. Chapter 35 supplied that kind of runtime check.

### Recognized uncertainty and blind spots differ

**Table T37-04. Boundaries a reviewer must know**

| Source | Tool behavior | Remaining question |
| --- | --- | --- |
| `if False: DEBUG = True` | Reports the nested literal write | Is this branch reachable? The visitor does not evaluate the guard. |
| `DEBUG = True` followed by `DEBUG = False` | Reports the first literal write; counts both | Which value is finally loaded? No final-state analysis is performed. |
| `DEBUG = DEFAULT_FLAG` | Unresolved direct write | What binding supplies the name, and can it change? |
| `from defaults import *` | No direct write found | What does the imported module export? Imports are not followed. |
| `cfg.DEBUG = True` after a settings alias import | Attribute target is unsupported | Which object is `cfg`, and what setting does it mutate? |
| `DEBUG, OTHER = True, False` | Unpacking target is unsupported | Target/value mapping needs another rule. |
| `(DEBUG := True)` | Named expression is unsupported | It is a different AST node from the three handled here. |
| Function with `global DEBUG` and a later call | Definition is skipped | Called code may mutate module state. |
| `globals()["DEBUG"] = True`, `exec(...)`, custom loaders | No direct bare-name write found | Dynamic namespace changes require other evidence. |

An unresolved observation is evidence that the tool saw a supported write but did not decide its value. A blind spot can produce **no observation at all**. Therefore exit `0` cannot mean “Django debug is disabled.” It means this limited scan completed without a reported observation or scan error.

This is also why scope tests include known misses. They document the contract rather than disguising the limits with only easy passing examples. Extending alias resolution or data-flow tracking requires more than matching the spelling of an object. Names can be rebound, shadowed or supplied by imports whose code we will not execute.

## 3. `pyproject.toml`, console entry points and wheel contents

### Turn functions into a small installable tool

The **import package** contains the reusable checker. The **distribution** is the built artifact installed into an environment. A **console entry point** tells an installer which function a command should call.

Filename: `examples/ch37/src/casebook_check/__init__.py`.

```python
"""Local source-review exercise; no configuration execution."""
__version__ = "0.1.0"
```

The version is also declared in project metadata. The install checks confirm that the installed distribution has version `0.1.0`; keep both declarations consistent when changing this example.

### Give the command a predictable protocol

The CLI reads at most 256 KiB per file, computes a SHA-256 over the exact bytes read, detects the declared Python source encoding and parses the decoded text. The fingerprint identifies reviewed input bytes; it is not an approval signature or a hash of the running service's effective settings.

Only explicitly supplied files are read. There is no recursive discovery. Normalized input spellings are sorted and deduplicated; a relative and absolute path or two symlink aliases may still name the same file separately. The tool follows ordinary local file access rather than implementing a sandbox. The documented scope is bounded local review, not hostile remote uploads.

Filename: `examples/ch37/src/casebook_check/cli.py`.

```python
"""Explicit local files in; one stable JSON document out."""
import argparse
import hashlib
import io
import json
import os
from pathlib import Path
import tokenize

from . import __version__
from .core import check_source


MAX_BYTES = 256 * 1024


def run(paths):
    files, observations, errors = [], [], []
    labels = sorted({os.path.normpath(str(path)) for path in paths})
    for label in labels:
        path = Path(label)
        digest = None

        def problem(code, line=None):
            errors.append({"path": path.as_posix(), "source_sha256": digest,
                           "code": code, "line": line})

        try:
            if not path.is_file():
                problem("not_regular_file")
                continue
            with path.open("rb") as source:
                raw = source.read(MAX_BYTES + 1)
        except OSError:
            problem("read_error")
            continue
        if len(raw) > MAX_BYTES:
            problem("too_large")
            continue
        digest = hashlib.sha256(raw).hexdigest()
        try:
            encoding, _ = tokenize.detect_encoding(io.BytesIO(raw).readline)
            text = raw.decode(encoding)
        except (SyntaxError, UnicodeError, LookupError):
            problem("encoding_error")
            continue
        try:
            checked, found = check_source(text, filename=path.as_posix())
        except SyntaxError as error:
            problem("syntax_error", error.lineno)
            continue
        except RecursionError:
            problem("parser_limit")
            continue
        files.append({"path": path.as_posix(), "source_sha256": digest,
                      "checked_assignments": checked})
        observations.extend({"path": path.as_posix(), "source_sha256": digest, **row}
                            for row in found)
    observations.sort(key=lambda row: (row["path"], row["line"], row["column"], row["rule_id"]))
    code = (2 if errors else 1 if any(row["classification"] == "literal_true" for row in observations)
            else 3 if observations else 0)
    return {"schema_version": 1, "tool": "casebook-config-check", "tool_version": __version__,
            "files": files, "observations": observations, "errors": errors, "exit_code": code}


def main(argv=None):
    parser = argparse.ArgumentParser(description="Review direct DEBUG writes without importing the files.")
    parser.add_argument("--version", action="version", version=__version__)
    parser.add_argument("files", nargs="+", help="explicit local source files; no directory walk")
    args = parser.parse_args(argv)
    report = run(args.files)
    print(json.dumps(report, ensure_ascii=True, sort_keys=True, indent=2))
    return report["exit_code"]
```

The target source is passed to `ast.parse`, not `importlib`, `exec`, `eval` or a framework loader. Parse failure produces a scan error. The error report deliberately omits source excerpts and raw exception text, because configuration values may be private. Successful observations contain a controlled message, path, hash and location.

Source encoding and AST location units are separate concerns. A Latin-1 file can be decoded according to its cookie, while the AST positions still use UTF-8 offsets for the parsed text. The test checks both the raw-byte fingerprint and the reported line for such a file.

A size cap does not fully contain parser CPU or memory exhaustion. This implementation classifies a recursion error, but does not isolate parsing in a resource-limited subprocess or guarantee recovery from every interpreter failure. Use the specified local inputs; a service accepting hostile uploads would need a different execution boundary.

Filename: `examples/ch37/src/casebook_check/__main__.py`.


This supports `python -m casebook_check`. Its `SystemExit` carries the integer returned by `main`. Merely returning an integer from a module-level function call would not set the process exit status.

### Build and inspect the wheel

From the repository root, enter `examples/ch37/`. Use an environment that already has the pinned build tools. The recorded build used their exact versions stated at the chapter opening.

```bash
cd examples/ch37
```

`--no-index` avoids index access, and `--no-build-isolation` uses the already prepared builder. The latter does not automatically enforce that its installed versions equal the pins; check those versions before building. This is an explicit offline laboratory workflow, not a substitute for the dependency verification process from chapter 31.

A **wheel** is an installation archive. Inspect it before treating a successful build log as proof that the right package and entry point were shipped. Our small verifier reads the locally built archive without importing its code.

Filename: `examples/ch37/verify_wheel.py`.

```python
"""Inspect this known locally built wheel without importing its contents."""
import argparse
import configparser
from email.parser import Parser
from pathlib import Path
import zipfile


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("wheel", type=Path)
    args = parser.parse_args()
    prefix = "casebook_config_check-0.1.0.dist-info/"
    expected = {"casebook_check/" + name for name in
                ("__init__.py", "__main__.py", "core.py", "cli.py")}
    expected |= {prefix + name for name in
                 ("METADATA", "WHEEL", "entry_points.txt", "top_level.txt", "RECORD")}
    with zipfile.ZipFile(args.wheel) as archive:
        names = archive.namelist()
        if len(names) != len(set(names)) or set(names) != expected:
            raise ValueError("unexpected_wheel_members")
        metadata = Parser().parsestr(archive.read(prefix + "METADATA").decode())
        if (metadata["Name"] != "casebook-config-check" or metadata["Version"] != "0.1.0"
                or metadata["Requires-Python"] != ">=3.12" or metadata.get_all("Requires-Dist")):
            raise ValueError("unexpected_wheel_metadata")
        entries = configparser.ConfigParser()
        entries.read_string(archive.read(prefix + "entry_points.txt").decode())
        if dict(entries["console_scripts"]) != {"casebook-config-check": "casebook_check.cli:main"}:
            raise ValueError("unexpected_console_entry")
    print("wheel members: 9; runtime modules: 4; tests/fixtures absent")
    print("console script: casebook-config-check = casebook_check.cli:main")
    print("metadata: version 0.1.0; Requires-Python >=3.12; no runtime dependencies")


if __name__ == "__main__":
    main()
```


**Table T37-05. Expected members of this pinned example build**

| Wheel members | Count | Purpose |
| --- | ---: | --- |
| `casebook_check/__init__.py`, `__main__.py`, `core.py`, `cli.py` | 4 | Runtime package |
| `.dist-info/METADATA`, `WHEEL`, `entry_points.txt`, `top_level.txt`, `RECORD` | 5 | Distribution, installation and entry metadata |
| Fixtures, tests and verification scripts | 0 | Kept in the source project, outside the runtime wheel |

The prefix of these metadata files is `casebook_config_check-0.1.0.dist-info/`. The verifier deliberately expects this exact example's contents; it is not a general wheel security auditor. Its member/metadata checks do not verify every `RECORD` hash, authenticate the builder or prove that the code is harmless. The [wheel specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/) defines the broader format.

This identifies that build, not every future rebuild. Archive timestamps, tools or inputs may produce different bytes. Record your actual artifact and retain its source/build identity; do not claim reproducible builds from a version pin alone.

The helper also invokes Python with `-I` for the module check and verifies that the import origin is inside the installation environment. It removes `PYTHONPATH` from the console child's environment so a source override does not accidentally satisfy the check.

Filename: `examples/ch37/verify_install.py`.

```python
"""Run with the fresh environment's Python after installing the wheel."""
import json
import os
from pathlib import Path
import shutil
import subprocess
import sys
import tempfile


project = Path(__file__).resolve().parent
executable = Path(sys.executable).with_name(
    "casebook-config-check.exe" if os.name == "nt" else "casebook-config-check")
environment = dict(os.environ)
environment.pop("PYTHONPATH", None)
with tempfile.TemporaryDirectory(prefix="casebook-check-installed-") as directory:
    neutral = Path(directory)
    (neutral / "fixtures").mkdir()
    for name in ("literal_debug.py", "dynamic_debug.py"):
        shutil.copyfile(project / "fixtures" / name, neutral / "fixtures" / name)
    for name, expected in (("literal", 1), ("dynamic", 3)):
        result = subprocess.run([str(executable), f"fixtures/{name}_debug.py"],
                                cwd=neutral, env=environment, text=True, capture_output=True)
        report = json.loads(result.stdout)
        if result.returncode != expected or report["exit_code"] != expected:
            raise ValueError("unexpected_installed_exit")
        row, = report["observations"]
        if (row["line"], row["column"]) != (3, 1):
            raise ValueError("unexpected_installed_location")
        print(f"installed console {name}: exit={expected}; location=3:1")
    result = subprocess.run([sys.executable, "-I", "-m", "casebook_check",
                             "fixtures/dynamic_debug.py"], cwd=neutral,
                            text=True, capture_output=True)
    if result.returncode != 3:
        raise ValueError("unexpected_module_exit")
    query = ("import json, casebook_check, importlib.metadata as m; "
             "print(json.dumps({'path': casebook_check.__file__, "
             "'version': m.version('casebook-config-check')}))")
    result = subprocess.run([sys.executable, "-I", "-c", query], cwd=neutral,
                            text=True, capture_output=True, check=True)
    installed = json.loads(result.stdout)
    if (installed["version"] != "0.1.0"
            or not Path(installed["path"]).resolve().is_relative_to(Path(sys.prefix).resolve())):
        raise ValueError("package_not_from_expected_environment")
    print("isolated module entry: exit=3; package origin is inside the installed environment")
```

## 4. Stable output, exit contracts, fixture tests and tool documentation

### Stable output is part of the tool

For the same input bytes, normalized path spellings, tool version and supported runtime, the normal JSON report has a deterministic structure and ordering. It contains no current timestamp or source snippet. Paths and hashes can still reveal review context, so retain the report with appropriate access controls.

The top-level `schema_version` describes the report format. `tool_version` identifies the implementation. Each successfully parsed file has a `checked_assignments` count, including direct literal-False writes. Observations carry rule ID, classification, location and the same source hash. Errors remain visible alongside valid observations from other files.

After installation, run the two supplied files together:

Input order does not determine output order: the dynamic filename sorts before the literal filename. The report keeps its unresolved observation even though the literal observation determines the combined exit code.

**Table T37-06. Process exit contract**

| Exit | Meaning | Example |
| ---: | --- | --- |
| `0` | Scan completed with no reported observations or errors | Supported write `DEBUG = False`; also possible for unsupported/no-match files |
| `1` | At least one `CBK001` literal-True observation, with no scan errors | Literal fixture, alone or with the dynamic fixture |
| `2` | At least one scan/input error | Missing/non-regular file, oversized source, bad encoding or syntax |
| `3` | Unresolved observations only, with no scan errors | Dynamic fixture alone |

The precedence is `2`, then `1`, then `3`, then `0`. A parse error must not be hidden by a finding from another file. Likewise, unresolved results must remain in the report when a literal result is present. The integer is a compact signal, not a replacement for the JSON evidence.

Invalid CLI arguments follow `argparse`'s usage/error behavior on stderr with exit `2`, without a normal report. `--help` and `--version` use text and exit `0`. The [argparse reference](https://docs.python.org/3.12/library/argparse.html) documents this interface behavior. A caller must distinguish a normal scan error report from an invocation that never started a scan.

The nonzero finding/review exits are intentional. A runner that stops on any nonzero exit must capture them explicitly. Do not append a blanket success override and then call the scan clean. The installation helper uses `subprocess.run`, checks `returncode` and parses the JSON before deciding what happened.

### Tests should challenge the rule boundary

Filename: `examples/ch37/tests/test_checker.py`.

```python
import contextlib
import io
import json
import os
from pathlib import Path
import tempfile
import unittest
from unittest.mock import patch

from casebook_check.cli import MAX_BYTES, main, run
from casebook_check.core import check_source


PROJECT = Path(__file__).resolve().parents[1]


class CheckerTests(unittest.TestCase):
    def test_two_fixtures_have_exact_locations(self):
        cases = [("literal_debug.py", "CBK001", "literal_true"),
                 ("dynamic_debug.py", "CBK002", "unresolved")]
        for filename, rule, classification in cases:
            text = (PROJECT / "fixtures" / filename).read_text()
            checked, rows = check_source(text)
            self.assertEqual(checked, 1)
            self.assertEqual([(r["line"], r["column"], r["rule_id"], r["classification"])
                              for r in rows], [(3, 1, rule, classification)])

    def test_comment_and_string_are_not_assignments(self):
        self.assertEqual(check_source('# DEBUG = True\nTEXT = "DEBUG = True"\n'), (0, []))

    def test_target_source_is_not_executed(self):
        checked, rows = check_source('raise RuntimeError("must_not_execute")\nDEBUG = True\n')
        self.assertEqual((checked, rows[0]["line"]), (1, 2))

    def test_false_is_counted_but_integer_and_string_need_review(self):
        self.assertEqual(check_source("DEBUG = False\n"), (1, []))
        for expression in ("1", '"false"', "True and False", "choose_flag()"):
            self.assertEqual(check_source(f"DEBUG = {expression}\n")[1][0]["classification"], "unresolved")

    def test_annotation_and_chained_targets(self):
        checked, rows = check_source("DEBUG: bool = True\nFLAG = DEBUG = True\nDEBUG: bool\n")
        self.assertEqual(checked, 2)
        self.assertEqual([(r["line"], r["column"]) for r in rows], [(1, 1), (2, 8)])

    def test_nested_definition_bodies_are_skipped(self):
        source = ("def f():\n    global DEBUG\n    DEBUG = True\n"
                  "async def g():\n    DEBUG = True\n"
                  "class C:\n    DEBUG = True\n")
        self.assertEqual(check_source(source), (0, []))

    def test_module_guard_is_not_evaluated(self):
        checked, rows = check_source("if False:\n    DEBUG = True\n")
        self.assertEqual((checked, rows[0]["line"], rows[0]["column"]), (1, 2, 5))

    def test_later_override_does_not_erase_the_source_observation(self):
        checked, rows = check_source("DEBUG = True\nDEBUG = False\n")
        self.assertEqual(checked, 2)
        self.assertEqual(len(rows), 1)

    def test_augmented_write_is_unresolved(self):
        self.assertEqual(check_source("DEBUG |= True\n")[1][0]["classification"], "unresolved")

    def test_unsupported_alias_attribute_unpacking_and_walrus_are_documented_blind_spots(self):
        source = ("from django.conf import settings as cfg\ncfg.DEBUG = True\n"
                  "DEBUG, OTHER = True, False\nif (DEBUG := True):\n    pass\n")
        self.assertEqual(check_source(source), (0, []))

    def test_unicode_column_uses_code_points(self):
        prefix = 'عنوان = "تمرین"; '
        checked, rows = check_source(prefix + "DEBUG = True\n")
        self.assertEqual(checked, 1)
        self.assertEqual(rows[0]["column"], len(prefix) + 1)
        self.assertGreater(len(prefix.encode("utf-8")) + 1, rows[0]["column"])

    def test_environment_does_not_change_the_dynamic_source_observation(self):
        text = (PROJECT / "fixtures/dynamic_debug.py").read_text()
        with patch.dict(os.environ, {"CASEBOOK_DEBUG": "0"}):
            first = check_source(text)
        with patch.dict(os.environ, {"CASEBOOK_DEBUG": "1"}):
            self.assertEqual(check_source(text), first)

    def test_cli_order_duplicate_spelling_and_exit_precedence(self):
        literal = str(PROJECT / "fixtures/literal_debug.py")
        dynamic = str(PROJECT / "fixtures/dynamic_debug.py")
        first = run([literal, dynamic, literal])
        self.assertEqual(first, run([dynamic, literal]))
        self.assertEqual((first["exit_code"], len(first["files"])), (1, 2))
        self.assertEqual(run([dynamic])["exit_code"], 3)
        self.assertEqual(run([literal, str(PROJECT / "missing.py")])["exit_code"], 2)

    def test_cli_main_emits_one_json_document_and_returns_its_code(self):
        output = io.StringIO()
        with contextlib.redirect_stdout(output):
            code = main([str(PROJECT / "fixtures/literal_debug.py")])
        self.assertEqual(code, 1)
        self.assertEqual(json.loads(output.getvalue())["exit_code"], code)

    def test_syntax_error_keeps_valid_results_without_echoing_source(self):
        with tempfile.TemporaryDirectory() as directory:
            bad = Path(directory) / "bad.py"
            bad.write_text("DEBUG = @PRIVATE_MARKER\n")
            report = run([bad, PROJECT / "fixtures/literal_debug.py"])
            self.assertEqual(report["exit_code"], 2)
            self.assertEqual(report["errors"][0]["code"], "syntax_error")
            self.assertEqual(len(report["observations"]), 1)
            self.assertNotIn("PRIVATE_MARKER", json.dumps(report))

    def test_size_directory_and_encoding_failures_are_not_empty_success(self):
        with tempfile.TemporaryDirectory() as directory:
            path = Path(directory) / "large.py"
            path.write_bytes(b" " * (MAX_BYTES + 1))
            self.assertEqual(run([path])["errors"][0]["code"], "too_large")
            self.assertEqual(run([directory])["errors"][0]["code"], "not_regular_file")
            path.write_bytes(b"# coding: not-a-real-codec\nDEBUG = True\n")
            self.assertEqual(run([path])["errors"][0]["code"], "encoding_error")

    def test_encoding_cookie_and_exact_source_fingerprint(self):
        import hashlib
        with tempfile.TemporaryDirectory() as directory:
            path = Path(directory) / "latin.py"
            raw = b'# coding: latin-1\nTEXT = "caf\xe9"\nDEBUG = True\n'
            path.write_bytes(raw)
            report = run([path])
            self.assertEqual(report["exit_code"], 1)
            self.assertEqual(report["observations"][0]["line"], 3)
            self.assertEqual(report["files"][0]["source_sha256"], hashlib.sha256(raw).hexdigest())
            path.write_bytes(raw + b"# changed\n")
            self.assertNotEqual(run([path])["files"][0]["source_sha256"], report["files"][0]["source_sha256"])

    def test_false_only_file_has_zero_observations(self):
        with tempfile.TemporaryDirectory() as directory:
            path = Path(directory) / "false.py"
            path.write_text("DEBUG = False\n")
            report = run([path])
            self.assertEqual((report["exit_code"], report["files"][0]["checked_assignments"]), (0, 1))


if __name__ == "__main__":
    unittest.main()
```

Other cases test comments, strings, skipped scope, chained targets, annotations, Unicode columns, encoding cookies, input fingerprints, non-execution, error precedence and the documented blind spots.

The test for an unsupported attribute or walrus deliberately expects no observation under the current contract. It is not approval of that configuration. If you extend the rule later, update its documented contract, tests and version together.

### Turn output into a bounded review decision

**Table T37-07. Disposition for the two supplied files**

| Observation | Next review action | Evidence still needed |
| --- | --- | --- |
| Literal fixture, `3:1`, `CBK001` | Review why this literal write exists in the candidate configuration | Whether this file is selected, whether a branch/override changes the final value, safe loaded-settings evidence |
| Dynamic fixture, `3:1`, `CBK002` | Inspect the environment/helper contract and deployment inputs | The target process's effective value; do not use the checker's environment |
| No observation on an alias/attribute-only file | Apply another rule or manual review | Object identity, binding/rebinding and runtime configuration path |
| Syntax/input error | Fix the input or execution problem and rerun | A complete scan of the intended files; no inferred clean result |

For a real settings correction, a candidate change from literal `True` to explicit `False` should remove this rule's observation in a temporary copy. Then run the relevant loaded-setting and deployment checks. The checker does not automatically edit source or reopen a service.

Casebook's workspace rule remains independent. Mina's active Alpha read must succeed; Ravi's Alpha read must fail. A source file with no debug match does not establish either permission result, secure host/scheme handling or required audit durability. Retain the behavioral checks from earlier chapters.

## Hints and worked answers

### Guided lab answers

The literal fixture has one supported write at `3:1`, classified `literal_true` under `CBK001`. Its comment, string and local function write do not add observations. The dynamic fixture also has one supported write at `3:1`, classified `unresolved` under `CBK002`.

The token example exposes a `COMMENT`, a `STRING` and a `NAME` with different lexical roles. The last AST assignment has a `Name` target with `Store()` and a Boolean constant value. No regular expression is needed to decide whether those known tokens form that assignment.

The installed artifact contains only the four runtime modules and the five expected metadata members. The two fixtures remain ordinary project inputs; they are not configuration modules imported by the checker. The fresh-environment and neutral-directory checks protect against mistaking a source-tree import for a working wheel/entry point.

Changing the module assignment to `False` removes its literal observation, but does not erase the tool's limitations. Keep the original fixture and tests, then connect any real configuration change to loaded runtime evidence before drawing a deployment conclusion.

### Independent practice answers

**1. Two writes, one observation.** The visitor counts both writes and reports the first at its own location. It does not model the final value. In a simple executed module the second assignment may overwrite the first, but this tool's supported claim is only that the first syntactic assignment exists. Determine the actual execution path and final loaded configuration separately.

**2. Annotation and integer.** `DEBUG: bool` has no assigned value, so this visitor does not count it. `DEBUG: bool = 1` is a recognized write and produces `CBK002`. An annotation is not runtime validation, and integer `1` is not the literal Boolean `True`. The tool intentionally does not expand its rule into general truthiness evaluation.

**3. Alias blind spot.** A useful note says: “The current bare-name rule does not recognize the attribute target `cfg.DEBUG`, so exit `0` is not evidence that debug is disabled. Resolve the alias/object and selected runtime path, then collect a safe effective-setting check or extend the rule with binding-aware tests.” Matching every object's attribute named `DEBUG` would add false positives without establishing that the object controls Django settings.

**4. Error precedence.** Exit `2` takes priority. The valid literal observation and its file fingerprint remain in the report alongside a syntax-error entry for the bad file. The error message should not echo a private source line. A consumer cannot treat the mixed report as a complete clean scan.

**5. Extend deliberately.** For example, a proposed unpacking rule could specify `DEBUG, OTHER = True, False` at line `1`, column `1`, with a literal observation only when the tuple mapping is directly supported. Add cases for mismatched lengths, dynamic right-hand values, nested targets and skipped scopes before implementing it. Document the new coverage/uncertainty rules, change the appropriate version, rebuild the wheel and retest the installed artifact. Do not keep using an older installed package to validate changed source.

**6. Column conversion.** The prefix in the non-English example is twenty-seven UTF-8 bytes but seventeen code points. Adding one to the byte offset incorrectly reports `28`; the documented column is `18`. A consumer expecting a different location unit needs an explicit adapter. Keep the raw source identity so the reviewer knows which version those positions describe.

## What you can now explain

An AST distinguishes assignment structure from comments and quoted text. A useful visitor reports a precise target, admits unresolved values and states which scopes and constructs it ignores. A lack of matches is meaningful only within that contract.

Packaging adds another evidence boundary. Inspect the wheel and run its installed entry point, rather than relying only on a successful import from a source directory. Stable JSON, explicit errors and tested exit codes make the tool usable by another reviewer.

For chapter 38, retain the saved reports' rule IDs, classifications, tool/schema versions, input hashes, paths, locations and error status. They provide concrete source references for normalization and deduplication. Keep the distinction between a source observation, an unresolved review item and a demonstrated runtime issue when assigning priority.
