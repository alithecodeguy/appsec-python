Mina can read Alpha note `101`, and Ravi can read Beta note `202`. What must happen if Ravi requests Alpha's ID, Mina asks for the same data through export, or Lee removes Mina's membership before her next request?

This chapter carries one permission rule through list, detail and export. You will distinguish who may call a function, which objects it may return and which fields it may reveal. Then you will commit a membership change and repeat the reads, including retrieval of an already built private export.

You need chapter 15's joins and transactions, chapter 19's separation between models and routes, chapter 20's ownership and response contracts, and chapters 21–22's trusted identity boundary. Keep `CB-READ-01` from chapter 18 and the Alpha/Beta acceptance matrix. The minimum fixture is Mina `1`, Ravi `2`, Lee `3`, workspaces Alpha `1` and Beta `2`, and notes `101` and `202`.

By the end, you will be able to:

- Name the subject, action, object and tenant in an access decision.
- Turn roles, attributes and ownership rules into a filled permission matrix.
- Reuse a current-membership query across list, detail and bounded export while selecting permitted fields explicitly.
- Check management actions, cached copies and later operations after committed revocation.

The edition targets **CPython 3.12.14** and **Django 6.1.3**. This chapter's local authorization laboratory uses only the standard library and requires Python 3.12 or later for explicit SQLite transaction configuration. Its actual runtime appears in the verification record.

## 1. Subjects, actions, objects, tenants and deny-by-default decisions

**Authorization** decides whether a particular subject may perform an action on an object under the current conditions. Successful authentication supplies an identity; it does not answer every subsequent permission question.

A **subject** is the person or service identity asking to act. An **action** is the operation, such as read, export or revoke membership. An **object** is the protected resource, such as a note, membership or private artifact. A **tenant** is an isolation domain for customer or team data. In Casebook, a workspace is the tenant boundary.

**Tenant isolation** means Alpha's authorized activity does not expose or modify Beta's protected data. Different host names, UI tabs or numeric ID ranges do not enforce that boundary by themselves.

**Table T23-01. Name the decision before writing a condition**

| Request | Subject | Action | Object | Tenant and binding |
| --- | --- | --- | --- | --- |
| Mina opens an Alpha list | Mina's trusted local identity | Read summaries | Every returned note | Each note's stored workspace is Alpha |
| Ravi submits `note_id=101` | Ravi's trusted local identity | Read detail | Alpha note `101` | Requested ID cannot override stored Alpha association |
| Mina exports note `101` | Mina's trusted local identity | Read selected note content into a copy | Every selected note | All selected notes must be authorized in Alpha |
| Lee requests Mina's artifact | Lee's trusted local identity | Retrieve private copy | Mina's export | Alpha membership plus requester binding; Lee is not its requester |
| Lee revokes Mina | Lee's trusted local identity | Change membership | Mina's Alpha membership | Lee manages Alpha only |

### State the complete read rule

For this exercise, permit a note read only when:

1. The service has an established local identity.
2. The stored account is active.
3. A current stored membership links that account to the note's stored workspace.
4. That membership is active and has a recognized role, `member` or `manager`.
5. The requested operation and returned fields are allowed by their separate contracts.

Every returned list item and selected export note must satisfy the rule. A download additionally requires the current requester to match the artifact's stored requester. A workspace manager may build their own authorized export, but management does not grant another person's requester-bound artifact.

**Deny by default** means that missing or unrecognized authority results in refusal. An absent identity, missing membership, inactive flag or unknown role must not fall through to an allow branch. It also means that a new route, bulk operation or field does not become permitted merely because it has been added to the codebase.

### Selectors are not authority

`workspace_id=1` and `note_id=101` select candidate resources. They are not proof of membership. The note's stored workspace association must participate in the selection. The user can change a selector even if the UI never offers the alternative.

This mistake is often described as **broken object-level authorization**, or **BOLA**. Older material also uses **insecure direct object reference**, or **IDOR**, for closely related object-access failures. The meaningful failure is that a changed identifier reaches another protected object without the required permission check. Replacing an integer ID with a UUID may make guessing harder, but does not establish the requester's right to the object.

### Choose an observable denial

The local response contract follows chapter 20's distinction:

- Anonymous fixture caller: `403` with `{"error":{"code":"access_denied"}}`.
- Identified but unauthorized workspace/object/requester: generic `404` with `{"error":{"code":"not_found"}}`.
- Authorized member calling a manager-only operation: `403 action_denied`.
- Authorized workspace with no notes: `200` with an empty list.

These statuses are modeled contract choices. A real adapter must implement its actual HTTP authentication challenge/login policy, JSON representation and private caching headers. A generic 404 does not replace authorization; it describes how an already enforced denial is reported.

Do not put a denied title, body, owner or “this note belongs to Beta” explanation in the error. Errors and response metadata can release private information even when the main result is absent. An operational database failure must remain a failure, not become a successful empty list.

## 2. Roles, attributes, ownership and a permission matrix

A **role** groups permitted actions, such as member or manager. **Role-based access control**, or **RBAC**, uses those roles in decisions. A role must have a scope: Lee is an Alpha manager, not a global manager.

An **attribute** is a fact relevant to a decision, such as account-active state or membership-active state. **Attribute-based access control**, or **ABAC**, evaluates such facts. A relationship such as “this membership links this user to this workspace” is equally important. Real policies often combine role, attribute and relationship checks rather than choosing only one label.

**Ownership** identifies a relationship to an object. Chapter 20 defined the note owner as its original creator. That field does not override Casebook's active-workspace-membership rule. Ravi must not read an Alpha note merely because a test changes its owner to Ravi. Conversely, Mina and Lee can both read an Alpha note under the workspace rule even though only Mina created it.

### Fill the same matrix for every read path

**Table T03. Subjects, actions and objects in two workspaces**

In the export column, “permit” means building an export of that workspace's authorized selected note and retrieving the actor's own artifact while permission remains current. It does not grant retrieval of another requester's artifact.

| Current subject | Target | List | Detail | Export build and own retrieval | Revoke ordinary member in target workspace |
| --- | --- | --- | --- | --- | --- |
| Mina, active Alpha member | Alpha / note `101` | Permit | Permit | Permit | Deny: manager role required |
| Mina, active Alpha member | Beta / note `202` | Deny | Deny | Deny | Deny: no Beta membership |
| Ravi, active Beta member | Alpha / note `101` | Deny | Deny | Deny | Deny: no Alpha membership |
| Ravi, active Beta member | Beta / note `202` | Permit | Permit | Permit | Deny: manager role required |
| Lee, active Alpha manager | Alpha / note `101` | Permit | Permit | Permit | Permit for an eligible Alpha ordinary member |
| Lee, active Alpha manager | Beta / note `202` | Deny | Deny | Deny | Deny: Alpha management gives no Beta authority |
| Anonymous visitor | Alpha or Beta | Deny | Deny | Deny | Deny |
| Mina after committed Alpha revocation | Alpha / note `101` | Deny | Deny | Deny, including a previously built artifact | Deny |
| Inactive Mina account, membership still active | Alpha / note `101` | Deny | Deny | Deny | Deny |

An owner-only read rule would implement a different product. A manager bypass that ignores tenant scope would also implement a different product. Write the intended matrix before translating it into SQL or framework permissions.

### Function, object and field decisions are different

**Function-level authorization** decides who may invoke a protected operation. In this laboratory only an active workspace manager may revoke an active ordinary member in the same workspace. Manager replacement, invitations, restoring membership and preventing last-manager loss require separate contracts; this small operation cannot revoke manager rows.

**Object-level authorization** decides which specific records the operation may affect or return. Lee's manager role does not let the revoke function modify Ravi's Beta membership. A bulk operation must check every selected object, not only the first one.

**Field-level authorization** decides which fields may be read or changed. An allowed object does not make every stored column part of every response. A title-only list, a full note detail and a note-content export have different approved field sets.

**Table T23-02. Explicit read representations**

| Representation | Allowed fields | Excluded from this representation |
| --- | --- | --- |
| List item | `id`, `workspace_id`, `title` | Private body and all unapproved storage columns |
| Detail | `id`, `workspace_id`, `title`, `body` | Unapproved account, membership and internal/storage columns |
| Note-content export item | Same four fields as detail | Unapproved storage fields; no extra workspace's records |
| Export envelope | `workspace_id`, `notes` | Requester credential, tokens or membership record |
| Denial | Safe error code only | Private object fields and artifact bytes |

The note body remains private even when an active member can read it through detail. List permission does not by itself approve returning it in a summary. Chapter 18's minimized support-diagnostic bundle is a different representation from this note-content export; do not substitute one field set for the other.

## 3. Object-, field- and function-level checks in query and service layers

A **service layer** coordinates one operation: validate its inputs, load current authority, select permitted records and produce the approved representation. A **query layer** constrains what data is loaded. A **serializer** chooses the fields and encoding sent onward.

These layers support one policy; they must not create competing versions of it. A safe list query followed by an unscoped detail lookup still leaves a read path open. A correct service check followed by serializing every stored model field can still reveal an unapproved field.

### Reuse the complete scope

The local `VISIBLE_SQL` query joins each note to the caller's current active membership in that note's workspace and to an active account. `visible_rows` adds only bound selection values and a bounded limit. List, detail and export use that same scope.

The service also calls `require_member` to distinguish an authorized empty workspace from an inaccessible workspace. Both the gate and the note selection run in one short database transaction. The returned rows are fully materialized before the connection closes. A later request opens a new connection and transaction, rather than reusing an evaluated list or old permission flag.

`note_fields` then constructs a dictionary from a fixed output allowlist. It does not remove one known sensitive field from a whole model dump and assume future columns are safe. For a larger service, also select only needed columns where practical. This small shared query loads a body for authorized rows, then the list projection omits it; the projection is an output boundary, not a claim that the body was never loaded.

**Listing L04. A permission-scoped query reused by two views**

The complete module includes the shared scope, the two local response adapters and the export/revocation services so the example can run independently.

Filename: `authorization_service.py`.

```python
"""Local authorization laboratory: trusted fixture identities, no HTTP authentication."""
from contextlib import closing, contextmanager
from dataclasses import dataclass
import json
import sqlite3


class AccessDenied(PermissionError):
    def __init__(self, status=404, code="not_found"):
        self.status = status
        self.code = code
        super().__init__(code)


def positive_id(value):
    return type(value) is int and 1 <= value <= 2**63 - 1


@contextmanager
def unit(path, *, write=False):
    with closing(sqlite3.connect(path, autocommit=True, timeout=2)) as db:
        db.row_factory = sqlite3.Row
        db.execute("PRAGMA foreign_keys = ON")
        db.execute("BEGIN IMMEDIATE" if write else "BEGIN")
        try:
            yield db
        except BaseException:
            db.execute("ROLLBACK")
            raise
        else:
            db.execute("COMMIT")


def seed(path):
    with unit(path, write=True) as db:
        for statement in (
            "CREATE TABLE workspaces (id INTEGER PRIMARY KEY, name TEXT UNIQUE NOT NULL)",
            "CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT NOT NULL, active INTEGER NOT NULL CHECK(active IN (0,1)))",
            """CREATE TABLE memberships (
                workspace_id INTEGER NOT NULL REFERENCES workspaces(id),
                user_id INTEGER NOT NULL REFERENCES users(id),
                role TEXT NOT NULL CHECK(role IN ('member','manager')),
                active INTEGER NOT NULL CHECK(active IN (0,1)),
                PRIMARY KEY(workspace_id,user_id))""",
            """CREATE TABLE notes (
                id INTEGER PRIMARY KEY, workspace_id INTEGER NOT NULL REFERENCES workspaces(id),
                owner_id INTEGER NOT NULL REFERENCES users(id), title TEXT NOT NULL,
                body TEXT NOT NULL, state TEXT NOT NULL, version INTEGER NOT NULL,
                updated_by INTEGER NOT NULL REFERENCES users(id))""",
        ):
            db.execute(statement)
        db.executemany("INSERT INTO workspaces VALUES (?,?)", [(1, "Alpha"), (2, "Beta")])
        db.executemany("INSERT INTO users VALUES (?,?,1)", [(1, "Mina"), (2, "Ravi"), (3, "Lee")])
        db.executemany("INSERT INTO memberships VALUES (?,?,?,1)",
                       [(1, 1, "member"), (2, 2, "member"), (1, 3, "manager")])
        db.executemany("INSERT INTO notes VALUES (?,?,?,?,?,?,?,?)", [
            (101, 1, 1, "Release plan", "Alpha private fixture", "open", 1, 1),
            (202, 2, 2, "Pricing review", "Beta private fixture", "open", 1, 2),
        ])


def require_member(db, user_id, workspace_id):
    if user_id is None:
        raise AccessDenied(403, "access_denied")
    if not positive_id(user_id) or not positive_id(workspace_id):
        raise AccessDenied()
    row = db.execute("""SELECT m.role FROM memberships AS m
        JOIN users AS u ON u.id = m.user_id AND u.active = 1
        WHERE m.workspace_id = ? AND m.user_id = ? AND m.active = 1
          AND m.role IN ('member','manager')""", (workspace_id, user_id)).fetchone()
    if row is None:
        raise AccessDenied()
    return row["role"]


# Reuse this complete authorization scope, never a global evaluated list of notes.
VISIBLE_SQL = """SELECT n.id, n.workspace_id, n.title, n.body FROM notes AS n
    JOIN memberships AS m ON m.workspace_id = n.workspace_id AND m.user_id = ?
        AND m.active = 1 AND m.role IN ('member','manager')
    JOIN users AS u ON u.id = m.user_id AND u.active = 1
    WHERE n.workspace_id = ?"""


def visible_rows(db, *, user_id, workspace_id, note_ids=None, limit=20):
    sql = VISIBLE_SQL
    parameters = [user_id, workspace_id]
    if note_ids is not None:
        # Only placeholder syntax is generated. Each identifier remains a bound value.
        sql += " AND n.id IN (" + ",".join("?" for _ in note_ids) + ")"
        parameters.extend(note_ids)
    sql += " ORDER BY n.id LIMIT ?"
    parameters.append(limit)
    return [dict(row) for row in db.execute(sql, parameters)]


def note_fields(row, *, body=False):
    fields = ("id", "workspace_id", "title", "body") if body else ("id", "workspace_id", "title")
    return {field: row[field] for field in fields}


def list_for_user(path, *, user_id, workspace_id, limit=20):
    if type(limit) is not int or not 1 <= limit <= 50:
        raise ValueError("limit must be an integer from 1 to 50")
    with unit(path) as db:
        require_member(db, user_id, workspace_id)
        rows = visible_rows(db, user_id=user_id, workspace_id=workspace_id, limit=limit)
        return [note_fields(row) for row in rows]


def detail_for_user(path, *, user_id, workspace_id, note_id):
    with unit(path) as db:
        require_member(db, user_id, workspace_id)
        if not positive_id(note_id):
            raise AccessDenied()
        rows = visible_rows(db, user_id=user_id, workspace_id=workspace_id,
                            note_ids=[note_id], limit=1)
        if not rows:
            raise AccessDenied()
        return note_fields(rows[0], body=True)


def export_selection(note_ids):
    if (not isinstance(note_ids, (list, tuple)) or not 1 <= len(note_ids) <= 10
            or not all(positive_id(value) for value in note_ids)
            or len(set(note_ids)) != len(note_ids)):
        raise ValueError("select 1 to 10 distinct positive note IDs")
    return tuple(sorted(note_ids))


@dataclass(frozen=True)
class Artifact:
    # Trusted in-process record only; never construct it from a browser or queue payload.
    requested_by: int
    workspace_id: int
    note_ids: tuple[int, ...]
    payload: bytes


def selected_rows(db, *, user_id, workspace_id, note_ids):
    require_member(db, user_id, workspace_id)
    rows = visible_rows(db, user_id=user_id, workspace_id=workspace_id,
                        note_ids=note_ids, limit=10)
    if len(rows) != len(note_ids):
        raise AccessDenied()  # No partial export if any selected note is inaccessible.
    return rows


def build_export(path, *, user_id, workspace_id, note_ids):
    ids = export_selection(note_ids)
    with unit(path) as db:
        rows = selected_rows(db, user_id=user_id, workspace_id=workspace_id, note_ids=ids)
        document = {"workspace_id": workspace_id,
                    "notes": [note_fields(row, body=True) for row in rows]}
        payload = json.dumps(document, ensure_ascii=False, separators=(",", ":")).encode("utf-8")
        return Artifact(user_id, workspace_id, ids, payload)


def download_export(path, *, user_id, artifact):
    # artifact must come from trusted service-managed storage, not client-supplied metadata.
    with unit(path) as db:
        require_member(db, user_id, artifact.workspace_id)
        if user_id != artifact.requested_by:
            raise AccessDenied()
        selected_rows(db, user_id=user_id, workspace_id=artifact.workspace_id,
                      note_ids=artifact.note_ids)
        return artifact.payload


def revoke_member(path, *, actor_id, workspace_id, target_user_id):
    if not positive_id(target_user_id):
        raise AccessDenied()
    with unit(path, write=True) as db:
        if require_member(db, actor_id, workspace_id) != "manager":
            raise AccessDenied(403, "action_denied")
        changed = db.execute("""UPDATE memberships SET active = 0
            WHERE workspace_id = ? AND user_id = ? AND role = 'member' AND active = 1""",
            (workspace_id, target_user_id)).rowcount
        if changed != 1:
            raise AccessDenied()


def response(operation):
    # Models the selected contract status/body; it is not an HttpResponse or HTTP server.
    try:
        return 200, operation()
    except AccessDenied as exc:
        return exc.status, {"error": {"code": exc.code}}


def list_view(path, *, user_id, workspace_id, limit=20):
    return response(lambda: list_for_user(path, user_id=user_id, workspace_id=workspace_id, limit=limit))


def detail_view(path, *, user_id, workspace_id, note_id):
    return response(lambda: detail_for_user(path, user_id=user_id, workspace_id=workspace_id, note_id=note_id))


def snapshot(path):
    # Privileged local evidence, not an API response or a support screen.
    with unit(path) as db:
        return {name: [dict(row) for row in db.execute(f"SELECT * FROM {name} ORDER BY 1,2")]
                for name in ("workspaces", "users", "memberships", "notes")}
```

### Read the security decisions in the code

`unit` creates a fresh request-local transaction. With `autocommit=True`, explicit SQL `BEGIN`, `COMMIT` and `ROLLBACK` control it. Read operations use `BEGIN`; the membership change uses `BEGIN IMMEDIATE` to begin a SQLite write transaction. This is local SQLite behavior, not a promise about every database isolation level.

`require_member` handles missing identity, validates selector types and loads authority from storage. The note query independently includes the same active-account/membership conditions. `owner_id` is absent from its permission predicate. A role outside the recognized pair cannot accidentally grant read access.

The query generates only placeholder syntax for a bounded `IN` selection. Note IDs remain bound values. Sorting and SQL structure come from code, not the browser. `list_for_user` caps the first-page result at 50; it does not implement chapter 20's proposed `after_id` pagination or counts. The export selection is limited to 1–10 distinct positive IDs.

`selected_rows` compares the number of authorized rows with the requested distinct IDs. A selection `[101, 202]` from Alpha fails as a whole. It does not silently produce a partial artifact and label it the requested export. This preserves chapter 17's all-or-nothing selection decision.

`Artifact` binds the original requester, workspace and selected IDs to the bytes. In this local model it is an immutable in-process record returned by trusted code. A frozen dataclass is not a storage integrity or authentication protocol. A real service must load those bindings and the matching payload from trusted durable records/storage. Never reconstruct this object from browser or queue claims and treat its fields as authority.

`download_export` checks both requester binding and current selected-note access before returning the existing payload. It does not merely ask whether the artifact was built successfully earlier. It returns the earlier authorized snapshot's bytes, not a newly generated current-note snapshot. Current access is rechecked; content freshness and retention are separate contracts.

`revoke_member` checks manager role and matches the target membership's workspace in the update itself. No operation here allows a client to rename the target workspace or edit a global user role. If the update finds no eligible active ordinary-member row, the operation is refused and the transaction is rolled back.

`snapshot` uses table names only from a fixed code tuple. It is privileged test evidence, not an endpoint or a support screen. The normal response adapters catch the modeled `AccessDenied` decision. They do not turn arbitrary storage/programming errors into successful results or implement a general HTTP validation boundary.

### Translate the scope into a web application deliberately

In a Django implementation, load current memberships from trusted models and construct the permission-scoped QuerySet for the request. Reuse that scope for both a collection and an object lookup. Fetch detail from the scoped QuerySet rather than fetching globally and hoping a list filter already protected it. Use explicit representation fields rather than serializing every model attribute.

Django QuerySets can be lazy and cache their evaluated results. Keep permission-related evaluation local to the operation; do not put an evaluated private QuerySet or membership result in a global variable for subsequent requests. The database and query timing determine which snapshot is read. Merely wrapping code in `transaction.atomic()` is not a universal guarantee of immediate visibility under every database configuration.

## 4. Admin actions, background jobs, caches and permission revocation

A permission rule is incomplete if a second path can release the same private data without it. Review a route, a management tool, a worker and a cache as separate entry points, even if they all call similar code.

### Administrative access still needs a policy

Django's `is_staff` flag is relevant to admin access; it does not mean “manager of every Casebook workspace.” An internal admin page can expose list views, object forms, related-object selectors, bulk actions and exports. Restrict its querysets and object/action permissions according to a separate approved operational policy, and test direct URLs as well as navigation.

Do not assume the default backend's model-level permissions establish tenant-level object access. Likewise, a framework superuser bypass is not automatically the intended product behavior for ordinary workspace managers.

Our `revoke_member` service is a product manager action, not a general database-operator interface. Operators with direct database or private-storage credentials have a different trust boundary and need restricted access, logging and approved procedures. An application query filter cannot stop someone who is already authorized to read the underlying database directly.

### A queued job does not preserve permission forever

A **background job** runs later, possibly in another process. A queue message should identify trusted durable intent, not grant authority through `user_id`, `workspace_id` or `may_read=true` supplied by an untrusted publisher.

At execution, load the job's stored requester, workspace and selection. Check current account and membership before reading private source data. Before releasing the result, check current retrieval authority again, including requester binding. A worker process's permission to read storage is not the end user's permission to receive the bytes.

The local `build_export` models a bounded source-read decision; `download_export` models the later retrieval gate. They make separate current database checks. Chapters 28 and 41–44 still need durable job state, queue authentication, retries, artifact binding and final release ordering. Passing this in-memory model is not proof of worker authorization or delivery correctness.

If a real build is denied after revocation, it must not publish a ready private artifact as though access succeeded. Inspect final job/artifact state, not only an error log. No background job or ready-state transition is created by the current laboratory, so those persistence assertions remain later work.

### Cache data without caching permanent permission

A **cache** keeps a copy for reuse. A cached note or artifact can outlive the membership decision that originally allowed it to be produced. A correct cache key reduces cross-user mixing, but a key containing user and workspace does not by itself handle revocation.

Casebook requires a revocation committed before the next authorization check to affect that check. A stale “allowed for five minutes” decision violates that rule unless the product explicitly changes its requirement. Safe designs either check current authority before private cached-byte release or enforce a coherently updated authorization version/invalidation protocol that meets the same timing promise. Best-effort cache invalidation is not evidence of that promise.

In the laboratory, artifact bytes are the cached copy. `download_export` rechecks current authority before returning them. The cached object is trusted internal state; the caller cannot swap its requester/workspace binding. A real storage implementation must preserve that association and prevent an alternate direct route from bypassing the gate.

Private HTTP responses need an explicit cache policy, such as the proposed no-store policy from chapter 20, and tests through the deployed browser/proxy path. The local response tuples emit no HTTP headers. A browser Back button or a managed copy already received by an authorized user is also different from a new server release after revocation.

Membership revocation is neither account deletion nor note deletion. Mina can still be a valid authenticated account while no longer having Alpha authority. Restoring her membership would be a separate authorized operation, not an effect of signing in again or replaying an old request.

### State the concurrent boundary honestly

These tests order the operations deliberately: the revocation commits, then the next request opens its transaction and checks authority. That proves sequential next-request behavior.

A request already in progress can have an earlier database snapshot. A revocation may race with a source read, cache gate, streaming response or byte release. The product must define the relevant ordering point and implement it consistently with the chosen database/storage mechanisms. This chapter does not claim to interrupt an existing response or prove concurrent release ordering. Chapter 18 already kept that decision open, and the worker/capstone chapters must resolve it for private export delivery.

- Django's [query guide](https://docs.djangoproject.com/en/6.1/topics/db/queries/), [QuerySet reference](https://docs.djangoproject.com/en/6.1/ref/models/querysets/) and [transaction guide](https://docs.djangoproject.com/en/6.1/topics/db/transactions/) document evaluation and database behavior that the real web integration must consider. Its [admin reference](https://docs.djangoproject.com/en/6.1/ref/contrib/admin/) documents queryset and permission hooks; this chapter does not claim the default admin enforces the Casebook tenant policy.
- Python's [`sqlite3` reference](https://docs.python.org/3.12/library/sqlite3.html) and SQLite's [transaction reference](https://www.sqlite.org/lang_transaction.html) describe the local storage mechanisms. SQLite documents [snapshot/isolation behavior](https://www.sqlite.org/isolation.html); sequential local results must not be presented as a proof of concurrent release ordering.
