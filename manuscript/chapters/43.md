### Read the private-data path

Review the implementation in its trust order:

1. `request_export` resolves current membership, validates the whole selection and compares retry intent before reserving capacity.

### Rollback must preserve the privacy history

A **rollback** returns selected running code/configuration to an identified prior version. It does not automatically mean restoring an old database. The latter may revive a revoked membership, clear a terminal closure, reintroduce deleted payloads or lose nonce-use history.

Before promotion, identify the prior approved artifact/configuration digests and check schema compatibility. Decide whether rollback can reuse the current database and which key versions remain required. Do not invent a “last known good” build for a feature that has not yet been deployed through the reviewed process.

If a future deployment fails, the operator's plan should cover:

1. Stop new export admission and pause work publication under the incident procedure; preserve the independent release-denial gate.
2. Preserve current membership, expiry, closure, deletion and nonce-use facts. Protect minimal evidence without copying private payloads into ordinary logs.
3. Select only an approved compatible artifact/configuration. If none exists, keep the feature disabled while repairing forward rather than installing an identified unsafe path.
4. Confirm queued and ready work cannot reopen terminal requests or bypass current membership under the selected code.
5. Recheck Alpha/Beta isolation, Mina's post-revocation denial, expiry at equality, duplicate publication and deletion obligations after the change.
6. Resume only after the authorized release/incident decision has adequate evidence for the actual subject.

This plan is authored, not executed rollback evidence. We have no prior approved deployment digest or rehearsal report for this capstone. A rollback filename or a general backup claim cannot close that gate.

        # Extract only the builder's own validated allowlist, not an arbitrary supplied archive.
        with zipfile.ZipFile(archive) as bundle:
            for name in contents:
                destination=extracted/name
                destination.parent.mkdir(parents=True,exist_ok=True)
                destination.write_bytes(bundle.read(name))
                assert sha(destination.read_bytes())==sha(contents[name])
        env={**os.environ,"PYTHONPATH":str(extracted),"PYTHONNOUSERSITE":"1","PYTHONDONTWRITEBYTECODE":"1"}
        process=subprocess.run([sys.executable,"-c",RUNNER],cwd=extracted,env=env,capture_output=True,text=True,check=True)
        observed=json.loads(process.stdout)
        demos={}
        for stage in ("admission","worker","lifecycle"):
            process=subprocess.run([sys.executable,"-m","examples.ch42.demo","--stage",stage],
                cwd=extracted,env=env,capture_output=True,text=True,check=True)
            demos[stage]=process.stdout
    report={"evidence_kind":"actual local execution of extracted candidate source",**subject,
            "collected_at_utc":datetime.now(timezone.utc).isoformat(),**observed,"demonstrations":demos,
            "dependency_scope":"selected observed local runtime distributions; not a complete SBOM, lock or advisory scan",
            "working_tree_used":False,"baseline_python":"3.12.14",
            "baseline_python_tested":observed["runtime"]["python"]=="3.12.14"}
    (args.out/"candidate-run.json").write_text(json.dumps(report,indent=2)+"\n")
    print("commit:",commit)
    print("artifact SHA-256:",digest)
    for name,result in observed["tests"].items():
        print(name+":",result["passed"],"passed,",result["skipped"],"skipped")
    print("dependency/advisory scan: MISSING")
    print("production promotion: HOLD (mandatory integration/configuration/recovery evidence incomplete)")
    if not all(result["successful"] for result in observed["tests"].values()):
        raise SystemExit("Candidate tests failed; retained reports are failure evidence")


if __name__=="__main__":
    main()

### Keep a navigable record

**Table T43-11. Retained evidence index**

| ID | File under `examples/ch43/` | Kind and subject | What another reviewer can inspect |
| --- | --- | --- | --- |
| `SRC43` | `evidence/candidate.json` | ACTUAL build record, source commit and ZIP digest | Allowlist, per-file hashes, builder hash and explicit source-archive scope |
| `ART43` | `evidence/candidate-source.zip` | ACTUAL archive bytes | Committed runnable implementation, helper Python files and requirement declarations |
| `RUN43` | `evidence/candidate-run.json` | ACTUAL-RUN, same commit/digest | Exact test transcripts, skips, demos, verified import origins and selected runtime inventory |
| `REV43` | `manual-review.json` | ACTUAL-REVIEW, same commit/digest | Concrete source observations, bounded dispositions and proposed owners |
| `EX43` | `example-findings.json` | EXAMPLE ONLY | Fictional detector/advisory/image records; never substitute for missing scanner or deployment evidence |
| `DEC43` | `release-decision.json` | Worked local review, same commit/digest | All twelve control rows, actual gate states, HOLD, next actions and referenced evidence hashes |
| `COL43` | `build_candidate.py` | Actual local collector recipe | Exact source scope and execution method; local unsigned builder, not a trusted CI identity |
| `CHECK43` | `check_evidence.py` | Actual consistency checker | Artifact/commit/report binding and control-row completeness, not evidence authenticity |

`SRC43` identifies the runnable-source archive and `RUN43` records its actual re-execution. The chapter 42 local report is a separate working-example record; it is not bundled as though it were an installed dependency or deployment artifact.

`DEC43` stores hashes of the candidate manifest/run, source review and example record. Changing one of those files invalidates the retained linkage until the decision is reviewed again. Local consistency still does not authenticate the writer: an attacker able to replace all records can replace hashes too. Production use needs the controller/storage/signature/approval protections discussed in chapter 32 and an actual authorized reviewer.

### Verify the local links

**Listing L43-02. Evidence consistency without pretending to approve release**

Filename: `examples/ch43/check_evidence.py`.

```python
"""Check local evidence consistency. This does not authenticate reports or approve release."""
import hashlib
import json
from pathlib import Path
import subprocess
import zipfile


def main():
    root=Path(__file__).resolve().parents[2]
    review=root/"examples/ch43"
    def read(name): return json.loads((review/name).read_text())
    def digest(data): return hashlib.sha256(data).hexdigest()
    candidate=read("evidence/candidate.json")
    archive=review/"evidence"/candidate["artifact"]
    assert digest(archive.read_bytes())==candidate["artifact_sha256"],"artifact changed"
    with zipfile.ZipFile(archive) as bundle:
        assert set(bundle.namelist())==set(candidate["files_sha256"]),"archive inventory differs"
        for name,expected in candidate["files_sha256"].items():
            committed=subprocess.check_output(["git","-C",str(root),"show",f'{candidate["source_commit"]}:{name}'])
            assert digest(bundle.read(name))==expected==digest(committed),name
            assert digest((root/name).read_bytes())==expected,("working example differs",name)
    assert digest((review/"build_candidate.py").read_bytes())==candidate["builder_sha256"],"builder changed"
    for name in ("evidence/candidate-run.json","manual-review.json","example-findings.json","release-decision.json"):
        record=read(name)
        for field in ("source_commit","artifact_sha256"):
            assert record[field]==candidate[field],(name,field)
    decision=read("release-decision.json")
    for name,expected in decision["evidence_sha256"].items():
        assert digest((review/name).read_bytes())==expected,name
    assert {row["id"] for row in decision["controls"]}=={f"EXP-{n:02}" for n in range(1,13)}
    print("candidate/evidence consistency: PASS")
    print("mandatory control rows:",len(decision["controls"]))
    print("production decision:",decision["decision"])
    print("scope: unsigned local records; not authenticated release approval")


if __name__=="__main__":
    main()
```

## What you can now explain

A release review connects a particular candidate to requirements and applicable evidence. A narrow test or finding disposition can be supported while production remains blocked. Installed versions must be established for the subject being assessed, and absent integration or dependency evidence cannot be replaced by a promising source declaration.

The useful handover is the identified candidate, honest control ledger, retained reports and concrete next actions. HOLD is justified here by specific missing and unsuitable boundaries, while the local implementation remains available for the next controlled learning step.

## Primary sources

- NIST's [SSDF 1.1, SP 800-218](https://csrc.nist.gov/pubs/sp/800/218/final) provides a framework for defined security criteria, verification, vulnerability response and protected development artifacts. The mandatory controls, owners and HOLD decision here are Casebook's authored policy/review.
- The [SLSA provenance specification](https://slsa.dev/spec/v1.2/provenance) describes evidence linking artifacts to their origins. This local unsigned source/archive record illustrates binding but makes no SLSA-level or authenticated-builder claim.
- PyPA's [core metadata specification](https://packaging.python.org/en/latest/specifications/core-metadata/), [version specifiers](https://packaging.python.org/en/latest/specifications/version-specifiers/) and Python's [`importlib.metadata` reference](https://docs.python.org/3.12/library/importlib.metadata.html) explain package/version/requirement facts. pip's [`inspect` documentation](https://pip.pypa.io/en/stable/cli/pip_inspect/) describes another inventory mechanism; this exercise uses its own selected metadata collector, not a recorded pip-inspect run.
- OWASP's [Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) supports current, explicit access checks across protected paths. The [Software Component Verification Standard](https://owasp.org/www-project-software-component-verification-standard/) provides component-verification context. Neither substitutes for Casebook's missing actual runtime, advisory, deployment or recovery evidence.
