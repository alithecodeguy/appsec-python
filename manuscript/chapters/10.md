## 1. Describe an interface with type hints

A **type hint**, also called an annotation, describes an expected type for a variable, parameter or return value. A **static type checker** examines code for inconsistent uses of those expectations without executing the program's ordinary operations.

For example, `def remaining_places(limit: int, count: int) -> int:` describes two integer parameters and an integer return value. The colon after a parameter introduces its annotation. The arrow introduces the return annotation.

| Annotation | How to read it |
| --- | --- |
| `str` | A string |
| `list[str]` | A list whose items are strings |
| `dict[str, int]` | A dictionary with string keys and integer values |
| `tuple[int, str]` | A two-item tuple containing an integer and a string |
| `int | None` | An integer or the missing value `None` |
| `object` | An arbitrary Python object requiring inspection before specialized use |

The vertical bar describes a **union**, meaning one of the listed types. `int | None` is an optional integer value. It does not make a function argument optional to supply. A default value in the signature controls omission, as in chapter 06.

These annotations describe values and operations. They do not express every business rule. An integer can still be negative. A string can still exceed a title limit. A function's `str` parameter does not establish that the caller belongs to the named workspace.

### Distinguish static information from runtime enforcement

Python normally permits execution even when supplied values disagree with annotations. A checker can flag disagreements visible in the code it examines. Validation code runs when the program executes and can inspect actual external values.

JSON decoding is an important boundary. The standard decoder returns dynamically typed data, commonly represented to a checker as `Any`. **Any** permits operations without requiring the checker to establish a specific type first. Treating a value as `Any` can allow a mistake through static checking.

We will mark the parser's public input as `object` to signal that callers may supply arbitrary data. The parser and model will perform checks before treating it as a usable draft. [Python typing reference](https://docs.python.org/3.15/library/typing.html)

## 2. Give related values an instance

A **class** defines a type of object. An **instance** is one object of that class. An **attribute** is a value attached to an object, accessed through a dot. A method is a function associated with the class and used through an instance.

Start with a small draft containing a title.

**Listing L10-01. A class with an attribute and a method**

Filename: `class_basics.py`.

```python
class NoteDraft:
    def __init__(self, title: str) -> None:
        self.title = title

    def title_length(self) -> int:
        return len(self.title)


draft = NoteDraft(title="برنامه انتشار")
print(draft.title)
print(draft.title_length())
```

The expected output is the following.

```text
برنامه انتشار
13
```

Calling `NoteDraft(...)` creates an instance and invokes its initializer, `__init__`. The conventional first parameter, `self`, refers to that instance. `self.title = title` stores the supplied value as an instance attribute. Calling `draft.title_length()` supplies `draft` as `self` automatically.

The double-underscore method name has a role defined by Python. Ordinary method names such as `title_length` are chosen by the author. The initializer's `-> None` annotation describes its own return value; the class call still produces the new instance.

This introductory class lives in its own file. The complete model below adds fields and validation in a separate module. [Python's class tutorial](https://docs.python.org/3.15/tutorial/classes.html)

### Worked example 1. Build the complete draft dataclass

A **dataclass** generates common methods for a class whose fields are declared with annotations. These include initialization, value equality and a useful representation. The `@dataclass` line is a **decorator** that applies this behavior to the following class. Chapter 11 will examine decorators more generally.

An **enum** gives a small set of choices explicit names. Our model has two states, `DRAFT` and `PUBLISHED`. Their stored string values are `"draft"` and `"published"`.

For this exercise, a draft can have no owner yet. Publication requires a positive owner identifier. Publication remains a workspace-private lifecycle state; reading the note still requires the access rule from chapter 06.

**Table T10-01. Draft model policy**

| Field or action | Rule |
| --- | --- |
| Workspace | Canonical registered name `Alpha` or `Beta` |
| Title | 1–120 code points, containing some non-whitespace text; preserve accepted text |
| Owner identifier | `None` or an exact integer from 1 through 999999; reject booleans |
| Body | Text of at most 4096 code points; omit it from the generated representation |
| Initial state | `DRAFT` |
| Publish | Allowed from `DRAFT` when an owner is assigned |
| Published state | Must have an owner; publishing an already published model is refused |

The owner range is a local teaching policy. Its check establishes a valid identifier shape and range. A later database lookup must establish that the owner exists and is eligible for the workspace.

**Listing L10-02. A validated dataclass and its transition**

Filename: `note_models.py`.

```python
from dataclasses import dataclass, field, replace
from enum import Enum


class NoteState(Enum):
    DRAFT = "draft"
    PUBLISHED = "published"


@dataclass(frozen=True, kw_only=True)
class NoteDraft:
    workspace: str
    title: str
    owner_id: int | None = None
    body: str = field(default="", repr=False)
    state: NoteState = NoteState.DRAFT

    def __post_init__(self) -> None:
        if not isinstance(self.workspace, str):
            raise ValueError("workspace must be text")
        if self.workspace not in ("Alpha", "Beta"):
            raise ValueError("unknown workspace")
        if not isinstance(self.title, str):
            raise ValueError("title must be text")
        if not 1 <= len(self.title) <= 120 or not self.title.strip():
            raise ValueError("title must contain text within 120 code points")
        if self.owner_id is not None:
            if type(self.owner_id) is not int or not 1 <= self.owner_id <= 999999:
                raise ValueError("owner_id must be an integer from 1 to 999999")
        if not isinstance(self.body, str) or len(self.body) > 4096:
            raise ValueError("body must be text within 4096 code points")
        if not isinstance(self.state, NoteState):
            raise ValueError("state must be a NoteState")
        if self.state is NoteState.PUBLISHED and self.owner_id is None:
            raise ValueError("published note requires an owner")

    def publish(self) -> "NoteDraft":
        if self.state is not NoteState.DRAFT:
            raise ValueError("only a draft can be published")
        return replace(self, state=NoteState.PUBLISHED)
```

`kw_only=True` makes the generated initializer take named field arguments. `frozen=True` prevents ordinary attribute assignment after initialization. A successful change uses `replace`, which constructs a new instance and runs its initialization checks again.

`__post_init__` is called by the generated initializer. Its conditions are the runtime enforcement in this model. The annotations alone would not perform those checks. A **domain model** combines data with rules that describe a product concept, here a note's valid fields and lifecycle.

`field(repr=False)` excludes the body from the generated `repr`. The body still exists on the instance. Other fields, including the title, remain visible in that representation. Choose explicit fields for reports and public responses instead of using a whole object representation as a response format.

The quoted return annotation `"NoteDraft"` refers to the class being defined. `NoteState(Enum)` uses the enum machinery to define named choices. Access a member's string value through `.value`. [Dataclass behavior](https://docs.python.org/3.15/library/dataclasses.html) · [Enums](https://docs.python.org/3.15/library/enum.html)

### Verify the allowed transition and unchanged original

**Listing L10-03. Publishing a draft with an owner**

Filename: `publish_draft.py`.

```python
from dataclasses import asdict

from note_models import NoteDraft

draft = NoteDraft(
    workspace="Alpha",
    title="برنامه انتشار",
    owner_id=42,
    body="Private release details",
)
published = draft.publish()

print("Original state", draft.state.value)
print("New state", published.state.value)
print("Same instance", draft is published)
print("Body shown in repr", "Private release details" in repr(draft))
print("Body included by asdict", "body" in asdict(draft))
```

The expected output is the following.

```text
Original state draft
New state published
Same instance False
Body shown in repr False
Body included by asdict True
```

`asdict` turns dataclass fields into dictionary data. It includes a field even when `repr=False` hides that field from the representation. Representation control and serialization policy therefore need separate decisions. An enum value also needs an explicit representation choice when writing JSON.

| Operation | Expected outcome |
| --- | --- |
| Publish an owned draft | A new published instance |
| Inspect the original after publishing | Still a draft |
| Publish an ownerless draft | `ValueError` during construction of the proposed published instance |
| Publish an already published instance | `ValueError` before replacement |

The new instance is returned only after its checks succeed. A failed transition leaves the original frozen instance intact.

### Give the checker two mistakes to find

Save the next file for static checking. It deliberately contains two incompatible uses.

**Listing L10-04. A wrong argument and an unresolved optional value**

Filename: `bad_types.py`.

```python
from note_models import NoteDraft

draft = NoteDraft(workspace="Alpha", title="Release plan", owner_id="42")


def require_owner(draft: NoteDraft) -> int:
    return draft.owner_id
```

Run the checker with the appropriate project interpreter.

```powershell

```

```shell
./.venv/bin/python -m mypy --strict bad_types.py
```

The checker should report two issues. Exact diagnostic wording and source locations depend on its version.

- `owner_id="42"` supplies a string where the generated initializer expects `int | None`.
- `require_owner` promises an integer but returns a value that may be `None`.

Running this file as Python would reach our model's explicit owner check and raise `ValueError` for the string. The type checker finds the incompatible argument before that run. Both observations depend on different mechanisms. [Mypy getting started](https://mypy.readthedocs.io/en/stable/getting_started.html)

### Narrow the optional value before returning it

**Type narrowing** uses a condition to establish a more specific type on a particular execution path.

**Listing L10-05. Requiring an owner deliberately**

Filename: `checked_types.py`.

```python
from note_models import NoteDraft


def require_owner(draft: NoteDraft) -> int:
    owner_id = draft.owner_id
    if owner_id is None:
        raise ValueError("owner is not assigned")
    return owner_id


draft = NoteDraft(workspace="Alpha", title="Release plan", owner_id=42)
print(require_owner(draft))
```

The expected Python output is `42`, followed by a newline. Run mypy with `--strict checked_types.py` in place of `bad_types.py`. It should accept this file and the imported model.

After the `None` branch raises, every remaining path has an integer `owner_id`. The checker can follow that fact. At runtime, an ownerless draft reaches the exception rather than being treated as owned.

This is also a small interface. A caller asks for a definite owner number and either receives an integer or gets the documented `ValueError`. It does not need to know the representation details of `NoteState` or the draft body. [Type narrowing](https://mypy.readthedocs.io/en/stable/type_narrowing.html)

### Compose models without sharing mutable defaults

**Composition** means an object contains other objects. A review queue can contain draft instances without inheriting the fields and behavior of a note.

**Listing L10-06. Independent queues of draft models**

Filename: `review_queue.py`.

```python
from dataclasses import dataclass, field

from note_models import NoteDraft


@dataclass
class ReviewQueue:
    drafts: list[NoteDraft] = field(default_factory=list)


first_queue = ReviewQueue()
second_queue = ReviewQueue()
first_queue.drafts.append(NoteDraft(workspace="Alpha", title="Release plan"))

print("First queue", len(first_queue.drafts))
print("Second queue", len(second_queue.drafts))
print("Shared list", first_queue.drafts is second_queue.drafts)
```

The expected output is the following.

```text
First queue 1
Second queue 0
Shared list False
```

`default_factory=list` asks initialization to create a fresh list for each queue. It carries forward the ownership lesson from chapters 05–06. The queue is mutable, while each stored draft resists ordinary field reassignment. Freezing an outer object would not recursively freeze a list stored inside it.

## 4. Check external input at runtime

A successful static check cannot establish the contents of a file that will arrive tomorrow. The following short example demonstrates why annotated dataclass fields need executable checks at that boundary.

**Listing L10-07. A hint-only dataclass receives dynamic data**

Filename: `unchecked_input.py`.

```python
from dataclasses import dataclass
import json


@dataclass
class OwnerInput:
    owner_id: int | None = None


payload = json.loads('{"owner_id": "42"}')
supplied = OwnerInput(owner_id=payload["owner_id"])
print(type(supplied.owner_id).__name__)
```

The expected output is the following.

```text
str
```

The standard JSON decoder supplies dynamic data, and this dataclass has no validation hook. Its generated initializer accepts the string at runtime. Mypy can accept this file because the dynamically typed value does not establish an incompatible argument in the same way as the literal in `bad_types.py`.

Our complete `NoteDraft` has a validation hook. The next parser checks the external record's shape and constructs that validated model.

### Worked example 2. From JSON owner to a checked model

The draft input shape requires `workspace` and `title`. It permits optional `owner_id` and `body`. It accepts canonical workspace names from the chapter 08 representation. An interface using short codes must first resolve them through the chapter 07 policy and registry.

State is server-controlled in this input interface. A supplied `state` key is rejected as unexpected. New drafts begin in `DRAFT`, and publication goes through the explicit transition.

**Listing L10-08. Parsing an external draft record**

Filename: `draft_input.py`.

```python
from note_models import NoteDraft


def parse_note_draft(payload: object) -> NoteDraft:
    if not isinstance(payload, dict):
        raise ValueError("draft input must be an object")
    for name in ("workspace", "title"):
        if name not in payload:
            raise ValueError(f"missing field {name}")
    if set(payload) - {"workspace", "title", "owner_id", "body"}:
        raise ValueError("unexpected fields")
    return NoteDraft(
        workspace=payload["workspace"],
        title=payload["title"],
        owner_id=payload.get("owner_id"),
        body=payload.get("body", ""),
    )
```

The dictionary values are still dynamically typed after the shape check. The constructor's `__post_init__` inspects their actual types, value limits and relationships. This keeps the field rules in one model rather than repeating them in every parser.

Save this complete fixture as `drafts.json` in UTF-8.

```json
[
  {
    "workspace": "Alpha",
    "title": "برنامه انتشار",
    "owner_id": 42,
    "body": "Private release details"
  },
  {
    "workspace": "Alpha",
    "title": "Owner pending"
  },
  {
    "workspace": "Alpha",
    "title": "Broken owner",
    "owner_id": "42"
  }
]
```

A draft has no stored note identifier yet, so this input shape differs from the existing-note inventory in chapter 08. Each fixture here represents a proposed new draft.

**Listing L10-09. Reading and reporting three draft candidates**

Filename: `read_drafts.py`.

```python
import json
from pathlib import Path

from draft_input import parse_note_draft

with Path("drafts.json").open("r", encoding="utf-8") as source:
    payloads = json.load(source)
if not isinstance(payloads, list):
    raise ValueError("draft file must contain a list")

for number, payload in enumerate(payloads, start=1):
    try:
        draft = parse_note_draft(payload)
    except ValueError as error:
        print(number, "Rejected", str(error))
    else:
        print(number, "Accepted", draft.owner_id, draft.state.value)
```

The expected output is the following.

```text
1 Accepted 42 draft
2 Accepted None draft
3 Rejected owner_id must be an integer from 1 to 999999
```

**Table T10-02. Following the owner value through the boundary**

| Stage | Owned fixture | Owner-pending fixture | Broken-owner fixture |
| --- | --- | --- | --- |
| JSON decoding | Integer `42` | No owner key | String `"42"` |
| Parser selection | Pass `42` to the constructor. | Pass `None` from `.get`. | Pass the supplied string to the constructor. |
| Runtime model check | Accept its integer type and range. | Permit absence while drafting. | Reject the string. |
| Valid model's annotated field | `int | None`, narrowed by later checks | `int | None`, requiring an absence check | No valid model returned |
| Publication | New published model is permitted. | Refused until an owner is assigned. | Candidate never reaches publication. |

The model's runtime checks also reject `True`, zero and negative owner numbers. A type checker can identify a string literal passed to an integer field, but it generally cannot prove the required numeric range from an `int` annotation.

Publication and ownership assignment are product operations whose callers still need authorization. A valid model and a valid state transition establish the domain rules shown here; chapter 23 will connect operations to service-wide permission checks.

## Worked answers

### Exercise 1

The caller must still supply the argument if no default is present. Writing `owner_id: int | None = None` permits omission and supplies the missing value by default.

### Exercise 2

The string literal is incompatible with `int | None`, so a checker can flag it directly. Both the string and integer `-1` are rejected by this model's runtime checks. `None` is valid for a draft, but a published instance requires an owner. An integer annotation alone cannot establish positivity or the upper bound.

### Exercise 3

The draft's `publish` method attempts a replacement with state `PUBLISHED`. Construction rejects the combination of that state and `owner_id=None`. The original instance remains an ownerless draft. Calling `.publish()` on a published model reaches the method's initial state guard and raises `only a draft can be published`.

### Exercise 4

`asdict` includes the body, and direct attribute access still returns it. `repr=False` changes only its inclusion in the generated representation. Select serialization and response fields according to the operation's needs.

### Exercise 5

Only the first queue changes. Each initialization receives a fresh list from its factory. The draft may itself be referenced from several places, but the two queue lists are independent objects.

### Practice check

The owned Persian-title fixture can become a new published instance. Its original stays in `DRAFT`. The owner-pending fixture constructs a valid draft but publication raises `published note requires an owner`. The string owner fixture raises `owner_id must be an integer from 1 to 999999` during the constructor's post-initialization checks.

The checker reports the string argument and the optional return in `bad_types.py`. The guarded return in `checked_types.py` satisfies its integer result contract. Those code observations and the parser's runtime observations answer different questions about the same model.
