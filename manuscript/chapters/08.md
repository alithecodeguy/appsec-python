## 1. Locate a file with `pathlib`

`Path` represents a filesystem path. A **relative path** is interpreted from a starting directory. For these direct file operations, that starting point is the process's current working directory. An **absolute path** identifies a location from the filesystem root or a Windows drive.

| Expression | Meaning |
| --- | --- |
| `Path("notes.csv")` | The name `notes.csv` relative to the working directory |
| `Path("fixtures") / "notes.csv"` | A path inside the relative `fixtures` directory |
| `Path.cwd()` | The current working directory |
| `Path("notes.csv").resolve()` | An absolute resolved form of that path |

The `/` operator between a `Path` and a filename joins path components. Python uses the appropriate path conventions for your operating system.

Running a script from another directory can change which file a relative path selects. When diagnosing a missing file, inspect the working directory and resolved input path before changing the record reader.

### Worked example 1. Read the Persian title as UTF-8 text

The exercise below recreates the exact `note-title.txt` fixture from chapter 07. It creates or replaces that file in the working directory with the title and no final newline. The write makes this example self-contained even if an editor changed the earlier fixture.

**Listing L08-01. Reading a title from a relative path**

Filename: `read_title.py`.

```python
from pathlib import Path

path = Path("note-title.txt")
path.write_text("برنامه انتشار", encoding="utf-8")

with path.open("r", encoding="utf-8") as source:
    title = source.read()

print(repr(title))
print("Code points", len(title))
print("UTF-8 bytes", len(title.encode("utf-8")))
print("File closed", source.closed)
```

The expected output is the following.

```text
'برنامه انتشار'
Code points 13
UTF-8 bytes 25
File closed True
```

`.write_text` encodes the supplied string using the named encoding. Opening with mode `"r"` creates a readable text stream, which decodes the file's bytes as you read. `.read()` without a size reads the remaining text into one string. The title stays identical across this explicit UTF-8 write/read boundary. [Path operations](https://docs.python.org/3.12/library/pathlib.html)

## 2. Own the open file with a `with` block

An open file holds an operating-system resource. The `with` statement gives that resource a clear lifetime. `as source` binds the open file object to a name, and the indented block performs the read. Leaving the block closes the file, including when an exception leaves the block.

In Listing L08-01, the string `title` remains available after the file closes. The file object also remains accessible through `source`, allowing the `source.closed` check. Further reads from that closed object would raise `ValueError`.

An opening failure, such as a nonexistent path, happens before the block begins. An invalid UTF-8 sequence can raise `UnicodeDecodeError` during reading. Chapter 09 develops exception handling for these distinct failures. [Reading and writing files](https://docs.python.org/3.12/tutorial/inputoutput.html#reading-and-writing-files) · [The `with` statement](https://docs.python.org/3.12/reference/compound_stmts.html#the-with-statement)

### Read incrementally when the format supports it

Iterating over a text file with `for line in source` reads successive lines instead of first creating a string containing the whole file. Each line normally retains its line ending. An empty file supplies zero lines.

CSV needs a format-aware reader because one logical record can contain quoted fields and even embedded line breaks. Its reader consumes the text stream incrementally. JSON's `json.load` reads and constructs a complete document. Choose a reading strategy according to the format and expected input size.

The converter later in this chapter retains a small inventory and its summary in memory. An incremental CSV reader does not make the entire conversion constant in memory when the application also collects every parsed record.

### Choose read and write modes deliberately

| Mode | Behavior relevant to this chapter |
| --- | --- |
| `"r"` | Read an existing file; a missing path raises an error. |
| `"w"` | Create or replace a file's contents for writing. |
| `"a"` | Append text at the end, creating the file if needed. |

Our converter writes one complete JSON document to each output file with `"w"`. Repeatedly appending complete JSON documents would not produce the single JSON array or object a normal reader expects.

## 3. Read complete CSV and JSON fixtures

A **format** specifies how data is represented in a file. A **schema** describes the expected structure and meaning of that data. Successfully parsing a format still leaves schema checks to perform.

The two fixtures below describe the same three candidate records. They use short workspace codes from chapter 07. Records one and two have titles. Record three has an identifier and workspace, but no supplied title.

### CSV fixture with a quoted comma

Save the following complete file as `notes.csv` in UTF-8. Its final record intentionally ends after `beta`, without a third field.

**Fixture F08-01. Three candidate CSV records**

```csv
id,workspace,title
1,alpha,"Release plan, phase 1"
5,alpha,برنامه انتشار
2,beta
```

The header names the three fields. Double quotes around `Release plan, phase 1` make its comma part of the title. A plain `.split(",")` would divide that title incorrectly.

Use `csv.DictReader` to associate each field with its header name. Open CSV text files with `newline=""` so the CSV reader can handle line endings according to its own rules.

**Listing L08-02. Inspecting the parsed CSV rows**

Filename: `read_csv_notes.py`.

```python
import csv
from pathlib import Path

with Path("notes.csv").open("r", encoding="utf-8", newline="") as source:
    reader = csv.DictReader(source, strict=True)
    for record_number, row in enumerate(reader, start=1):
        print(record_number, row)
```

`enumerate` pairs successive items with a counter. `start=1` makes our first data record number one. The loop unpacks each pair into `record_number` and `row`.

The expected output is the following.

```text
1 {'id': '1', 'workspace': 'alpha', 'title': 'Release plan, phase 1'}
2 {'id': '5', 'workspace': 'alpha', 'title': 'برنامه انتشار'}
3 {'id': '2', 'workspace': 'beta', 'title': None}
```

CSV supplies the identifier as text. Its quotes are format syntax and disappear from the parsed title. For a short row, `DictReader` supplies `None` for the unfilled field by default. With a trailing comma, `2,beta,` would instead supply an empty string as the title.

`strict=True` asks the CSV parser to report syntax problems it recognizes. It still permits this short row, so field completeness needs a schema check. Our record numbers count parsed data records, excluding the header. They are distinct from physical line numbers when fields contain line breaks. [Python CSV reference](https://docs.python.org/3.12/library/csv.html) · [The `enumerate` function](https://docs.python.org/3.12/library/functions.html#enumerate)

### JSON fixture with an absent key

Save this complete document as `notes.json` in UTF-8.

**Fixture F08-02. The same three candidates as JSON**

```json
[
  {
    "id": 1,
    "workspace": "alpha",
    "title": "Release plan, phase 1"
  },
  {
    "id": 5,
    "workspace": "alpha",
    "title": "برنامه انتشار"
  },
  {
    "id": 2,
    "workspace": "beta"
  }
]
```

The outer brackets describe a JSON array. Each object inside has named members. The third object lacks a `title` member entirely.

| JSON representation | Python result |
| --- | --- |
| Object | `dict` |
| Array | `list` |
| String | `str` |
| Integer number | `int` |
| Number with a fraction or exponent | Usually `float` with default decoding |
| `true` or `false` | `True` or `False` |
| `null` | `None` |

JSON object member names and string values use double quotes. JSON uses `null` for an explicit null value. Omitting a member and giving it `null` are different parsed structures, even when the application's policy rejects both.

**Listing L08-03. Inspecting the JSON types and missing key**

Filename: `read_json_notes.py`.

```python
import json
from pathlib import Path

with Path("notes.json").open("r", encoding="utf-8") as source:
    records = json.load(source)

print("Records", len(records))
print("First id type", type(records[0]["id"]))
print("Third has title", "title" in records[2])
```

The expected output is the following.

```text
Records 3
First id type <class 'int'>
Third has title False
```

Parsing JSON already gives us integer identifiers in this fixture. It does not establish that the document is a list of acceptable notes. The converter will check that separately. [Python JSON reference](https://docs.python.org/3.12/library/json.html)

## 4. Validate and convert into one record shape

The importer will produce records using the earlier workspace identifiers `Alpha` and `Beta`. The short code is resolved through the small registry from chapter 07.

**Table T08-01. Inventory schema for this exercise**

| Element | Rule |
| --- | --- |
| JSON document | A list of candidate note objects |
| CSV header | Exactly `id`, `workspace` and `title`, each appearing once; column order may vary |
| Required fields | All three fields must be supplied; `None` counts as missing |
| Additional fields | Reject unexpected fields |
| Identifier | Integer from 1 through 999999; CSV supplies one to six ASCII decimal digits for conversion |
| Workspace | A valid short code registered as `alpha` or `beta` |
| Title | A string of 1 through 120 code points with some non-whitespace text |
| Text preservation | Keep an accepted title exactly as supplied |
| Record refusal | Save its one-based record number and first rejection reason |

Booleans are excluded from the identifier rule even though Python treats them as an integer subtype. The exact type check below expresses that choice. Leading zeros in a CSV identifier are accepted and converted to their integer value. This schema does not deduplicate note identifiers; it evaluates each source record independently.

### Put the common checks in one module

Save the following as `note_records.py`. It imports the unchanged code validator from chapter 07.

**Listing L08-04. Shared validation and CSV adaptation**

```python
from workspace_codes import validate_workspace_code


WORKSPACE_NAMES = {"alpha": "Alpha", "beta": "Beta"}


def validate_note(record):
    if not isinstance(record, dict):
        return None, "record must be an object"
    for field in ("id", "workspace", "title"):
        if field not in record or record[field] is None:
            return None, f"missing field {field}"
    if set(record) - {"id", "workspace", "title"}:
        return None, "unexpected fields"

    note_id = record["id"]
    if type(note_id) is not int or not 1 <= note_id <= 999999:
        return None, "id must be an integer from 1 to 999999"

    code, reason = validate_workspace_code(record["workspace"])
    if code is None:
        return None, f"workspace {reason}"
    if code not in WORKSPACE_NAMES:
        return None, "unknown workspace"

    title = record["title"]
    if not isinstance(title, str):
        return None, "title must be text"
    if not 1 <= len(title) <= 120 or not title.strip():
        return None, "title must contain text within 120 code points"

    return {
        "id": note_id,
        "workspace": WORKSPACE_NAMES[code],
        "title": title,
    }, "accepted"


def convert_csv_note(row):
    raw_id = row.get("id")
    if raw_id is not None:
        if not 1 <= len(raw_id) <= 6:
            return None, "CSV id must contain 1 to 6 ASCII digits"
        if not raw_id.isascii() or not raw_id.isdecimal():
            return None, "CSV id must contain 1 to 6 ASCII digits"
        row = row.copy()
        row["id"] = int(raw_id)
    return validate_note(row)
```

Uppercase names such as `WORKSPACE_NAMES` conventionally identify module-level constants. This dictionary supplies the fixture registry. It remains mutable as a Python object, so the validator reads it without changing it.

`convert_csv_note` expects a row from `DictReader`. Such field values are strings or `None` under our reader settings. Its digit and length checks make `int(raw_id)` suitable for the accepted CSV spelling. The copied dictionary protects the raw parsed row from that conversion's assignment.

`validate_note` handles the common record shape. Its missing-field loop runs before ordinary value checks. In the third record from either fixture, the first failure is `missing field title`.

The expression `set(record) - {...}` finds unexpected keys. Set subtraction retains members present only on the left. A CSV row with excess fields receives an additional key from `DictReader` and is refused by this check.

### Convert both fixture files and write their summaries

The following script loads a small file, validates each candidate and writes one summary. It repeats the same process for CSV and JSON. Both input files and `workspace_codes.py` must be present in the learning folder.

**Listing L08-05. A complete small-inventory converter**

Filename: `convert_notes.py`.

```python
import csv
import json
from pathlib import Path

from note_records import convert_csv_note, validate_note


def load_records(path, file_format):
    with path.open("r", encoding="utf-8", newline="") as source:
        if file_format == "csv":
            reader = csv.DictReader(source, strict=True)
            fields = reader.fieldnames
            if fields is None or len(fields) != 3:
                raise ValueError("CSV header must name three fields")
            if set(fields) != {"id", "workspace", "title"}:
                raise ValueError("CSV header must name id, workspace and title")
            return list(reader)
        if file_format == "json":
            records = json.load(source)
            if not isinstance(records, list):
                raise ValueError("JSON document must be a list")
            return records
        raise ValueError("unsupported input format")


def convert_inventory(source_path, destination_path, file_format):
    records = load_records(source_path, file_format)
    accepted = []
    rejected = []

    for record_number, raw_record in enumerate(records, start=1):
        if file_format == "csv":
            note, reason = convert_csv_note(raw_record)
        else:
            note, reason = validate_note(raw_record)
        if note is None:
            rejected.append({"record": record_number, "reason": reason})
        else:
            accepted.append(note)

    summary = {
        "source_records": len(records),
        "accepted_count": len(accepted),
        "rejected_count": len(rejected),
        "records": accepted,
        "rejections": rejected,
    }
    with destination_path.open("w", encoding="utf-8") as destination:
        json.dump(summary, destination, ensure_ascii=False, indent=2)
        destination.write("\n")
    return summary


if __name__ == "__main__":
    for file_format in ("csv", "json"):
        source_path = Path(f"notes.{file_format}")
        destination_path = Path(f"{file_format}-summary.json")
        summary = convert_inventory(source_path, destination_path, file_format)
        print(
            source_path.name,
            summary["source_records"],
            summary["accepted_count"],
            summary["rejected_count"],
        )
```

`list(reader)` consumes the CSV reader into a list while the file is open. The `return` leaves the `with` block and closes the file before the caller receives that list.

`raise ValueError(...)` signals that the entire file setup or document shape is unacceptable. An unhandled raised exception ends this script and reports the problem. Chapter 09 will teach how to handle such exceptions. A rejected candidate record, by contrast, produces a rejection entry and permits the converter to examine the remaining candidates.

`json.dump` serializes the summary to the destination file. `ensure_ascii=False` keeps the Persian title readable in the UTF-8 JSON text. `indent=2` formats the document for inspection. The explicit final newline belongs to the output document, outside any title value.

The script creates or replaces `csv-summary.json` and `json-summary.json`. Keep those output paths distinct from the input files. It validates the inventory before opening the destination for writing. Chapter 09 will examine cleanup and file-write failures, including how to preserve a previous output if a replacement fails partway.

### Distinguish an empty inventory from an empty file

| Input | Result under this exercise's policy |
| --- | --- |
| CSV header followed by no data records | Valid empty inventory, with all three counts zero |
| Zero-byte CSV file | Refused because the required header is absent |
| JSON document `[]` | Valid empty inventory, with all three counts zero |
| Zero-byte or whitespace-only JSON file | JSON parsing fails because there is no document |
| JSON document `{}` | Parsing succeeds; the list requirement fails |
| Record with `"title": null` | Rejected as `missing field title` |
| Record with `"title": ""` | Rejected by the nonempty-title rule |

An empty inventory is a defined collection with no members. An empty file may lack the format structure needed even to establish that collection. Use the format and schema together when interpreting zero records.
