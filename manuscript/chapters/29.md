The new helper is called `unscoped_rows`. A **scope** is the set of records a query is allowed to return for the current operation. Here, scope includes both the requested workspace and the user's current permission. The helper's name is a useful warning, but names are not proof. ### Write the rule before judging the implementation

For this change, the existing requirements are concrete:

1. A list contains notes only from the requested workspace, and its reader is currently an active member there.
2. An export uses the requester, workspace and selected IDs from the trusted stored request. The worker checks their current relationship before generating the artifact.
3. Download separately checks the requester, expiry, current membership and current note visibility before returning private bytes.
4. A denied queued request ends as `denied`, without a committed result slot, encrypted artifact or nonce reservation. Redelivery leaves that terminal state unchanged.

The second rule is part of chapter 28's implemented behavior. The third is the separate release boundary. A control at release can limit the consequence of a generation error; it does not make that generation error disappear.

### Trace each entry point, including unchanged code

An **entry point** is where an operation begins for the path being reviewed. These are service entry points, not HTTP endpoints. The caller supplies a trusted authenticated user ID to the service; the standalone fixture does not authenticate a browser.

In particular, `visible_rows` joins active membership and active users, filters `n.workspace_id`, then applies ordering and a limit. `selected_rows` also checks that every selected note was found in that authorized scope. Counting global rows cannot establish the same fact.

### Ask what each check proves

`require_member(db, 1, 1)` establishes Mina's current membership in Alpha. It does not constrain a later query that selects all notes. Removing `body` from a response establishes its field shape. It does not authorize Beta's title. Validating `202` as an integer establishes a permitted value shape. It does not grant Mina access to Beta note `202`.

The worker's identity is another boundary. It may have database access broader than any requester. The operation must still act on behalf of the requester stored by the trusted service. Replacing `selected_rows` with a query that has no requester or workspace arguments removes that relationship from the generation decision.

Read beyond the added lines. The unchanged `except AccessDenied` still exists, but it cannot catch a denial that the new path never raises. With note `101` still present, revoking Mina does not change the global query's row count.

## 2. SAST, rule scope and taint-flow vocabulary

**Static application security testing**, or **SAST**, analyzes code without exercising the application operation under review. Some rules look for syntax; others model how data moves. A finding is a lead to investigate, not a completed exploit demonstration. OWASP's [source code analysis overview](https://community.owasp.org/Source_Code_Analysis_Tools) describes both its utility and its limits, including access-control analysis.

Python tools may inspect an **abstract syntax tree**, or **AST**: a structured representation of parsed code. It distinguishes a function call, an argument and an f-string without requiring a running database. A syntax rule can see SQL string construction while lacking the runtime knowledge that its inserted values are exact integers.

**Table T29-02. Vocabulary for reading a data-flow claim**

| Term | Meaning | Example or question in this packet |
| --- | --- | --- |
| Source | The origin a rule treats as untrusted or sensitive | Request-selected IDs, or private note rows. State which property the analysis tracks. |
| Propagation | A step that carries the tracked data | JSON decoding, assignment to `ids`, or joining converted IDs into `ids_sql`. |
| Sink | An operation where that property can matter | SQL execution for injection; list serialization or artifact creation for private-data handling. |
| Sanitizer | A check or transformation a rule models as stopping a particular unsafe flow | Exact integer validation constrains SQL grammar in this branch. It does not establish workspace authorization. |
| Path | The branches and calls joining those steps | The `note_ids is None` list branch differs from the worker's selected-ID branch. |
| Reachability | Whether the reviewed entry point can execute that path under stated conditions | Can unvalidated text reach interpolation? Can a revoked request reach encryption? |

The same data can be acceptable for SQL syntax and unacceptable under access policy. Avoid a single label such as “sanitized” without naming the property it protects.

[Semgrep's taint-analysis documentation](https://docs.semgrep.dev/writing-rules/data-flow/taint-mode/overview) describes sources, propagation, sanitizers and sinks. Analysis coverage depends on the rule, language support, engine and configuration. Establish whether a run models calls across functions or files before relying on that behavior. The local rule below is a **search rule**, not a taint rule. It does not claim to follow a requester across the worker pipeline.

### Worked example 1: compare the warning with the actual argument type

Start at the worker call site. It supplies `json.loads(request["note_ids"])` as `note_ids`. JSON decoding alone does not prove a list of integers. The next important line is inside the new helper: `ids = export_selection(note_ids)`.

The relevant existing validator is reproduced here so the proof does not depend on its name:

```python
def positive_id(value):
    return type(value) is int and 1 <= value <= 2**63 - 1


def export_selection(note_ids):
    if (not isinstance(note_ids, (list, tuple)) or not 1 <= len(note_ids) <= 10
            or not all(positive_id(value) for value in note_ids)
            or len(set(note_ids)) != len(note_ids)):
        raise ValueError("select 1 to 10 distinct positive note IDs")
    return tuple(sorted(note_ids))
```

This is a source excerpt from `examples/ch23/authorization_service.py`, not a second implementation to save. It rejects numeric strings, floats, booleans, duplicate IDs, an empty selection and IDs outside the bound. `bool` is a subclass of `int` in Python, so `type(value) is int` matters here. A type hint alone would not perform this check; Python's [typing reference](https://docs.python.org/3.12/library/typing.html) explicitly distinguishes annotations from runtime enforcement.

Now continue through the actual path:

1. The worker supplies a JSON-decoded list.
2. The helper calls `export_selection` before interpolation.
3. A successful call produces a new sorted tuple of exact built-in positive integers.
4. `str(value)` converts those integers into decimal digits; the join inserts only fixed commas.
5. The result is placed inside fixed SQL syntax.

The list branch does not reach interpolation at all. Its limit is bound using `?`, and the public list function separately restricts the limit to an exact integer from 1 to 50.

Predict these two cases. Does `["101) OR 1=1 --"]` reach `execute`? What about `[101, 202]`?

**Listing L29-02. Inspect values at the suspect boundary**

Filename: `examples/ch29/probe_arguments.py`.

```python
from examples.ch23.authorization_service import export_selection, unscoped_rows


class RecordingDB:
    def __init__(self):
        self.calls = []

    def execute(self, sql, *parameters):
        self.calls.append((sql, parameters))
        return []


def main():
    ids = export_selection([202, 101])
    print("after validation:", ids, tuple(type(value).__name__ for value in ids))
    db = RecordingDB()
    unscoped_rows(db, note_ids=ids)
    print("query:", db.calls[0][0])
    before = len(db.calls)
    invalid = (["101) OR 1=1 --"], ["101"], [True], [101.0])
    for values in invalid:
        try:
            unscoped_rows(db, note_ids=values)
        except ValueError:
            continue
        raise AssertionError("invalid selection reached SQL")
    assert len(db.calls) == before
    print("invalid inputs rejected before execute:", len(invalid))


if __name__ == "__main__":
    main()
```

This probe establishes the argument-construction behavior and that the four refused cases never reach `execute`. It does not demonstrate database authorization. For this reviewed branch and validator, no attacker-controlled SQL syntax survives to the interpolated expression. Close the **SQL injection claim** as a false positive for this source revision, with that reasoning. A **false positive** is a reported vulnerability claim that does not hold for the reviewed path. The string-building observation itself is real.

Prefer bound values in maintained SQL anyway. Do not describe parameter binding as the complete fix for this diff. Even perfect binding of `(101, 202)` can select Beta's note for the wrong reader. The second finding concerns that relationship.

### Worked example 2: one helper, two authorization regressions

Start with the smallest fixture: one Alpha note and one Beta note. Mina requests Alpha. `require_member` succeeds for Alpha, then the global list query returns both records. `note_fields` omits bodies but returns both titles. Ravi's Beta list and Lee's Alpha list have the same scope failure.

A second boundary is object movement. In the disposable fixture, move note `101` to Beta after enqueue. The ID remains an integer and the note still exists. ## 4. Confidence, false positives, fixes and regression coverage

**Confidence** describes how well the available evidence supports the finding. **Severity** describes the consequence if the weakness is real under stated conditions. A high-confidence harmless operation and a lower-confidence potentially serious path need different decisions. A scanner's confidence is also separate from the reviewer's confidence after inspecting source and running a test.

### Write two review comments

A useful comment identifies a location, condition, consequence, correction and verification. It also states its disposition: confirmed, closed with evidence, or unresolved pending specific information. “Unsafe query, please fix” leaves too much work for the developer.

**Review comment RC29-01 — close the injection claim with evidence**

### Select regression checks that answer the claim

A **regression check** detects an old error returning after a correction. Prefer observable behavior at the affected boundary over a test that only asks whether a particular helper name appears in source.

**Table T29-05. Checks and their limits**

| Question | Concrete assertion | What it does not establish |
| --- | --- | --- |
| Is a successful list properly scoped? | Mina and Lee get only `101` for Alpha; Ravi gets only `202` for Beta. The response fields omit `body`. | HTTP authentication, routing or browser behavior. |
| Are direct unauthorized lists refused? | Cross-workspace readers receive the chosen 404; anonymous readers receive 403. Stored notes and memberships are unchanged. | That a successful same-workspace list excludes foreign rows; that needs the preceding check. |
| Does queued permission change matter? | Revoke Mina after enqueue. Processing returns `denied`, records `access_denied`, and leaves zero slot/artifact/nonce rows. Redelivery changes nothing. | A live broker, concurrent revocation during an open transaction, or distributed consistency. |
| Does current object scope matter? | Move `101` to Beta after enqueue. Processing refuses without output records. | A public move endpoint or its authorization. |
| Does legitimate behavior survive? | Active Mina gets her note body. One result commits; redelivery returns `duplicate` with identical stored result rows. | Every resource, expiry or cancellation boundary from chapter 28. Retain those earlier tests. |
| Is release independently enforced? | After successful generation, other users and an anonymous reader are denied; revoking Mina denies her next read without changing result rows. | Every possible delivery channel or access already granted to downloaded copies. |

The following suite uses real service calls and disposable SQLite files. The selection test isolates the validator. The release test remains valuable even though it passes on the candidate: it establishes the limit of the demonstrated worker issue.

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory
import unittest

from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from examples.ch23.authorization_service import (
    AccessDenied, export_selection, list_view, revoke_member, snapshot, unit,
)
from examples.ch27.export_crypto import Keyring
from examples.ch28.export_queue import (
    download, enqueue, initialize, inventory, process_request,
)

NOW = 1795683600  # Fixed fixture clock, not the current time.


class ReviewTests(unittest.TestCase):
    def setUp(self):
        self.folder = TemporaryDirectory(prefix="casebook-review-test-")
        self.addCleanup(self.folder.cleanup)
        self.database = Path(self.folder.name) / "casebook.sqlite3"
        initialize(self.database)
        key = AESGCM.generate_key(bit_length=256)
        self.keys = Keyring({"review-test": key}, "review-test")

    def submit(self, **changes):
        values = dict(user_id=1, workspace_id=1, note_ids=[101],
                      client_key="review-001", now=NOW)
        return enqueue(self.database, **(values | changes))

    def process(self, request_id):
        return process_request(self.database, request_id=request_id,
                               keyring=self.keys, now=NOW + 1)

    def read(self, request_id, user_id=1):
        return download(self.database, user_id=user_id, request_id=request_id,
                        keyring=self.keys, now=NOW + 2)

    def assert_denied_state(self, request_id):
        saved = inventory(self.database)
        self.assertEqual(len(saved["export_requests"]), 1)
        request = saved["export_requests"][0]
        self.assertEqual((request["id"], request["state"], request["error"]),
                         (request_id, "denied", "access_denied"))
        for name in ("export_slots", "encrypted_exports", "used_nonces"):
            self.assertEqual(saved[name], [], name)
        return saved

    def test_lists_return_only_the_requested_workspace(self):
        before = snapshot(self.database)
        for user, workspace, note in ((1, 1, 101), (2, 2, 202), (3, 1, 101)):
            with self.subTest(user=user):
                status, rows = list_view(self.database, user_id=user,
                                         workspace_id=workspace)
                self.assertEqual(status, 200)
                self.assertEqual([row["id"] for row in rows], [note])
                self.assertEqual({row["workspace_id"] for row in rows}, {workspace})
                self.assertEqual(set(rows[0]), {"id", "workspace_id", "title"})
        self.assertEqual(snapshot(self.database), before)

    def test_list_refuses_other_workspace_and_anonymous_reader(self):
        before = snapshot(self.database)
        for user, workspace, expected in ((1, 2, 404), (2, 1, 404),
                                           (3, 2, 404), (None, 1, 403)):
            status, body = list_view(self.database, user_id=user, workspace_id=workspace)
            self.assertEqual(status, expected)
            self.assertEqual(set(body), {"error"})
        self.assertEqual(snapshot(self.database), before)

    def test_revoked_queued_request_leaves_no_artifact(self):
        request = self.submit()
        revoke_member(self.database, actor_id=3, workspace_id=1, target_user_id=1)
        before = snapshot(self.database)
        self.assertEqual(self.process(request), "denied")
        saved = self.assert_denied_state(request)
        self.assertEqual(self.process(request), "denied")
        with self.assertRaises(AccessDenied):
            self.read(request)
        self.assertEqual(inventory(self.database), saved)
        self.assertEqual(snapshot(self.database), before)

    def test_note_moved_to_beta_while_queued_is_denied(self):
        request = self.submit()
        # Privileged fixture change models an intervening workspace reassignment.
        with unit(self.database, write=True) as db:
            db.execute("UPDATE notes SET workspace_id=2 WHERE id=101")
        before = snapshot(self.database)
        self.assertEqual(self.process(request), "denied")
        self.assert_denied_state(request)
        self.assertEqual(snapshot(self.database), before)

    def test_active_request_succeeds_and_redelivery_changes_nothing(self):
        request = self.submit()
        self.assertEqual(self.process(request), "created")
        document = json.loads(self.read(request))
        self.assertEqual(document["workspace_id"], 1)
        self.assertEqual([row["id"] for row in document["notes"]], [101])
        self.assertEqual(document["notes"][0]["body"], "Alpha private fixture")
        saved = inventory(self.database)
        self.assertEqual([len(saved[name]) for name in
                          ("export_slots", "encrypted_exports", "used_nonces")], [1, 1, 1])
        self.assertEqual(self.process(request), "duplicate")
        self.assertEqual(inventory(self.database), saved)

    def test_release_keeps_requester_and_current_membership_checks(self):
        request = self.submit()
        self.assertEqual(self.process(request), "created")
        self.assertEqual(json.loads(self.read(request))["notes"][0]["id"], 101)
        saved = inventory(self.database)
        for user in (None, 2, 3):
            with self.assertRaises(AccessDenied):
                self.read(request, user_id=user)
        revoke_member(self.database, actor_id=3, workspace_id=1, target_user_id=1)
        with self.assertRaises(AccessDenied):
            self.read(request)
        self.assertEqual(inventory(self.database), saved)

    def test_selection_rejects_non_integer_and_boundary_inputs(self):
        self.assertEqual(export_selection([202, 101]), (101, 202))
        self.assertEqual(export_selection([2**63 - 1]), (2**63 - 1,))
        for values in (["101) OR 1=1 --"], ["101"], [True], [101.0],
                       [], [0], [-1], [2**63], [101, 101], list(range(1, 12))):
            with self.subTest(values=values), self.assertRaises(ValueError):
                export_selection(values)

    def test_mixed_workspace_selection_is_denied_at_admission(self):
        before = inventory(self.database)
        with self.assertRaises(AccessDenied):
            self.submit(note_ids=[101, 202])
        self.assertEqual(inventory(self.database), before)


if __name__ == "__main__":
    unittest.main()
```

### Keep suppression and closure reviewable

Closing one alert is not the same as accepting a known vulnerability. A false-positive closure records why the claimed flaw is absent. Risk acceptance records a real remaining weakness and its accountable decision. An unresolved item names the evidence still needed.

Do not add a file-wide suppression to make these two cards disappear. If a real project keeps a safe operation that a rule cannot model, use its supported narrow suppression or triage mechanism, attach the proof and regression check, and state when to revisit it. Avoid silently suppressing future findings at unrelated call sites. Here, the complete correction removes the newly introduced helper, so no suppression is needed.

Finally, a **false negative** is a real weakness a tool fails to report. A zero-finding run can coexist with a missed authorization error, skipped source or a rule that never models the relevant path. A release decision needs the relevant behavioral evidence and known coverage gaps, not only an alert count.
