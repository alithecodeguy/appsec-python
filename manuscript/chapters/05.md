Casebook now has six notes across two workspaces. How can you group them without losing their workspace information? If you add a role to Mina's account, how can you check that Ravi's roles stay intact?

Chapter 04 used individual values to make decisions and a small tuple to repeat three scenarios. This chapter introduces collections that hold multiple values. You will also follow a mistake in which two users accidentally share the same editable list.

Begin in `casebook-learning` with the `.venv` interpreter from chapter 02. You need assignments, comparisons, loops and the distinction between equality and identity from chapters 03–04.

By the end, you will be able to do four things.

- Choose a list, tuple, set or dictionary for a small data task.
- Find items with indexes, slices, membership checks and dictionary lookups.
- Trace changes to shared objects and choose where a copy is needed.
- Group six note records and print a summary in a predictable order.

Save each listing under its supplied filename. On Windows, run it using the following command, replacing the filename for each example.

```powershell
.\.venv\Scripts\python.exe collection_shapes.py
```

On macOS and Linux, use the following.

```shell
./.venv/bin/python collection_shapes.py
```

## 1. Choose a collection for the information you need

A **collection** holds multiple values. Its rules determine whether order matters, whether duplicates remain and how you retrieve an item.

**Table T05-01. Four collection choices**

| Collection | Example | Useful property | Casebook use |
| --- | --- | --- | --- |
| List | `[1, 2, 3]` | Ordered, allows duplicates, editable | Notes to process in a chosen order |
| Tuple | `("Mina", "Alpha")` | Ordered, fixed positions | A small pair of related values |
| Set | `{"member", "manager"}` | Holds distinct values, supports membership checks | Recognized role names |
| Dictionary | `{"workspace": "Alpha"}` | Maps unique keys to values | Fields in one note record |

An editable object is **mutable**. Lists, sets and dictionaries are mutable. A tuple's item references are fixed once it is created. If a tuple contains a mutable list, that list can still change. The choice of an outer container does not automatically protect its nested contents.

### Read the literal forms

Square brackets create a list. Commas separate its items. A tuple can be written with parentheses and commas. For a one-item tuple, keep the comma, as in `("Alpha",)`. Without that comma, `("Alpha")` is a parenthesized string expression.

Braces containing values create a set. Braces containing key/value pairs create a dictionary. Empty braces, `{}`, create an empty dictionary. Use `set()` for an empty set. An empty list is `[]`, and an empty tuple is `()`.

A dictionary **key** identifies an associated value. In `{"workspace": "Alpha"}`, the key is `"workspace"` and its value is `"Alpha"`. For now, use strings or integers as keys. Keys and set members must be **hashable**, a property supporting lookup. Lists and dictionaries are unsuitable as keys or set members. A tuple is suitable only if all its contents are hashable.

**Listing L05-01. Inspecting four collection shapes**

Filename: `collection_shapes.py`.

```python
note_ids = [1, 2, 3]
membership = ("Mina", "Alpha")
known_roles = {"member", "manager"}
note = {"id": 1, "workspace": "Alpha", "title": "Release plan"}

print(note_ids)
print(membership)
print(len(known_roles))
print(note["workspace"])
```

`len` returns the number of items in a collection. The dictionary lookup in the last line retrieves the value associated with the supplied key.

The expected output is the following.

```text
[1, 2, 3]
('Mina', 'Alpha')
2
Alpha
```

There are three list items, two tuple items, two set members and three dictionary entries. A dictionary's size counts its keys, independently of the size of each stored value.

### Preserve the meaning of duplicate values

A list can record the same role more than once. A set removes duplicates according to value equality. That is useful for answering which role names occur. Counting distinct roles answers a different question from counting memberships.

**Worked example 1. Count memberships and distinct role names**

The three entries below describe Mina's Alpha membership, Lee's Alpha management role and Ravi's Beta membership, in that order. Each list entry contributes one membership's role.

**Listing L05-02. Removing duplicate role names**

Filename: `distinct_roles.py`.

```python
membership_roles = ["member", "manager", "member"]
unique_roles = set(membership_roles)

print(f"Membership records {len(membership_roles)}")
print(f"Distinct role names {len(unique_roles)}")
print("member" in unique_roles)
print("owner" in unique_roles)
```

The `in` operator asks whether a collection contains an item. The expected output is the following.

```text
Membership records 3
Distinct role names 2
True
False
```

Both Mina and Ravi have a `member` role, but in different workspaces. Counting two distinct role names preserves no information about which user belongs to which workspace. Keep those relationships in records when making access decisions.

## 2. Retrieve values without hiding missing information

Lists and tuples use **indexes**, integer positions starting at zero. Dictionaries use keys. Sets support membership checks, but have no positional index.

**Listing L05-03. Indexing, slicing and membership**

Filename: `note_positions.py`.

```python
note_ids = [1, 2, 3, 4, 5, 6]

print(note_ids[0])
print(note_ids[-1])
print(note_ids[1:3])
print(note_ids[6:9])
print(4 in note_ids)
print(7 not in note_ids)
```

Before running it, write down the item at index one and decide whether a slice ending at three includes index three.

The expected output is the following.

```text
1
6
[2, 3]
[]
True
True
```

The first item is at index zero. A negative index counts backward from the end, so `-1` selects the last item. A **slice** such as `[1:3]` selects from the starting index through the item before the stop index. Here it includes indexes one and two.

A slice can reach beyond the available items and return a shorter or empty list. Directly requesting a nonexistent item, such as `note_ids[6]`, raises `IndexError`. An empty list also has no item at index zero or minus one. Check whether there are items before asking for a first or last one.

`not in` asks whether a value is absent. In a dictionary, `in` and `not in` examine keys. If you need to inspect dictionary values instead, its `.values()` method supplies them.

### Look up a field and keep absence distinct

Use square brackets for a required key. `note["title"]` retrieves the title or raises `KeyError` if it is absent. For an optional field, `.get` can return a chosen default.

A **method** is an operation accessed through an object. Read `note.get(...)` as “call the dictionary's lookup method.” The dot connects the object to its method, just as the earlier `sys.executable` expression accessed information through a module.

**Listing L05-04. A missing key and an explicit missing value**

Filename: `optional_fields.py`.

```python
note = {"id": 1, "workspace": "Alpha", "title": "Release plan"}

print(note["title"])
print(note.get("reviewer", "Unassigned"))
print("reviewer" in note)

note["reviewer"] = None
print(note.get("reviewer", "Unassigned"))
print("reviewer" in note)
```

The expected output is the following.

```text
Release plan
Unassigned
False
None
True
```

The assignment adds a `reviewer` key with value `None`. `.get` uses its default only when the key is absent. A present `None` remains `None`. Calling `.get` without a default returns `None` for an absent key too, so a separate membership check may be needed when those states have different meanings.

Assigning to an existing dictionary key replaces its value. Repeating a key in a dictionary literal also leaves the last supplied value for that key. Preserve separate note records in a list instead of trying to store several notes under the same dictionary key without a containing collection. [Dictionary and sequence operations](https://docs.python.org/3.12/library/stdtypes.html)

### Defaults are lookup results

Suppose a dictionary has no `"Beta"` key. Calling `grouped.get("Beta", [])` gives you an empty list for that call. It does not add an entry to `grouped`. Appending to that temporary list would leave the dictionary unchanged. In the grouping example below, you will first store a new list under the key and then append to it.

## 3. Trace mutation, aliasing and copies

**Mutation** changes an existing object. Calling a list's `.append` method adds one item to its end. A second name for that same list will observe the change.

An **alias** is another reference to the same object. Assignment creates a binding to an object. It does not automatically copy the object. You saw reassignment with integers in chapter 03. Here you will change a list while its existing references remain in place.

### Worked example 2. Two users share one role list

The roles below belong within each user's own workspace. Mina belongs to Alpha and Ravi belongs to Beta. These fictional role collections will let you inspect an accidental state change without altering any real account.

**Listing L05-05. The shared-list mistake**

Filename: `shared_roles.py`.

```python
default_roles = ["member"]
roles_by_user = {
    "Mina": default_roles,
    "Ravi": default_roles,
}

print(roles_by_user["Mina"] is roles_by_user["Ravi"])
roles_by_user["Mina"].append("manager")
print(roles_by_user["Mina"])
print(roles_by_user["Ravi"])
```

Predict Ravi's final list before running the file.

```text
True
['member', 'manager']
['member', 'manager']
```

The identity check produces `True`. Both dictionary entries refer to one list. Appending through the Mina entry changes that shared object, so the Ravi entry also shows the added role.

**Table T05-02. References before and after the mutation**

| Reference | Before append | After append |
| --- | --- | --- |
| `default_roles` | Shared list containing `"member"` | Same list now also contains `"manager"`. |
| `roles_by_user["Mina"]` | Refers to the shared list. | Observes the added role. |
| `roles_by_user["Ravi"]` | Refers to the shared list. | Observes the same added role. |

If an authorization system used these lists as trusted role state, that accidental mutation could change Ravi's permissions. The intended update belonged only to Mina's Alpha role collection. The data representation needs to preserve that ownership.

### Create separate lists and check the result

For a flat list of immutable role-name strings, `.copy()` creates a separate outer list suitable for independent appends.

**Listing L05-06. Independent role collections**

Filename: `independent_roles.py`.

```python
default_roles = ["member"]
roles_by_user = {
    "Mina": default_roles.copy(),
    "Ravi": default_roles.copy(),
}

print(roles_by_user["Mina"] is roles_by_user["Ravi"])
roles_by_user["Mina"].append("manager")
print(roles_by_user["Mina"])
print(roles_by_user["Ravi"])
print("Ravi unchanged", roles_by_user["Ravi"] == ["member"])
print("Defaults unchanged", default_roles == ["member"])
```

The expected output is the following.

```text
False
['member', 'manager']
['member']
Ravi unchanged True
Defaults unchanged True
```

Two checks matter. The identity result shows that the lists are separate objects. The value comparison after the append shows that Ravi's roles still have their expected contents. Printing only Mina's updated roles would miss the effect on another user.

Writing two separate list literals, one for each user, would also create independent lists. Copying is useful when both initial values come from an established template.

### A shallow copy still shares nested objects

A **shallow copy** creates a new outer collection while retaining references to its items. Copying a dictionary with a nested list therefore needs extra thought.

**Listing L05-07. Separate records with a shared nested list**

Filename: `nested_roles.py`.

```python
template = {"roles": ["member"]}
mina = template.copy()
ravi = template.copy()

print(mina is ravi)
print(mina["roles"] is ravi["roles"])
mina["roles"].append("manager")
print(ravi["roles"])
```

The expected output is the following.

```text
False
True
['member', 'manager']
```

The dictionaries differ, but their `roles` values refer to the same list. For this simple record shape, create each dictionary with a separate copy of the role list. The next listing begins with a fresh template.

**Listing L05-08. Copying at the boundary that needs independence**

Filename: `independent_records.py`.

```python
template = {"roles": ["member"]}
mina = {"roles": template["roles"].copy()}
ravi = {"roles": template["roles"].copy()}

mina["roles"].append("manager")
print(mina["roles"])
print(ravi["roles"])
print(mina["roles"] is ravi["roles"])
```

The expected output is the following.

```text
['member', 'manager']
['member']
False
```

For larger nested structures, Python supplies `copy.deepcopy` to recursively copy supported objects. Choose copies according to which data should have independent ownership. Some references are intentionally shared. The small examples here make that choice explicit for the role list. [Python's copying reference](https://docs.python.org/3.12/library/copy.html)

Slicing a list with `[:]` also makes a shallow outer copy. Neither slicing nor `.copy()` automatically isolates a nested dictionary or list. Likewise, placing a list inside a tuple leaves that nested list mutable.

## 4. Transform and group records with predictable output

A **comprehension** builds a collection from an iterable using an expression and, optionally, a condition. Start with a task you could already write as a loop.

**Listing L05-09. Selecting and ordering note identifiers**

Filename: `selected_ids.py`.

```python
note_ids = [5, 1, 3, 2]
selected_ids = [note_id for note_id in note_ids if note_id < 4]

print(selected_ids)
print(sorted(selected_ids))
print(note_ids)
```

Read the comprehension in three parts. Visit each `note_id` from `note_ids`. Keep it when `note_id < 4`. Place that value in the new list.

The expected output is the following.

```text
[1, 3, 2]
[1, 2, 3]
[5, 1, 3, 2]
```

The comprehension preserves the order of the selected input items. `sorted` returns a new ordered list, leaving its input intact. By contrast, `selected_ids.sort()` changes that existing list and returns `None`. Keep that distinction in mind when assigning a function or method's result.

Lists and tuples retain their item order. Dictionaries retain insertion order, but that order reflects how keys were added. Sets provide no guaranteed iteration order. Use an explicit sort when the output must be stable across different input orders or repeated runs. The items must also support the requested ordering. Arbitrarily mixed strings and integers cannot be sorted together using their default comparisons. [Python's sorting guide](https://docs.python.org/3.12/howto/sorting.html)

You can also build a set with `{expression for item in source}` or a dictionary with `{key_expression: value_expression for item in source}`. Choose a comprehension when it expresses one clear transformation. A grouping task with several updates is often easier to trace as an ordinary loop. [Comprehension syntax](https://docs.python.org/3.12/reference/expressions.html#displays-for-lists-sets-and-dictionaries)

### Group all six notes

Each note is a dictionary containing its identifier, workspace and title. A list holds the six records. `grouped` will map workspace names to lists of note records.

**Listing L05-10. Grouping a six-note inventory**

Filename: `group_notes.py`.

```python
notes = [
    {"id": 1, "workspace": "Alpha", "title": "Release plan"},
    {"id": 2, "workspace": "Beta", "title": "Pricing review"},
    {"id": 3, "workspace": "Alpha", "title": "Support rota"},
    {"id": 4, "workspace": "Beta", "title": "Team notes"},
    {"id": 5, "workspace": "Alpha", "title": "برنامه انتشار"},
    {"id": 6, "workspace": "Beta", "title": "Operations review"},
]

grouped = {}

for note in notes:
    workspace = note["workspace"]
    if workspace not in grouped:
        grouped[workspace] = []
    grouped[workspace].append(note)

grouped_count = 0
for workspace in sorted(grouped):
    workspace_notes = grouped[workspace]
    note_ids = [note["id"] for note in workspace_notes]
    grouped_count = grouped_count + len(workspace_notes)
    print(workspace, sorted(note_ids))

print("Total grouped", grouped_count)
print("All notes grouped", grouped_count == len(notes))
```

The title `برنامه انتشار` is ordinary Unicode text. Save the source file as UTF-8, the usual default in a code editor. Chapter 07 examines characters and encoded bytes in detail.

Before running the file, write the identifiers that you expect under each workspace. Then predict the total.

```text
Alpha [1, 3, 5]
Beta [2, 4, 6]
Total grouped 6
All notes grouped True
```

The first loop creates one list for each newly encountered workspace. Appending afterward stores each note in the appropriate list. The second loop sorts workspace names and each group's identifiers for stable output.

**Table T05-03. Group membership after each input record**

| Note processed | Alpha identifiers | Beta identifiers |
| --- | --- | --- |
| 1 | `1` | No Beta group yet |
| 2 | `1` | `2` |
| 3 | `1, 3` | `2` |
| 4 | `1, 3` | `2, 4` |
| 5 | `1, 3, 5` | `2, 4` |
| 6 | `1, 3, 5` | `2, 4, 6` |

The grouping lists refer to the original note dictionaries. Editing a grouped note would therefore edit that same record in `notes`. This example deliberately builds another view of the records and only reads them afterward. Use a separately constructed record or an appropriate copy if a later operation needs independent editable data.

The total check establishes that six records were appended. It cannot by itself prove correct assignment to workspaces. Compare the identifiers in both groups with the expected table too. This grouping exercise organizes known records; the service's membership checks will still determine who may see them.

### Empty collections and unexpected workspace names

If `notes` is `[]`, both loops execute zero times. The final output is `Total grouped 0` and `All notes grouped True`, on separate lines. The empty input has been fully accounted for, while providing no evidence about behavior on nonempty input.

If a record has a new workspace name, the grouping loop creates a new key and list for it. That is the behavior of this general grouping operation. A service that accepts only registered workspace identifiers must validate the record's workspace before using the group as trusted application data.

## Worked answers

### Exercise 1

There are four membership records and two distinct role names. A set of those names has length two. It loses the repeated occurrences needed to infer how many membership records contributed the role values. Keep the original records when the application needs their count or associated users and workspaces.

### Exercise 2

The results are `3`, `[3, 4, 5]` and `5`. The slice includes indexes two, three and four. The negative index selects the second item from the end.

### Exercise 3

Each `.copy()` makes a new dictionary, but its `roles` value still refers to the template's existing list. The mutable role list needs independent ownership for each user. Listing L05-08 creates that boundary by copying the list when constructing each user's record.

### Exercise 4

The dictionary remains `{}`. `.get` supplies a temporary empty list, and `.append(1)` changes that list. The dictionary never receives an `"Alpha"` entry. Store the empty list first with `grouped["Alpha"] = []`, then call `grouped["Alpha"].append(1)`.

For the direct grouping task, `grouped["Alpha"] = [1]` also gives the intended result. Listing L05-10 uses a conditional insertion so that appending later notes preserves earlier entries.

### Exercise 5

Six appends can occur even when a record enters the wrong group. Identifier `2` belongs to Beta in the fixture. Compare each group's identifiers against the expected workspace assignment, as well as checking the total. Alpha should contain `[1, 3, 5]` and Beta should contain `[2, 4, 6]`.

### Practice check

Listing L05-10 produces the required groups and total. Listing L05-06 produces Mina's `['member', 'manager']` and Ravi's `['member']`, with the identity comparison false and both unchanged-value checks true. Running those two complete files is one way to verify the checkpoint. Combining their independent sections into one file gives the same required observations.

Your checks must examine the state after the append. A correct starting list says little about what a shared reference may do during an update.

## Glossary

| Term | Meaning in this chapter |
| --- | --- |
| Alias | Another reference to the same object |
| Collection | An object holding multiple values |
| Comprehension | An expression that builds a collection from another iterable |
| Dictionary | A collection mapping unique keys to values |
| Hashable | Suitable for hash-based lookup, as required of dictionary keys and set members |
| Index | An integer position in a sequence, starting at zero |
| Key | A value identifying an entry in a dictionary |
| Method | An operation accessed through an object |
| Mutable | Able to change while retaining the same object identity |
| Mutation | A change to an existing object |
| Set | A collection of distinct hashable values |
| Shallow copy | A new outer collection retaining references to its items |
| Slice | A selection of sequence items using start, stop and optionally step |
| Tuple | An ordered collection with fixed item references |
