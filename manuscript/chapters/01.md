Can you predict exactly what a small Python program will display, and explain who should see a private note?

You can begin with paper and a pencil. Read each example, write your prediction and compare it with the expected output. Chapter 02 will help you install Python and run the same examples on your computer.

By the end of this chapter, you will be able to do four things.

- Identify the data, instruction and output in a small program.
- Explain how a saved Python file becomes a running program.
- Read a quoted string and a call to `print`.
- Explain the access rule for a private Casebook note.

The examples use fictional records. Casebook is the application you will build throughout the book. It stores notes for teams. Each team has a **workspace**, which is a shared area for its members and their notes.

## 1. Follow input, steps and output

A **program** is a set of instructions a computer can execute. **Execute** means carry out. A program may receive data, process it and produce a result.

Consider a person sorting envelopes. The names on the envelopes provide data. The person follows a delivery rule. The sorted envelopes are the result. A software program also needs both data and instructions.

Our first program displays three pieces of text. In Python, `print` asks the program to write something to its output. For these exercises, imagine that output appearing on a screen. Read `print("Alpha")` as “display the text Alpha, then move to the next line.”

**Listing L01-01. A three-line display for a fictional note**

Filename when you save it later: `first_note.py`.

```python
print("Release plan")
print("Alpha")
print("Deny")
```

Before reading further, copy the three lines onto paper. Beside each line, write the text you expect to appear. Keep the letters, spaces and capital letters exactly as shown inside the quotes.

The expected output is the following.

```text
Release plan
Alpha
Deny
```

Trace the program one instruction at a time. Start at the top. After each instruction, add its output below the output already written.

**Table T01-01. A paper trace of the first program**

| Instruction executed | Text added to the output | Next output begins on |
| --- | --- | --- |
| `print("Release plan")` | `Release plan` | Line 2 |
| `print("Alpha")` | `Alpha` | Line 3 |
| `print("Deny")` | `Deny` | Line 4 |

The third call ends its output line too. Your pencil can represent this by moving to the next empty line. The three calls produce three lines of text.

### Where is the input?

**Input** is data supplied to an operation. Here, each piece of quoted text is input to `print`. The author supplies this data directly in the program. Running these three instructions requires no typing from the person watching the output.

Later, input will come from places such as a file, a web request or a database. For now, follow data that you can see directly in the instructions.

| Input data | Instruction that uses it | Resulting output text |
| --- | --- | --- |
| The text `Release plan` | `print("Release plan")` | `Release plan` |
| The text `Alpha` | `print("Alpha")` | `Alpha` |
| The text `Deny` | `print("Deny")` | `Deny` |

The third line displays a decision supplied by the author. It displays `Deny` every time the program runs successfully. A later chapter will teach the program how to choose a decision from membership information.

**Check your understanding.** If you exchange the first and second instructions, which output line changes? Write the complete result before moving on.

## 2. Understand what runs a Python instruction

The text of a program is called **source code**, often shortened to **code**. A text file containing Python source code can be called a **script**. Python filenames commonly end in `.py`, as in `first_note.py`.

The **Python interpreter** is the program that carries out Python code. This book uses CPython, a widely used implementation of Python. You give it a script to run. It checks and processes the code, then executes valid instructions.

For our three-line script, successful execution follows the instructions from top to bottom. Chapter 04 introduces instructions that choose or repeat steps.

An **editor** helps you create and change the text of a script. Saving a file records that text on your computer. Running the file asks an interpreter to execute it. If you change the text in the editor, save it before running the file again.

### Read the saved file as plain text

When you save Listing L01-01, the file contains the three Python instructions shown in that listing. The filename identifies the file. The expected-output block shows what its instructions produce during execution.

A Markdown code block is a way this book displays code clearly. The opening and closing fences around a block belong to the book's formatting. Copy the three instructions inside the Python block into your `.py` file.

Keep the expected output in your exercise notes. When you run the script later, compare the interpreter's output with that prediction.

### Running the examples after setup

Chapter 02 explains the **terminal**, the place where you enter commands, and how to reach the folder containing your script. Once that setup is complete, you can run this chapter's saved files with the appropriate command below.

For Windows, using the Python launcher from chapter 02, enter the following command.

```shell

```

For macOS or Linux, enter the following command.

```shell

```

These commands ask the selected Python interpreter to run `first_note.py`. Chapter 02 checks that the selected interpreter matches the book's edition. Use the same command form for later listings in this chapter, replacing the filename with the one given above the listing.

## 3. Read strings and function calls

Look closely at one instruction.

```python
print("Release plan")
```

A **function** is a named operation that you can ask a program to perform. A **function call** asks for that operation to run. This instruction calls the function named `print`.

An **argument** is a value supplied in a function call. Here, the argument is the text `Release plan`.

**Table T01-02. The parts of a call**

| Part of the code | How to read it |
| --- | --- |
| `print` | The name of the function |
| `(` | The start of the call's argument area |
| `"Release plan"` | A quoted text value supplied as an argument |
| `)` | The end of the call |

A text value in Python is called a **string**. Writing the text directly between quote marks creates a **string literal**. The quote marks tell Python where that text starts and ends. The string's contents are the characters between them.

For the calls in this chapter, `print` writes the string's contents and then a newline. A **newline** ends an output line. It makes subsequent output begin on the next line. The function's full interface has more options, which you will meet when they are useful. [Python documentation for `print`](https://docs.python.org/3.12/library/functions.html#print)

### Worked example 1. Predict every character in a title

Return to `first_note.py`. Focus on its first output line, `Release plan`.

| Position | Character |
| --- | --- |
| 1 | `R` |
| 2 | `e` |
| 3 | `l` |
| 4 | `e` |
| 5 | `a` |
| 6 | `s` |
| 7 | `e` |
| 8 | One space |
| 9 | `p` |
| 10 | `l` |
| 11 | `a` |
| 12 | `n` |
| After the title | A newline |

The initial `R` is a capital letter. The space between the words is part of the string. The output line starts with `R` and ends with `n`. The quote marks and parentheses have jobs in the source code and produce no characters in this output.

Write this title on paper. Underline the single space and draw a downward arrow after the final `n` to represent the newline. These marks are annotations in your notebook.

### Worked example 2. Change one quoted word

Change the word `plan` to `notes`. Keep the other two instructions the same.

**Listing L01-02. The same display with a different title**

Filename when saved: `changed_note.py`.

```python
print("Release notes")
print("Alpha")
print("Deny")
```

Predict all three output lines before looking below.

```text
Release notes
Alpha
Deny
```

The changed first line has 13 characters before its newline. Positions 1–8 still contain `Release` followed by one space. Positions 9–13 now contain `n`, `o`, `t`, `e`, `s`, followed by the newline.

**Table T01-03. Comparing the two runs**

| Output line | Original script | Changed script |
| --- | --- | --- |
| 1 | `Release plan` followed by a newline | `Release notes` followed by a newline |
| 2 | `Alpha` followed by a newline | `Alpha` followed by a newline |
| 3 | `Deny` followed by a newline | `Deny` followed by a newline |

This is a useful programming habit. Change one thing, predict its effect and compare the result with the prediction.

### A boundary case. Empty text

A string can contain zero characters. Two adjacent quote marks represent an **empty string**.

**Listing L01-03. An empty title**

Filename when saved: `empty_title.py`.

```python
print("")
print("Alpha")
print("Deny")
```

The first call still writes its newline. The complete expected output starts with an empty line.

```text

Alpha
Deny
```

You can check this on paper by drawing three output lines. Leave line 1 empty, put `Alpha` on line 2 and put `Deny` on line 3.

Compare an empty string with `" "`, which contains one space. Their first output lines can look identical on a screen. One contains zero characters before the newline. The other contains one space before the newline. Exact output includes spaces even when they are hard to see.

### Recognize a damaged instruction

Python expects the parts of an instruction to fit its language rules. Those rules are called **syntax**.

Here is a damaged fragment with a missing closing quote.

```text
print("Release plan)
```

The fragment starts quoted text without closing it. Python reports a `SyntaxError`, which means it cannot parse the source as valid Python code. Read the highlighted line and check its quote marks. Exact error wording and display can vary with the interpreter version. Chapter 09 develops a method for reading errors.

For these examples, use straight double quotes, `"`, as shown in the listings. Some writing applications replace them with curved quotation marks. A code editor helps preserve the characters needed for Python source.

**Check your understanding.** What is the argument in `print("Deny")`? Which characters reach the output, and what follows them?

## 4. Explain what a private note needs to protect

Application security, or **AppSec**, is the work of helping an application protect its users, data and operations.

The title in our examples belongs to a fictional note in Alpha. Casebook has two workspaces, Alpha and Beta. Mina is an active Alpha member. Ravi is an active Beta member. Lee manages Alpha. A visitor has no account.

Our rule is that a reader must be an active member of a note's workspace at the time of the read. Lee's management authority applies inside Alpha.

**Table T01-04. Human decisions for an Alpha note**

| Person at the time of the read | Relevant fact | May read the Alpha note? |
| --- | --- | --- |
| Mina | Active member of Alpha | Allow |
| Ravi | Belongs to Beta and has no Alpha membership | Deny |
| Lee | Manages Alpha | Allow |
| Visitor | Has no account or workspace membership | Deny |
| Mina after leaving Alpha | Her Alpha membership is no longer active | Deny |

Read one row aloud. “Ravi belongs to Beta. The note belongs to Alpha. Ravi has no Alpha membership, so access is denied.” The decision needs information about both the reader and the note.

### Connect the rule to the first program

Listing L01-01 displays the supplied decision `Deny`. Its three calls contain only text to display. The reader's identity and current membership are absent from those calls. Changing the text to `Allow` would make the program display `Allow` for everyone who runs it.

In chapter 04, you will introduce information about the reader and teach Python how to choose between outcomes. Here, use the permission table to make the choice yourself. Then distinguish that human decision from the fixed word the script displays.

Displaying private content is itself a release of information. In the finished application, the permission check must happen before private content is sent to a reader. These first exercises use fictional titles so you can study output directly.

### Three questions an engineer asks

| Question | Casebook example | Security term |
| --- | --- | --- |
| Who may see the information? | Ravi must receive no Alpha note content. | Confidentiality |
| Who may change the information? | A reader's ability to edit needs its own rule. | Integrity |
| Can permitted people use the service when needed? | Mina should be able to open her team's notes when the service is operating. | Availability |

These terms will return throughout the book. For this chapter, concentrate on the first question. If Mina leaves Alpha after asking for a note, which fact must Casebook check before it gives her the content?

## Glossary

| Term | Meaning in this chapter |
| --- | --- |
| Argument | A value supplied to a function call |
| Execute | Carry out an instruction |
| Function | A named operation a program can ask to perform |
| Function call | An instruction asking a function to perform its operation |
| Input | Data supplied to a program or operation |
| Interpreter | A program that executes Python code |
| Newline | An output character that ends a line |
| Output | A result a program produces, such as displayed text |
| Script | A file containing Python code to run |
| Source code | The text of a program |
| String | A text value |
| String literal | Text written directly inside quotes in source code |
| Syntax | The language rules that describe how code is written |
| Workspace | A shared area for a team's notes and members |
