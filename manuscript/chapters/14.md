# 14. Command-line tools and child processes

Can another program read Casebook's note count without mistaking an error message for a number? What happens when the input filename contains spaces, or a helper takes too long to finish?

A **command-line interface**, or **CLI**, accepts arguments from a launcher and reports a result through output streams and an exit code. This chapter builds a small local CLI with a written contract. You will run it directly, read input from a pipe and ask a fixed helper process to count the same inventory.

Begin in the `casebook-learning` folder from chapter 02. You need file and JSON handling from chapter 08, exception handling from chapter 09 and pytest from chapter 12. Chapter 13 established the meaning of stdout, stderr and startup exit codes. These listings stand alone: keep chapter 13's `casebook_settings.py` and `casebook_start.py`, but do not import them here. Counting a local fixture requires no service credential.

By the end, you will be able to:

- Define a subcommand, its arguments and generated help with `argparse`.
- Report a count, an input error and a timeout through distinct output contracts.
- Pass a filename with spaces to a fixed helper without constructing a shell command.
- Set input, output and time budgets, and remove temporary input after success or failure.

This tool counts synthetic inventories supplied by the local operator. It provides no web access and makes no membership decision. Possessing a local file is not proof of current Casebook authorization. A deployed private-note read still needs the active-workspace-membership check from the book's recurring rule.

## 1. `argparse` subcommands, help and arguments

An **argument** is one item given to a program. In `count "team notes.json"`, the shell removes the grouping quotes and passes two items: `count` and `team notes.json`. The space inside the second item remains part of that filename.

A **subcommand** selects an operation. Our only operation is `count`. A **positional argument** gets its meaning from its position; here it names the input. An **option** begins with a flag such as `--via-helper` or `--timeout`.

Python's `argparse` module checks arguments and generates help. `add_subparsers(required=True)` requires the operation name. `add_argument("source")` requires an input. `action="store_true"` creates a boolean flag that is `False` unless present. This differs from chapter 13's environment values: the parser itself supplies the boolean.

**Table T14-01. The command surface**

| Invocation after `note_cli.py` | Meaning |
| --- | --- |
| `--help` | Describe available operations |
| `count --help` | Describe count arguments |
| `count "team notes.json"` | Read one UTF-8 JSON inventory from a file |
| `count -` | Read an inventory from standard input |
| `count --via-helper "team notes.json"` | Ask the fixed helper to read that file |
| `count --via-helper --timeout 1 -` | Stage standard input, then allow the helper one second |
| `count -- "-draft.json"` | Treat the leading hyphen as part of a filename |

`--` ends option parsing for the count subcommand. It protects filenames beginning with a hyphen from being treated as options. A filename consisting of `-` is reserved for standard input; use `./-` to name an actual file with that name.

We disable abbreviated options with `allow_abbrev=False`. A caller must write `--via-helper`, rather than relying on an abbreviation that might become ambiguous after a later change.

### Define the input before counting it

The inventory is one JSON array of normalized records. It uses the `id`, `workspace` and `title` fields and the `Alpha` and `Beta` workspace names from chapters 05 and 11. The new filename deliberately contains a space.

**Listing L14-01. A three-note fixture**

Filename: `team notes.json`.

```json
[
  {"id": 1, "workspace": "Alpha", "title": "Release plan"},
  {"id": 2, "workspace": "Beta", "title": "Pricing review"},
  {"id": 5, "workspace": "Alpha", "title": "برنامه انتشار"}
]
```

Predict the result: three array items should produce `3`, followed by a newline. An empty array should produce `0`. An object such as `{}` is not an inventory and must produce no count.

The policy accepts at most 65,536 input bytes and 1,000 notes. Every note must have exactly the three named fields, a unique integer ID from 1 through 999999, a known workspace and a nonblank title of at most 200 characters. These are local format rules, not permission checks.

**Listing L14-02. Bounded input and one shared counting rule**

Filename: `note_count_core.py`.

```python
import json
from pathlib import Path
from typing import BinaryIO


MAX_INPUT_BYTES = 65_536
MAX_NOTES = 1_000


class InputError(ValueError):
    """An expected problem with the supplied inventory."""


def read_payload(stream: BinaryIO) -> bytes:
    try:
        payload = stream.read(MAX_INPUT_BYTES + 1)
    except OSError:
        raise InputError("error: cannot read input") from None
    if len(payload) > MAX_INPUT_BYTES:
        raise InputError("error: input exceeds 65536 bytes")
    return payload


def read_path(path: Path) -> bytes:
    try:
        with path.open("rb") as stream:
            return read_payload(stream)
    except OSError:
        raise InputError("error: cannot read input") from None


def count_payload(payload: bytes) -> int:
    if len(payload) > MAX_INPUT_BYTES:
        raise InputError("error: input exceeds 65536 bytes")
    try:
        notes = json.loads(payload.decode("utf-8"))
    except (UnicodeDecodeError, json.JSONDecodeError, RecursionError):
        raise InputError("error: input must be UTF-8 JSON") from None

    if type(notes) is not list:
        raise InputError("error: invalid note inventory")
    if len(notes) > MAX_NOTES:
        raise InputError("error: inventory exceeds 1000 notes")

    seen = set()
    for note in notes:
        if type(note) is not dict or set(note) != {"id", "workspace", "title"}:
            raise InputError("error: invalid note inventory")
        note_id = note["id"]
        workspace = note["workspace"]
        title = note["title"]
        if (
            type(note_id) is not int
            or not 1 <= note_id <= 999999
            or note_id in seen
            or type(workspace) is not str
            or workspace not in {"Alpha", "Beta"}
            or type(title) is not str
            or not title.strip()
            or len(title) > 200
        ):
            raise InputError("error: invalid note inventory")
        seen.add(note_id)
    return len(notes)
```

`BinaryIO` describes a binary stream: reading it returns bytes. Reading the limit plus one byte lets the program detect overflow without loading the rest. Decoding explicitly as UTF-8 preserves the Persian title and rejects invalid encoding. The exact-type ID check excludes JSON `true`, which becomes Python `True`.

All validation finishes before a count is returned. A malformed last record cannot leave a partial success number on stdout. Errors use fixed messages; private titles and filesystem exception details do not enter diagnostics.

## 2. Standard input, standard output, standard error and exit codes

**Standard input**, or **stdin**, supplies data from the launcher. **Standard output**, or **stdout**, carries the command's normal result. **Standard error**, or **stderr**, carries its diagnostic. A launcher can capture them separately.

An **exit code** is a small integer the process returns to its launcher. Zero means success. The meanings of nonzero codes belong to this tool's documented contract. Code `3` is our timeout choice; another tool may use a different number.

**Table T14-02. The note-count result contract**

| Outcome | Stdout | Stderr | Exit code |
| --- | --- | --- | --- |
| Three valid notes | `3\n` | Empty | `0` |
| Empty array | `0\n` | Empty | `0` |
| Missing or unreadable file | Empty | `error: cannot read input\n` | `2` |
| Invalid UTF-8 or JSON | Empty | `error: input must be UTF-8 JSON\n` | `2` |
| Invalid record or top-level shape | Empty | `error: invalid note inventory\n` | `2` |
| Input byte limit exceeded | Empty | `error: input exceeds 65536 bytes\n` | `2` |
| Record limit exceeded | Empty | `error: inventory exceeds 1000 notes\n` | `2` |
| Helper exceeded its wait budget | Empty | `error: helper timed out\n` | `3` |
| Helper launch, exit or protocol failure | Empty | `error: helper failed\n` | `4` |
| Help requested | Generated help | Empty | `0` |
| Invalid command arguments | Empty | Generated usage and argument error | `2` |

Here, `\n` represents a newline character. It is not two printed characters. Generated help and usage layout can vary with the Python version and terminal. The application messages in the table are exact.

### Assemble the CLI

The listing below imports the helper wrapper supplied in section 3. Save all program listings before running it.

`type=timeout_seconds` makes `argparse` call a validator on the option's text. `math.isfinite()` rejects values such as `nan` and `inf`; comparisons alone can mishandle `nan`. The valid range is 0.05 through 30 seconds. The default is two seconds. A timeout option is accepted only with `--via-helper`.

**Listing L14-03. A count subcommand with separate result streams**

Filename: `note_cli.py`.

```python
import argparse
import math
from pathlib import Path
import sys
from tempfile import TemporaryDirectory

from note_count_core import InputError, count_payload, read_path, read_payload
from note_helper_runner import HelperError, HelperTimeout, run_helper


def timeout_seconds(text: str) -> float:
    try:
        value = float(text)
    except ValueError:
        raise argparse.ArgumentTypeError("must be a finite number from 0.05 to 30")
    if not math.isfinite(value) or not 0.05 <= value <= 30:
        raise argparse.ArgumentTypeError("must be a finite number from 0.05 to 30")
    return value


def make_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(
        prog="casebook-notes",
        description="Count a local JSON note inventory.",
        allow_abbrev=False,
    )
    commands = parser.add_subparsers(dest="command", required=True)
    count = commands.add_parser(
        "count", help="count notes in one inventory", allow_abbrev=False
    )
    count.add_argument("source", help="UTF-8 JSON file, or - for stdin")
    count.add_argument("--via-helper", action="store_true", help="use the fixed helper")
    count.add_argument("--timeout", type=timeout_seconds, help="helper seconds, 0.05 to 30")
    return parser


def main(argv: list[str] | None = None) -> int:
    parser = make_parser()
    args = parser.parse_args(argv)
    if args.timeout is not None and not args.via_helper:
        parser.error("--timeout requires --via-helper")

    try:
        if not args.via_helper:
            payload = (
                read_payload(sys.stdin.buffer)
                if args.source == "-"
                else read_path(Path(args.source))
            )
            total = count_payload(payload)
        else:
            timeout = 2.0 if args.timeout is None else args.timeout
            if args.source == "-":
                payload = read_payload(sys.stdin.buffer)
                with TemporaryDirectory(prefix="casebook-count-") as directory:
                    staged = Path(directory) / "stdin notes.json"
                    staged.write_bytes(payload)
                    total = run_helper(staged, timeout=timeout)
            else:
                total = run_helper(Path(args.source), timeout=timeout)
    except InputError as error:
        print(error, file=sys.stderr)
        return 2
    except HelperTimeout:
        print("error: helper timed out", file=sys.stderr)
        return 3
    except (HelperError, OSError):
        print("error: helper failed", file=sys.stderr)
        return 4

    print(total)
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`argv=None` tells `argparse` to read the real command arguments. A test can instead pass a list. The parser's help and argument-error paths raise `SystemExit` themselves. Normal application paths return a code, which the final guard passes to the launcher.

The final `print(total)` is the only success output. Neither progress messages nor note titles share stdout with the number.


## 3. `subprocess` argument lists, executable selection and environment scope

A **child process** is another process launched by the current program. Here, the CLI launches a known Python helper, not a user-selected command.

Save this helper beside the core module. It accepts exactly `--` followed by one path. It shares the core validator and uses the same bounded error messages.

**Listing L14-04. The fixed helper**

Filename: `note_count_helper.py`.

```python
from pathlib import Path
import sys

from note_count_core import InputError, count_payload, read_path


def main() -> int:
    if len(sys.argv) != 3 or sys.argv[1] != "--":
        print("error: helper arguments", file=sys.stderr)
        return 4
    try:
        total = count_payload(read_path(Path(sys.argv[2])))
    except InputError as error:
        print(error, file=sys.stderr)
        return 2
    print(total)
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

The caller must choose the interpreter, script and environment. `sys.executable` identifies the interpreter running the CLI, keeping the helper in the same Python environment. `HELPER` is an absolute path derived from the wrapper's own file, not the operator's working directory or an input filename.

**Listing L14-05. Launch and validate one bounded helper**

Filename: `note_helper_runner.py`.

```python
import os
from pathlib import Path
import re
import subprocess
import sys

from note_count_core import InputError, MAX_NOTES


HELPER = Path(__file__).resolve().with_name("note_count_helper.py")
INPUT_ERRORS = {
    b"error: cannot read input\n",
    b"error: input exceeds 65536 bytes\n",
    b"error: input must be UTF-8 JSON\n",
    b"error: invalid note inventory\n",
    b"error: inventory exceeds 1000 notes\n",
}


class HelperTimeout(Exception):
    pass


class HelperError(Exception):
    pass


def run_helper(path: Path, *, timeout: float) -> int:
    command = [
        sys.executable, "-E", "-s", str(HELPER), "--", str(path.resolve())
    ]
    child_env = {
        name: os.environ[name]
        for name in ("SystemRoot", "WINDIR")
        if name in os.environ
    }
    try:
        result = subprocess.run(
            command,
            shell=False,
            stdin=subprocess.DEVNULL,
            capture_output=True,
            cwd=HELPER.parent,
            env=child_env,
            timeout=timeout,
            check=False,
        )
    except subprocess.TimeoutExpired:
        raise HelperTimeout from None
    except OSError:
        raise HelperError from None

    result.stderr = result.stderr.replace(b"\r\n", b"\n")
    if len(result.stdout) > 16 or len(result.stderr) > 128:
        raise HelperError
    if result.returncode == 2 and result.stdout == b"" and result.stderr in INPUT_ERRORS:
        raise InputError(result.stderr.decode("ascii").rstrip("\n"))
    if (
        result.returncode != 0
        or result.stderr != b""
        or re.fullmatch(rb"(?:0|[1-9][0-9]{0,3})\r?\n", result.stdout) is None
    ):
        raise HelperError
    total = int(result.stdout)
    if total > MAX_NOTES:
        raise HelperError
    return total
```

A **protocol** is an agreed format for communication. The helper's success protocol is a decimal count and one newline. Its input errors must match a fixed set. Arbitrary helper output is never forwarded to the CLI's user.

`capture_output=True` collects stdout and stderr separately. With binary capture, `.stdout` and `.stderr` are bytes. `check=False` lets the caller inspect the return code explicitly. Setting it to `True` would instead raise `CalledProcessError` on nonzero exit.

Python text output uses `\r\n` on Windows. The success pattern accepts either newline form. The wrapper normalizes captured error line endings before comparing them with the fixed error set. It does not accept arbitrary diagnostic text. The later tests capture the CLI in text mode, which normalizes platform line endings too.

### Worked example 2: pass a filename containing spaces

Run on macOS or Linux:

```shell
./.venv/bin/python note_cli.py count --via-helper "team notes.json"
echo $?
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe note_cli.py count --via-helper "team notes.json"
$LASTEXITCODE
```

Expected CLI result: stdout `3\n`, empty stderr and exit code `0`.

The shell first passes `team notes.json` as one argument to the CLI. The CLI resolves it to an absolute path. The list supplied to `subprocess.run` then keeps that path in one item. Do not insert extra quotation characters into that list item. Python handles argument transport to the child.

The list has six items: interpreter, `-E`, `-s`, helper path, `--` and input path. `-E` tells Python to ignore `PYTHON*` environment variables. `-s` disables the user site-packages directory. Neither option creates a sandbox. The helper and core modules are trusted application code whose directory must not be writable by an untrusted user.

With `shell=False`, no shell interprets punctuation in the input path as commands. The fixed script also avoids executable lookup through `PATH`. The helper still has the operating-system permissions of the calling process; a separate process does not remove its authority to read files.

The `env` mapping replaces ordinary environment inheritance. This helper needs no credentials. The two Windows directory variables are retained if present for platform support. A different executable may need a different documented environment. Copying all of `os.environ` would also give that executable any credentials loaded in chapter 13.

`stdin=DEVNULL` supplies immediate end-of-input to the helper. It cannot accidentally wait for keyboard input. `cwd=HELPER.parent` gives it a known working directory, while the absolute input path keeps file selection independent of that directory.

## 4. Timeouts, output budgets, temporary files and cleanup

A **timeout** limits how long the caller waits for the helper's communication to finish. `subprocess.run(..., timeout=...)` kills and waits for its direct child on timeout, then raises `TimeoutExpired`. Process creation can add time outside that wait budget. This is not an exact deadline for the whole CLI.

The helper does not create descendants. If a future helper launches a process tree, killing the direct child alone may leave other processes alive. That design needs process-group or supervisor controls appropriate to its operating system.

### Account for each resource

**Table T14-03. Budgets and their limits**

| Resource | Present control | Limit of that control |
| --- | --- | --- |
| Input memory | Read at most 65,537 bytes; reject overflow | A stalled stdin or unusual filesystem can still block a read |
| Record count | At most 1,000 validated records | Does not authorize any record |
| Helper wait | 0.05–30 seconds, default 2 | Excludes stdin staging and some process-creation time |
| Helper response | Accept at most 16 stdout bytes and 128 stderr bytes | Lengths are checked after capture, not during execution |
| Success output | One validated integer and newline | A downstream reader must still check the exit code |
| Temporary input | Context-managed directory, bounded staged file | Cleanup removes files; it does not guarantee secure erasure |

`capture_output=True` buffers output in memory. Checking length afterward is a protocol check, not a live memory cap. It is appropriate here because the fixed, reviewed helper emits only one short result or one fixed error. Do not reuse this wrapper for arbitrary or potentially noisy commands. A general runner needs streaming limits or supervisor-enforced memory and storage quotas. Redirecting unlimited output to a temporary file merely moves the exhaustion risk to disk.

The direct file path is for ordinary local files, and stdin is expected to reach end-of-input. The byte limit does not impose a read deadline. A service accepting untrusted streams would need a separate input-time policy.

### Why standard input is staged for the helper

Our helper protocol accepts a path. For `count --via-helper -`, the CLI reads bounded stdin and writes it to `stdin notes.json` inside `TemporaryDirectory`. This also exercises a second filename containing spaces.

The write finishes and closes before the helper opens that path. The `with` block removes the directory after success, input rejection or a helper exception. On timeout, `subprocess.run` has waited for the child to terminate before cleanup begins. This matters on platforms that prevent deleting an open file.

An operating-system error during staging or cleanup is reported as a helper failure with code `4`, without printing the private temporary path. A forced process kill or machine crash can prevent normal context cleanup. Operational recovery must handle abandoned files when sensitive workloads use this pattern.

### Demonstrate a timeout without hoping a normal count runs slowly

Reducing a timeout until a fast helper sometimes fails produces an unstable exercise. Use a known slow fixture instead. The following script changes the trusted helper constant only inside a local demonstration process. It does not add an arbitrary-executable option to the CLI.

**Listing L14-06. A deterministic timeout demonstration**

Filename: `timeout_demo.py`.

```python
from pathlib import Path
from tempfile import TemporaryDirectory

import note_cli
import note_helper_runner


def main() -> int:
    original = note_helper_runner.HELPER
    try:
        with TemporaryDirectory(prefix="casebook-slow-fixture-") as directory:
            slow = Path(directory) / "slow helper.py"
            slow.write_text("import time\ntime.sleep(60)\n", encoding="utf-8")
            note_helper_runner.HELPER = slow
            return note_cli.main([
                "count", "--via-helper", "--timeout", "0.1", "team notes.json"
            ])
    finally:
        note_helper_runner.HELPER = original


if __name__ == "__main__":
    raise SystemExit(main())
```

Run `./.venv/bin/python timeout_demo.py` on macOS or Linux, or `.\.venv\Scripts\python.exe timeout_demo.py` on Windows.

Expected stdout: empty. Expected stderr:

```text
error: helper timed out
```

Expected exit code: `3`. Inspect it immediately with `echo $?` or `$LASTEXITCODE`. The child sleeps for 60 seconds, but the caller kills and waits for it after the short communication timeout. The demonstration restores the original helper path and removes its fixture directory before exiting.

### Test the process boundary

An in-process return value alone does not prove that the script returns that code to its launcher. These tests run the CLI through `sys.executable` and inspect the actual process result. They use `input=...` for stdin; `capture_output=True` collects the child's two streams. An outer ten-second timeout prevents a broken CLI from holding the test indefinitely.

For application-level timeout and cleanup checks, tests also call `main()` with a substituted helper. The timeout branch is tested both by a real sleeping process and by a controlled `TimeoutExpired` exception that exposes the staged path for inspection.

**Listing L14-07. Success, input errors, helper timeout and cleanup tests**

Filename: `tests/test_note_cli.py`.

```python
import json
from pathlib import Path
import subprocess
import sys

import pytest

import note_cli
from note_count_core import MAX_INPUT_BYTES, MAX_NOTES
import note_helper_runner


ROOT = Path(__file__).resolve().parents[1]
CLI = ROOT / "note_cli.py"


def invoke(*args, input_text=None, cwd=None):
    return subprocess.run(
        [sys.executable, str(CLI), *args],
        input=input_text,
        encoding="utf-8",
        capture_output=True,
        cwd=ROOT if cwd is None else cwd,
        timeout=10,
        check=False,
    )


def expect(result, code, out, err):
    assert result.returncode == code
    assert result.stdout == out
    assert result.stderr == err


@pytest.fixture
def inventory(tmp_path):
    path = tmp_path / "team notes.json"
    notes = [
        {"id": 1, "workspace": "Alpha", "title": "Release plan"},
        {"id": 2, "workspace": "Beta", "title": "Pricing review"},
        {"id": 5, "workspace": "Alpha", "title": "برنامه انتشار"},
    ]
    path.write_text(json.dumps(notes, ensure_ascii=False), encoding="utf-8")
    return path


@pytest.mark.parametrize("helper", [False, True])
def test_space_in_filename_and_other_working_directory(inventory, tmp_path, helper):
    options = ["--via-helper"] if helper else []
    result = invoke("count", *options, str(inventory), cwd=tmp_path)
    expect(result, 0, "3\n", "")


@pytest.mark.parametrize("helper", [False, True])
def test_stdin_empty_inventory(helper):
    options = ["--via-helper"] if helper else []
    expect(invoke("count", *options, "-", input_text="[]"), 0, "0\n", "")


@pytest.mark.parametrize("helper", [False, True])
def test_missing_input(tmp_path, helper):
    options = ["--via-helper"] if helper else []
    result = invoke("count", *options, str(tmp_path / "missing.json"))
    expect(result, 2, "", "error: cannot read input\n")


@pytest.mark.parametrize("helper", [False, True])
def test_invalid_shape_never_prints_a_count(helper):
    options = ["--via-helper"] if helper else []
    result = invoke("count", *options, "-", input_text='{"title":"private fixture"}')
    expect(result, 2, "", "error: invalid note inventory\n")
    assert "private fixture" not in result.stderr


@pytest.mark.parametrize("payload", ["{", "true", '[{"id":true}]'])
def test_bad_json_or_records(payload):
    message = (
        "error: input must be UTF-8 JSON\n"
        if payload == "{"
        else "error: invalid note inventory\n"
    )
    expect(invoke("count", "-", input_text=payload), 2, "", message)


def test_input_byte_boundary():
    valid = "[]" + " " * (MAX_INPUT_BYTES - 2)
    expect(invoke("count", "-", input_text=valid), 0, "0\n", "")
    expect(
        invoke("count", "-", input_text=valid + " "),
        2, "", "error: input exceeds 65536 bytes\n",
    )


def test_record_count_boundary():
    notes = [
        {"id": number, "workspace": "Alpha", "title": "x"}
        for number in range(1, MAX_NOTES + 2)
    ]
    expect(invoke("count", "-", input_text=json.dumps(notes[:-1])), 0, "1000\n", "")
    expect(
        invoke("count", "-", input_text=json.dumps(notes)),
        2, "", "error: inventory exceeds 1000 notes\n",
    )

def test_timeout_removes_staged_input(monkeypatch, capsys, tmp_path):
    staged_paths = []
    source = tmp_path / "pipe.json"
    source.write_bytes(b"[]")

    def expire(command, **kwargs):
        staged = Path(command[-1])
        assert staged.read_bytes() == b"[]"
        staged_paths.append(staged)
        raise subprocess.TimeoutExpired(command, kwargs["timeout"])

    with source.open("r", encoding="utf-8") as stdin:
        monkeypatch.setattr(sys, "stdin", stdin)
        monkeypatch.setattr(note_helper_runner.subprocess, "run", expire)
        code = note_cli.main(["count", "--via-helper", "-"])
    captured = capsys.readouterr()
    assert (code, captured.out, captured.err) == (3, "", "error: helper timed out\n")
    assert len(staged_paths) == 1
    assert not staged_paths[0].exists()
    assert not staged_paths[0].parent.exists()
```
