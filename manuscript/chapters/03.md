Casebook permits three notes in a workspace. A count arrives as `"0"`, `0` or `None`. Do those values give you the same information? Can you decide whether another note fits?

In chapter 02, you created `casebook-learning` and its `.venv` environment. Return to that folder. Keep using its interpreter for this chapter's files. You already know how to call `print` and how to inspect the interpreter with `show_runtime.py`.

By the end of this chapter, you will be able to do four things.

- Give a value a readable name and trace a later assignment.
- Distinguish text, integers, floats, booleans and a missing value.
- Predict arithmetic and comparison results, including a quota boundary.
- Convert a suitable value, format a message and distinguish displayed output from a returned value.

Save each listing under the filename given above it. To run a file on Windows, use the following command, replacing `names.py` with that listing's filename.

```powershell
.\.venv\Scripts\python.exe names.py
```

On macOS and Linux, use the following.

```shell
./.venv/bin/python names.py
```

For every example, make a prediction before running the file. Record both the value you expect and its type when the exercise asks for a type.

## 1. Give values readable names

In chapter 01, the title appeared directly inside a call to `print`. You can give that title a name and use the name later.

**Listing L03-01. Assigning and reassigning names**

Filename: `names.py`.

```python
note_title = "Release plan"
current_count = 2
print(note_title)
print(current_count)
current_count = current_count + 1
print(current_count)
```

The single equals sign, `=`, performs **assignment**. It evaluates the expression on its right and binds the name on its left to the resulting value. **Evaluate** means work out a value. An **expression** is code that produces a value when evaluated. A literal such as `2`, a name such as `current_count` and a calculation such as `current_count + 1` are expressions.

Read the first line as “give the name `note_title` to the string `Release plan`.” Read the fifth line in two steps. First, calculate `current_count + 1` using the current value, `2`. Then bind `current_count` to the result, `3`.

The expected output is the following.

```text
Release plan
2
3
```

**Table T03-01. Tracking the name through the calculation**

| Point in the program | Value named by `current_count` |
| --- | --- |
| After `current_count = 2` | `2` |
| While evaluating `current_count + 1` | Still `2` |
| After assigning the calculated result | `3` |

Running the saved script again begins with its assignments again. Its first assignment to `current_count` supplies `2` on each run. Saving a Python file preserves its instructions. Later chapters introduce storage for data that must survive between runs.

### Choose a name that explains the value

Use `current_count` for the number already stored and `note_limit` for the maximum permitted. These names help a reviewer read a calculation without guessing which number plays which role.

Python names are case-sensitive. `current_count` and `Current_Count` are different names. For your first names, use lowercase English letters and underscores, with digits after the first character when useful. Avoid spaces and reserved language words such as `if`. Keep built-in names such as `print`, `int` and `str` available for their usual jobs.

A **comment** gives a reader an explanation. It begins with `#` outside a string and continues to the end of the source line. For example, `note_limit = 3  # Maximum notes per workspace` binds a name and explains the number. The words after `#` add no output.

Keep the top-level instructions in these files aligned at the left margin. Leading spaces are called **indentation**. Python uses indentation to group instructions in blocks. Chapter 04 will introduce those blocks. An unexpected indent at the top level can produce an `IndentationError`. [Python's lexical rules](https://docs.python.org/3.12/reference/lexical_analysis.html)

**Predict before continuing.** If you change the first count in Listing L03-01 to `0`, what are its two printed counts?

## 2. Distinguish the value from its type

A value's **type** describes what kind of value it is and which operations it supports. The built-in function `type` lets you inspect that information.

**Table T03-02. Five types you will use immediately**

| Value in source code | Type | Meaning in a Casebook example |
| --- | --- | --- |
| `"0"` | `str` | One character of text received from somewhere |
| `0` | `int` | An integer count of zero notes |
| `1.5` | `float` | A measured duration in seconds |
| `False` | `bool` | A yes-or-no result whose answer is no |
| `None` | `NoneType` | A count has not been supplied in this example |

An **integer** is a whole number. A **float** is a floating-point number, often used for measurements with a fractional part. A **boolean** has one of two values, `True` or `False`. Capitalization matters for `True`, `False` and `None`.

`None` is a value Python provides for representing absence. What that absence means depends on the application. In this chapter, a missing count means Casebook lacks the information needed to make the quota decision.

### Worked example 1. Follow `"0"`, `0` and `None`

Printing `"0"` and `0` ordinarily produces the same visible character. To inspect their difference, use `repr` as well as `type`. `repr` returns a representation useful for inspecting a value. For a simple string, that representation includes quote marks.

`print` accepts several arguments separated by commas. With its default settings, it separates their displayed forms with spaces and finishes with a newline.

**Listing L03-02. Making types visible**

Filename: `value_types.py`.

```python
text_count = "0"
current_count = 0
missing_count = None

print(repr(text_count), type(text_count))
print(repr(current_count), type(current_count))
print(repr(missing_count), type(missing_count))
```

Before running it, write three rows in your notebook. Record each name, the supplied value and the type you expect.

The expected output is the following.

```text
'0' <class 'str'>
0 <class 'int'>
None <class 'NoneType'>
```

The word `class` appears in Python's display of a type. You will learn about classes in chapter 10. Here it tells you which type was returned by `type`.

The representation of the first value uses single quotes even though its source used double quotes. Both quoting styles can describe this same string. Its content is still the one character `0`.

**Table T03-03. The meaning of the three inputs**

| Value | What we know | What a quota calculation still needs |
| --- | --- | --- |
| `"0"` | We have text containing a digit. | A checked interpretation of that text as a count |
| `0` | The supplied count is zero. | Confirmation that it is a valid, current count for this workspace |
| `None` | The count is unavailable under our convention. | A reliable count before allowing another note |

### Truth values answer a different question

Python can interpret a value in a boolean context. This is called **truth-value testing**. You can inspect the result with `bool`.

**Listing L03-03. Three values tested as booleans**

Filename: `truth_values.py`.

```python
print(bool("0"))
print(bool(0))
print(bool(None))
print(bool(""))
print(bool("False"))
```

Predict all five output lines.

```text
True
False
False
False
True
```

Every nonempty string in this example tests as true. That includes the text `"0"` and the text `"False"`. Empty text, numeric zero and `None` test as false. A truth-value test therefore loses distinctions that the quota decision needs.

For a known count of zero, all three places are available. For a missing count, availability is unknown. Casebook must obtain or verify the count before allowing creation. The same `False` result from `bool` cannot express those two different situations. [Python's truth-value rules](https://docs.python.org/3.12/library/stdtypes.html#truth-value-testing)

## 3. Calculate and compare

Arithmetic expressions operate on numbers. Comparisons produce boolean answers. Start with the familiar operations below.

**Table T03-04. Arithmetic expressions**

| Expression | Result | Meaning |
| --- | --- | --- |
| `2 + 1` | `3` | Add |
| `3 - 2` | `1` | Subtract |
| `3 * 2` | `6` | Multiply |
| `3 / 2` | `1.5` | Divide and produce a float |
| `3 // 2` | `1` | Divide and round down to a whole-number result |
| `3 % 2` | `1` | Find the remainder |
| `2 ** 3` | `8` | Raise to a power |

For the integer operands shown, `//` produces an integer. Rounding down matters with negative results too. For example, `-3 // 2` is `-2`.

Python gives some operations priority over others. Multiplication happens before addition, so `1 + 2 * 3` is `7`. Parentheses make a chosen grouping explicit. `(1 + 2) * 3` is `9`. Use parentheses when they make a rule easier to review.

### Compare values deliberately

**Table T03-05. Comparison operators**

| Expression | Result | Question |
| --- | --- | --- |
| `2 == 3` | `False` | Are the values equal? |
| `2 != 3` | `True` | Are they unequal? |
| `2 < 3` | `True` | Is the first smaller? |
| `3 <= 3` | `True` | Is the first smaller or equal? |
| `3 > 3` | `False` | Is the first greater? |
| `3 >= 3` | `True` | Is the first greater or equal? |

Assignment uses `=`. A value-equality comparison uses `==`. Read `current_count = 2` as assigning a count. Read `current_count == 2` as asking a question about that count.

The result of `"0" == 0` is `False`. Python keeps this text value and this integer value distinct during the equality comparison. The expression `0 == 0.0` is `True` because the integer and float represent equal numeric values here.

**Identity** asks whether two references point to the same object. The `is` operator performs this check. Use `missing_count is None` to ask whether that name refers to Python's `None` object. Use `==` for ordinary value comparisons such as a note title or a numeric count. Python may reuse some immutable objects internally, which makes experiments with `is` on numbers or strings unsuitable as value checks. [Equality and identity comparisons](https://docs.python.org/3.12/reference/expressions.html#comparisons)

### Worked example 2. Predict a three-note quota

The limit is three notes in one workspace. Mina belongs to Alpha, and the count supplied to this example is Alpha's current count. Assume it is a valid nonnegative integer. For this calculation, the quota permits one more note only while the current count is strictly below the limit.

**Listing L03-04. Remaining places and a quota result**

Filename: `quota.py`.

```python
note_limit = 3
current_count = 2
remaining_places = note_limit - current_count
can_add_note = current_count < note_limit

print(remaining_places)
print(can_add_note)
```

Stop before running the file. Predict the value and type assigned to each name. Then answer the following question in words. Does Alpha have room for one more note?

The expected output is the following.

```text
1
True
```

The subtraction gives `1`, an integer. The comparison gives `True`, a boolean. That boolean is the quota result. Authorization still needs the membership check introduced in chapter 01. A reader from Beta gains no access to Alpha by observing an available quota place.

**Table T03-06. Tracing the quota calculation**

| Name after assignment | Value | Type | Reason |
| --- | --- | --- | --- |
| `note_limit` | `3` | `int` | The maximum permitted count |
| `current_count` | `2` | `int` | The known current count |
| `remaining_places` | `1` | `int` | `3 - 2` |
| `can_add_note` | `True` | `bool` | `2 < 3` |

Change only `current_count` to `3`. Predict the two lines again. You should get `0` followed by `False`. Exactly at the limit, all places are occupied. Using `current_count <= note_limit` would answer true at this boundary and could admit a fourth note.

### Follow the boundary and the invalid cases

The expression assumes a valid count. A program must establish that assumption before relying on the result.

| Supplied count | Arithmetic or comparison result | Decision under the stated quota rule |
| --- | --- | --- |
| `0` | Three places remain and `0 < 3` is true. | Quota permits another note. |
| `2` | One place remains and `2 < 3` is true. | Quota permits another note. |
| `3` | No places remain and `3 < 3` is false. | Quota refuses another note. |
| `4` | Remaining places is `-1`. | Refuse another note and investigate the exceeded limit. |
| `-1` | `-1 < 3` is true. | Reject the invalid count and investigate its source. |
| `"0"` | Comparing it with `3` using `<` raises `TypeError`. | Check and interpret the text before deciding. |
| `None` | Subtracting it from `3` raises `TypeError`. | Obtain a reliable count before allowing creation. |

`TypeError` means an operation received an unsuitable type for that operation. The equality check `"0" == 0` can return false, while the ordering check `"0" < 3` raises an error. Different operators have different supported inputs.

Likewise, dividing by zero raises `ZeroDivisionError`. When an unhandled error occurs in these scripts, execution stops and Python reports it. Chapter 09 explains how to handle expected failures.

### Floats have representation limits

Keep note counts as integers. Floats are useful for quantities such as elapsed time, but many decimal fractions are approximations in binary floating-point arithmetic.

**Listing L03-05. Inspecting a floating-point sum**

Filename: `float_sum.py`.

```python
elapsed_seconds = 0.1 + 0.2
print(elapsed_seconds)
print(elapsed_seconds == 0.3)
```

On the CPython environments used for this book, the expected output is the following.

```text
0.30000000000000004
False
```

The stored approximation explains the comparison. Choose numeric representations and comparison rules according to what the quantity means. The quota examples use exact integer counts. [Python's floating-point tutorial](https://docs.python.org/3.12/tutorial/floatingpoint.html)

## 4. Convert, format and keep returned values

**Conversion** creates a value of another type from a suitable input. For example, `int("0")` interprets the text as an integer. `str(0)` produces its text form.

**Listing L03-06. Interpreting text as a count**

Filename: `convert_count.py`.

```python
text_count = "0"
current_count = int(text_count)
count_message = str(current_count)

print(repr(text_count), type(text_count))
print(repr(current_count), type(current_count))
print(repr(count_message), type(count_message))
print(current_count == 0)
```

The expected output is the following.

```text
'0' <class 'str'>
0 <class 'int'>
'0' <class 'str'>
True
```

`int` returns a new integer value for the assignment to `current_count`. The original string is still available through `text_count`.

Conversion succeeds only for supported inputs. `int("three")` raises `ValueError`, because that string does not describe an integer in the expected format. `int(None)` raises `TypeError`. `int(2.9)` produces `2` by discarding the fractional part. A quota that expects a whole-number count needs an input policy before such a conversion is accepted.

Python also treats booleans as a numeric subtype. For example, `False == 0` is true. A count validator therefore needs to distinguish booleans from accepted count inputs if the application requires an integer count. Later validation examples will implement that policy explicitly. [Built-in conversions](https://docs.python.org/3.12/library/functions.html#int) · [Boolean numeric behavior](https://docs.python.org/3.12/library/stdtypes.html#boolean-type-bool)

### Build readable messages with f-strings

An **f-string** is a string literal prefixed with `f`. Python evaluates expressions inside its braces, `{` and `}`, and inserts their formatted values into the text.

**Listing L03-07. A readable quota report**

Filename: `quota_report.py`.

```python
workspace_name = "Alpha"
note_limit = 3
current_count = 2
remaining_places = note_limit - current_count
can_add_note = current_count < note_limit

print(f"Workspace {workspace_name}")
print(f"Notes used {current_count} of {note_limit}")
print(f"Places remaining {remaining_places}")
print(f"Quota permits another note {can_add_note}")
```

The expected output is the following.

```text
Workspace Alpha
Notes used 2 of 3
Places remaining 1
Quota permits another note True
```

Read the final line alongside the rule. It reports only whether another note fits the current quota. The words before the inserted value give that boolean a clear meaning. [Python's guide to formatted strings](https://docs.python.org/3.12/tutorial/inputoutput.html#formatted-string-literals)

### A function can display one thing and return another

A **return value** is the value a function call supplies back to the surrounding expression. You can assign that value to a name. Displayed output is a separate effect of a call.

**Listing L03-08. Capturing the return value of `print`**

Filename: `printed_and_returned.py`.

```python
display_result = print("0")
print(repr(display_result), type(display_result))

converted_count = int("0")
print(repr(converted_count), type(converted_count))
```

Predict the value assigned to `display_result` before running the file.

```text
0
None <class 'NoneType'>
0 <class 'int'>
```

The first call displays `0` and returns `None`. Assignment binds `display_result` to that returned value. Calling `int("0")` returns the integer `0`, which is available for a calculation. If you need the converted count, retain the result of `int` directly.

You can now trace a possible mistake. Someone writes `current_count = print("0")` after seeing a zero appear on screen. The assigned value is `None`. The next subtraction in the quota calculation fails because the count name refers to a missing-value object. Inspect the value being returned whenever output and later behavior disagree. [Built-in function reference](https://docs.python.org/3.12/library/functions.html#print)

## Guided lab. Check a quota before running it

Start with `quota_report.py` from Listing L03-07 in your learning folder. Write a prediction table in your notebook before editing the file.

1. Predict `remaining_places` and `can_add_note` for counts `0`, `2` and `3`. Write each result and its type.
2. Run the starting file with the project interpreter. Compare its output with the row for count `2`.
3. Change `current_count` to `0`, save and run. Then repeat with `3`.
4. At count `3`, temporarily change the comparison from `<` to `<=`. Predict and observe the changed boolean. Explain whether it agrees with the three-note limit.
5. Restore `<`. Change the count to `None` and predict what the subtraction will do. Save and run once to see the error report.
6. Restore the count to `2`. Run the file again and compare it with the starting output.

The final file should have `current_count = 2` and the strict comparison `<`. Your notebook should explain why a known count of zero permits a note, while an unknown count requires more information before permission can be given.

For the deliberate failure, inspect the last line of the error report and the source line Python identifies. Exact error-display details can vary between versions. The important observation is that subtracting `None` does not produce a remaining-place count.

## Worked answers

### The opening assignment prediction

Changing the initial count in `names.py` to `0` gives output lines `Release plan`, `0` and `1`. The final assignment adds one to the current zero before rebinding `current_count`.

### Exercise 1

The expected output is the following.

```text
2
3
```

`earlier_count` refers to integer `2`. The next assignment calculates `3` and binds `current_count` to that value. That assignment leaves the binding of `earlier_count` in place.

### Exercise 2

`count` holds `None`, whose type is `NoneType`. The call to `print` displays its argument and returns `None`. A replacement assignment is `count = int("0")`. It produces integer zero from this suitable string input.

### Exercise 3

With a count of three and a limit of three, `current_count <= note_limit` evaluates to `True`. Another note would bring the count to four. Use `current_count < note_limit`, which evaluates to `False` at the boundary.

### Exercise 4

The calculation `3 - (-1)` produces `4`. The comparison `-1 < 3` produces `True`. These are valid arithmetic results for the supplied numbers. Casebook still needs a valid nonnegative count of stored notes. Reject the invalid input and investigate where it came from before relying on the quota result.

### Practice check

The expected output of `expression_check.py` is the following.

```text
False
True
True
True
True
```

| Expression | Value | Result type | Explanation |
| --- | --- | --- | --- |
| `"0" == 0` | `False` | `bool` | The text value and integer value are unequal. |
| `int("0") == 0` | `True` | `bool` | Conversion produces integer zero, then equality compares two zeros. |

A known count of zero leaves three places. With `None`, the count is unavailable. It could turn out to be zero, three or another value. Casebook needs to obtain or verify the count before allowing another note. Substituting zero for missing information would make an unsupported decision about available capacity.
