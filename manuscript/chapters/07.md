## 1. Follow text across an encoding boundary

Python's `str` type represents text as a sequence of Unicode **code points**. A code point is a numbered element of the Unicode character system. Its written identifier often looks like `U+0628`, the code point for the Persian letter `ب`.

Computers store and transmit **bytes**, units with values from zero through 255. An **encoding** specifies how text is represented as bytes. UTF-8 is one such encoding. It uses different numbers of bytes for different code points.

**Encoding** converts text into bytes. **Decoding** interprets bytes as text using a specified encoding. In Python, these operations produce different types.

| Operation | Input type | Output type | Question it answers |
| --- | --- | --- | --- |
| `text.encode("utf-8")` | `str` | `bytes` | How is this text represented in UTF-8? |
| `data.decode("utf-8")` | `bytes` | `str` | Which text do these UTF-8 bytes represent? |

The encoding name belongs at the boundary. A byte sequence by itself does not identify its intended encoding. A format or protocol must establish that agreement.

### Worked example 1. Measure the Persian note title

Reuse the exact title from note 5 in chapter 05. It contains a single ordinary space between the words and has no trailing newline.

**Listing L07-01. Code points and UTF-8 bytes**

Filename: `title_size.py`.

```python
title = "برنامه انتشار"
encoded_title = title.encode("utf-8")
decoded_title = encoded_title.decode("utf-8")

print("Code points", len(title))
print("UTF-8 bytes", len(encoded_title))
print("Round trip equal", decoded_title == title)
print(type(title), type(encoded_title))
```

Predict the two lengths before running it. The expected output is the following.

```text
Code points 13
UTF-8 bytes 25
Round trip equal True
<class 'str'> <class 'bytes'>
```

**Table T07-01. Accounting for every part of the title**

| Text segment in logical order | Code points | UTF-8 bytes |
| --- | --- | --- |
| `برنامه` | 6 | 12 |
| One ordinary space, U+0020 | 1 | 1 |
| `انتشار` | 6 | 12 |
| Complete title | 13 | 25 |

All twelve letters in this particular title use two UTF-8 bytes each. Its ASCII space uses one. The total is therefore `12 * 2 + 1`, or 25 bytes. Other Unicode letters and symbols can have different byte lengths.

The table follows the string's stored, logical order. Persian text is displayed right to left, and its letter shapes depend on their surroundings. Display direction and shaping do not change the sequence stored in this fixture.

### Store those bytes, then decode the file

The next example previews two file methods from chapter 08. `Path` represents a filesystem location. Its `.write_bytes` method writes bytes to a file, and `.read_bytes` reads the file's bytes back.

This listing creates or replaces the exercise file `note-title.txt` in your current working directory. It writes exactly the encoded title, with no byte-order mark or added newline.

**Listing L07-02. A title crossing the file boundary**

Filename: `title_bytes.py`.

```python
from pathlib import Path

title = "برنامه انتشار"
path = Path("note-title.txt")
written_count = path.write_bytes(title.encode("utf-8"))
stored_bytes = path.read_bytes()
loaded_title = stored_bytes.decode("utf-8")

print("Bytes written", written_count)
print("Bytes read", len(stored_bytes))
print("Loaded code points", len(loaded_title))
print("Same title", loaded_title == title)
```

The expected output is the following.

```text
Bytes written 25
Bytes read 25
Loaded code points 13
Same title True
```

The read returns bytes. The explicit decode gives those bytes a text interpretation. Chapter 08 will introduce text-mode file reading, paths and resource ownership in more detail. [Python's Unicode guide](https://docs.python.org/3.12/howto/unicode.html) · [Path file methods](https://docs.python.org/3.12/library/pathlib.html)

### A byte slice can cut through a letter

The first letter of the title needs two UTF-8 bytes. Taking only the first byte gives an incomplete encoding of that letter.

**Listing L07-03. Slicing text and bytes**

Filename: `title_slices.py`.

```python
title = "برنامه انتشار"
encoded_title = title.encode("utf-8")

print(title[:1])
print(encoded_title[:1])
print(encoded_title[:2].decode("utf-8"))
```

The expected output is the following.

```text
ب
b'\xd8'
ب
```

The `b` prefix identifies a bytes representation. `\xd8` describes one byte by its hexadecimal value. Calling `.decode("utf-8")` on that one-byte slice raises `UnicodeDecodeError` because the sequence ends before the letter is complete.

Keep decoding strict when a format requires valid UTF-8. The optional error modes `ignore` and `replace` discard or replace information. Choose such behavior only when the application has a specific policy for that loss. A valid decode also says nothing about whether the resulting text is an authorized or accepted identifier.

## 2. Define what length and equality mean

`len(text)` counts Unicode code points. It does not measure rendered width or always count the units a reader perceives as individual characters. A **grapheme cluster** can combine multiple code points into one perceived character. Combining accents and some emoji sequences make that distinction visible.

Write the unit alongside every length rule. A title policy might limit code points for editing and UTF-8 bytes for a storage boundary. The short ASCII identifier policy later in this chapter will make both units coincide.

### Normalization can change the representation

Some text has more than one canonically equivalent code-point sequence. For example, an accented Latin letter can use one precomposed code point or a base letter followed by a combining accent.

**Normalization** transforms text according to a chosen Unicode normalization form. Python exposes those forms through `unicodedata.normalize`.

**Listing L07-04. Two representations of an accented letter**

Filename: `normalized_text.py`.

```python
import unicodedata

composed = "\u00e9"
decomposed = "e\u0301"

print("Code points", len(composed), len(decomposed))
print("UTF-8 bytes", len(composed.encode("utf-8")), len(decomposed.encode("utf-8")))
print("Equal before", composed == decomposed)
print("Equal after NFC", composed == unicodedata.normalize("NFC", decomposed))
```

The `\u` notation in these ordinary string literals specifies a Unicode code point using four hexadecimal digits. It makes the underlying sequences explicit even if they look alike on screen.

The expected output is the following.

```text
Code points 1 2
UTF-8 bytes 2 3
Equal before False
Equal after NFC True
```

NFC performs canonical normalization with composition. It can make these two sequences equal. Other forms, such as NFKC, also apply compatibility transformations. Choose the form as part of a field's policy because changing representation can affect equality and uniqueness.

Normalization does not make every pair of visually similar characters equal. Likewise, case conversion changes which spellings compare equal. Apply the same documented representation policy when creating an identifier and when looking it up. [Unicode normalization reference](https://docs.python.org/3.12/library/unicodedata.html#unicodedata.normalize)

## 3. Transform text under a stated policy

Strings are immutable. Their transformation methods return new strings, so a change such as `raw_code.strip()` leaves the original string available through `raw_code`.

**Listing L07-05. Inspecting text cleanup**

Filename: `text_methods.py`.

```python
raw_code = " Alpha "
trimmed_code = raw_code.strip()
lower_code = trimmed_code.lower()

print(repr(raw_code))
print(repr(trimmed_code))
print(repr(lower_code))
print(lower_code.startswith("a"))
print(lower_code.endswith("ha"))
```

The expected output is the following.

```text
' Alpha '
'Alpha'
'alpha'
True
True
```

`.strip()` removes whitespace at the ends. `.lower()` converts cased characters to lowercase. `.startswith()` and `.endswith()` inspect boundaries. Another method, `.casefold()`, performs more extensive transformations for caseless matching. These operations are useful when the field's policy calls for them.

For the code validator below, we choose exact acceptance. It will reject uppercase letters and surrounding spaces. It will inspect the supplied text directly, preserving the ability to explain why that input failed. If a future interface offers automatic cleanup, define that transformation before changing stored identifier comparisons.

### Split fields and join a report

`.split` divides text into parts. The separator affects the result. Calling `.split()` with no separator treats runs of whitespace as separators and omits empty parts at the ends. Calling `.split(",")` uses literal commas and preserves empty fields between adjacent commas.

**Listing L07-06. Keeping empty fields visible**

Filename: `split_fields.py`.

```python
print("  alpha   beta  ".split())

fields = "alpha,,beta".split(",")
print(fields)
print(" | ".join(fields))
```

The expected output is the following.

```text
['alpha', 'beta']
['alpha', '', 'beta']
alpha |  | beta
```

`.join` uses the string before the dot as the separator between supplied strings. The empty field is still present in the final report. Decide what an empty field means before discarding it.

A plain split does not understand quoting rules. A title containing a comma needs the CSV reader introduced in chapter 08 when it appears in CSV data. [Python string methods](https://docs.python.org/3.12/library/stdtypes.html#string-methods)

## 4. Validate a bounded identifier with a full match

A **regular expression**, often called a **regex**, describes a text pattern. Python's `re` module can check whether an entire string fits such a pattern.

Write the policy in ordinary language before choosing a pattern. The following is a book-local policy for Casebook short codes.

**Table T07-02. Workspace code policy, version 1**

| Property | Required behavior |
| --- | --- |
| Input type | A Python string; reject numbers, bytes and missing values. |
| Length | From 3 through 12 code points, inclusive. |
| Alphabet | ASCII lowercase letters, ASCII digits and internal hyphens. |
| First character | A lowercase letter from `a` through `z`. |
| Last character | A lowercase letter or digit. |
| Internal characters | Lowercase letters, digits or `-`; consecutive internal hyphens are permitted. |
| Reserved codes | Reject `admin`, `root` and `system`. |
| Transformations | Inspect the exact supplied string; reject uppercase or surrounding whitespace. |
| Success | Return the accepted code unchanged and the reason `accepted`. |
| Rejection | Return `None` and a specific reason. |

For an accepted ASCII code, the code-point count equals its UTF-8 byte count. Code syntax, workspace existence and access permission remain separate checks with different inputs and results.

### Read the pattern before using it

The shape pattern is `r"[a-z][a-z0-9-]{1,10}[a-z0-9]"`.

| Pattern part | Meaning |
| --- | --- |
| `[a-z]` | One lowercase ASCII letter |
| `[a-z0-9-]` | One lowercase ASCII letter, ASCII digit or hyphen |
| `{1,10}` | Repeat the preceding character class from one through ten times |
| `[a-z0-9]` | One lowercase ASCII letter or digit at the end |

The first and last characters plus the middle repetition give a total length of 3 through 12. The length check in the function also states that limit explicitly and rejects oversized input before matching.

The `r` prefix creates a **raw string literal**. It keeps backslashes available for the regex engine. For example, in `r"\d+"`, the regex engine receives `\d+`. Raw strings and the regex language have distinct jobs: Python creates the pattern string, then `re` interprets that string.

For Unicode string patterns, shortcuts such as `\d` and `\w` can accept characters beyond ASCII. Our explicit ranges express the narrower code policy. [Python's regular-expression reference](https://docs.python.org/3.12/library/re.html)

### Worked example 2. Validate three short codes

`re.fullmatch` returns a match object when the whole supplied string fits, or `None` when it does not. A prefix match or a substring search would answer a weaker question. Use the full-match result directly for this whole-field policy.

Save this module next to the calling script below.

**Listing L07-07. A code validator with explicit reasons**

Filename: `workspace_codes.py`.

```python
import re


def validate_workspace_code(value):
    if not isinstance(value, str):
        return None, "must be text"
    if not 3 <= len(value) <= 12:
        return None, "length must be 3 to 12"
    if not value.isascii():
        return None, "must contain ASCII characters only"
    if re.fullmatch(r"[a-z][a-z0-9-]{1,10}[a-z0-9]", value) is None:
        return None, "invalid workspace code shape"
    if value in {"admin", "root", "system"}:
        return None, "reserved workspace code"
    return value, "accepted"
```

`isinstance(value, str)` checks whether the value is a string. `.isascii()` checks that all its characters belong to ASCII. Each `return` supplies a two-item tuple: the accepted code or `None`, followed by a reason.

The next caller **unpacks** that tuple into two names. It uses a `for` loop to check three fixtures under the same policy.

**Listing L07-08. Accepted text and two rejected inputs**

Filename: `check_workspace_codes.py`.

```python
from workspace_codes import validate_workspace_code

for supplied_code in ("alpha", " Alpha", "بتا"):
    accepted_code, reason = validate_workspace_code(supplied_code)
    print(repr(supplied_code), repr(accepted_code), reason)
```

Predict each result before running it. The expected output is the following.

```text
'alpha' 'alpha' accepted
' Alpha' None invalid workspace code shape
'بتا' None must contain ASCII characters only
```

`" Alpha"` has six ASCII code points, so it passes the type, length and ASCII checks. The pattern rejects its leading space and uppercase letter. The Persian fixture has three code points and passes the length check, then fails the ASCII rule.

### Trace boundary and reserved-name cases

**Table T07-03. Additional policy decisions**

| Input written as a Python literal | Result | Reason |
| --- | --- | --- |
| `"ab"` | Reject | Below the minimum length |
| `"abc"` | Accept unchanged | Minimum-length valid code |
| `"a12345678901"` | Accept unchanged | Twelve valid ASCII characters |
| `"a123456789012"` | Reject | Thirteen code points |
| `"a--b"` | Accept unchanged | Consecutive internal hyphens are allowed |
| `"alpha-"` | Reject | Last character must be a letter or digit |
| `"alpha\n"` | Reject | A trailing newline is outside the permitted shape |
| `"admin"` | Reject | Reserved code |
| `""` | Reject | Empty string is below the minimum length |
| `None` | Reject | Missing value is not text |

Keep the input length guard ahead of regex matching. The fixed, bounded pattern has a small, explicit job. An application receiving an HTTP body will also need limits at that earlier boundary; this function receives an already-created Python value.

### Connect syntax to a registered workspace

Use `{"alpha": "Alpha", "beta": "Beta"}` as a small registry for this exercise. After validation succeeds, look up the accepted code there. A valid code such as `"gamma"` is absent and should produce an unknown-workspace result for this registry.

The registry supplies the existing workspace identifier for the access function from chapter 06. Membership and note records must use the same identifier representation. Do the same syntax and registry checks wherever that short-code interface accepts input, then load current membership before making the access decision.
