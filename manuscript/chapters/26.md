# 26. Outbound requests and integrations

Casebook asks a partner for a report status and receives a webhook when a report is ready. What stops a redirect from moving that request to an internal service, an oversized reply from consuming unbounded resources, or a repeated event from creating the same report twice?

This chapter constrains both directions of an integration. You will select a fixed partner destination, replay synthetic HTTP responses, authenticate stored webhook bytes and inspect the database after refusal, acceptance and duplicate delivery.

You need chapter 16's transport abstraction and timeout limits, chapter 20's idempotency contracts, chapter 23's current workspace checks and chapter 25's bounded-input/final-state approach. The Alpha/Beta fixture remains unchanged: Mina `1` belongs to Alpha `1`, Ravi `2` belongs to Beta `2`, and Lee `3` manages Alpha only.

By the end, you will be able to:

- Recognize SSRF as an authority and network-boundary problem.
- Select destinations through a registry and explain redirects, DNS and egress enforcement.
- Require verified TLS, bounded operations and strict partner response schemas.
- Authenticate exact webhook bytes, enforce a time window and commit duplicate protection with the business effect.

The edition targets **CPython 3.15.2** and **Django 6.1.3** for web integration. The local laboratory needs Python 3.12 or later and only the standard library. Its actual runtime and untested network boundaries appear in the verification record.

## 1. Server-side request forgery as a design risk and fixed destination registries

**Server-side request forgery**, or **SSRF**, occurs when an attacker influences a server's requests to reach destinations or perform interactions outside the intended policy. The service can have network access, credentials or a source identity that the attacker does not possess directly.

A field named `callback_url`, a remote-image importer, a webhook destination editor or a redirect can become such an entry point. The risk includes what the request sends and what it can reach, not only whether its response is displayed.

For Casebook's report-status integration, users need to choose an approved partner, not a network destination. A **destination registry** maps a small identifier to service-controlled endpoint configuration. A **binding** connects a workspace to the account identifier that the partner recognizes.

**Exhibit D26-01. Registry and workspace bindings**

| Configuration | Trusted local value | Source of authority |
| --- | --- | --- |
| Partner ID | `reports` | Supported integration selected by code/configuration |
| Endpoint | `https://reports.partner.example/v1/status` | Reviewed service registry |
| Alpha account | `alpha-remote` | Stored `(workspace=1, partner=reports)` binding |
| Beta account | `beta-remote` | Stored `(workspace=2, partner=reports)` binding |
| Response status vocabulary | `ok`, `degraded` | Partner contract |
| Outbound payload | One encoded `account_ref` query value | Derived from the authorized stored binding; no note body or browser credential |

The `.example` names are fictional. They are not discovery targets to contact during this exercise. Account references can still be sensitive metadata; do not log them or expose the configuration indiscriminately.

### Worked example 1: select the endpoint by ID

Mina requests an Alpha refresh with `partner_id=reports`. Predict the request target:

```text
https://reports.partner.example/v1/status?account_ref=alpha-remote
```

The service first checks Mina's active Alpha membership. It loads Alpha's binding and constructs one query value with `urlencode`. Mina does not submit a host, URL, local file path or alternate account reference.

Ravi requesting that same Alpha operation must be refused before any partner call. Ravi's valid Beta identity does not grant permission to trigger Alpha's integration. An input such as `partner_id=http://127.0.0.1` is an unknown registry key, not a destination to try.

A registry reduces external control over destinations; it does not prove the resolved address is safe or that provider configuration cannot be compromised. Restrict who can change endpoints, credentials and bindings, and review those changes as security-sensitive integration work.

## 2. URL parsing, redirects, DNS changes and network egress policy

A **URL parser** separates a string into components such as scheme, hostname, port, path and query. Parsing is not validation. A string can parse successfully while naming an unacceptable scheme, host or resource.

The laboratory checks the fixed registry value against its expected HTTPS host, port and path and refuses user information, query and fragment components in that base endpoint. This is a registry sanity check, not a general arbitrary-URL sanitizer. Keep user-supplied selectors as encoded data rather than concatenating them into a host or scheme.

### A redirect is a new destination decision

An HTTP **redirect** supplies another location, commonly through a 3xx status and a Location header. If a client follows it automatically, validating only the original registry URL is insufficient. Redirects can also change methods or accidentally forward credentials depending on the client and status.

This partner contract refuses all 3xx results and never follows Location. The fake transport itself has no redirect-following behavior. The refusal test verifies exactly one `get` call, a closed response and unchanged database state.

A real transport must also disable automatic redirect handling. Application code cannot reject an intermediate status that an adapter already followed invisibly. If another product genuinely requires redirects, every hop needs a separately enforced destination, credential and resource policy with a small hop budget. That is not this integration's contract.

### DNS can change the effective destination

**DNS** maps names to addresses. A fixed allowed hostname can resolve to a different address later, including an address the service should not reach. Checking an address and then allowing a client to resolve again creates a check/use gap.

Consider IPv4 and IPv6, loopback, link-local, private networks, cloud metadata services and other reserved or disallowed ranges under the actual environment's policy. Address-string tests are not enough to establish where an eventual socket connects. Some approved partners may intentionally be private; such exceptions need explicit configuration rather than a broad private-network allowance.

**Network egress policy** restricts outbound traffic at the connection/network boundary. A controlled egress proxy, firewall or equivalent enforcement should ensure that the actual connection reaches only approved destinations and ports. It must cover DNS changes and the real address used, including alternate IP representations and protocol families.

If an adapter pins a connection address, it must still verify the intended TLS hostname and send the appropriate server name. Do not solve DNS control by disabling certificate validation. Proxy behavior and environment-derived proxy settings also belong in the reviewed transport configuration.

**Table T26-01. Which layer enforces which destination fact?**

| Layer | Decision | Evidence in this chapter |
| --- | --- | --- |
| Product/service | Caller may use this workspace integration | Current membership before the fake call and before persistence |
| Registry/URL construction | Approved HTTPS endpoint and encoded account selector | Fixed-target assertion and unknown-partner refusal |
| HTTP adapter | No redirect following; controlled TLS, proxy and response behavior | Required adapter contract; no live adapter supplied |
| Resolver/connection/egress | Actual address and port are allowed at connection time | Not exercised by a fake; requires deployment network enforcement |
| Partner authorization | Credentials and account grant permit this request | Contract/configuration work; no real provider tested |

This table answers the practice check's network question: the fake cannot prove that DNS, sockets, TLS or an egress control prevents a connection to an internal or metadata address.

## 3. Verified TLS, timeouts, response limits and partner schema validation

**TLS verification** authenticates the expected peer under configured trust and protects data in transit. It does not make every value from that peer safe for the application. A trusted partner can return an error page, an obsolete schema or the wrong account's result.

A **timeout** limits waiting under the transport's documented behavior. A **deadline** bounds the intended complete operation. Per-operation socket timeouts do not necessarily include all DNS time, retries or a slow peer that repeatedly makes small progress.

The fake records a two-second timeout and a 128-byte response budget. The service checks a three-second elapsed budget before accepting the result. This detects a late return; it does not interrupt a blocked operation at exactly three seconds. A real adapter needs cancellation/supervision and appropriate resolver, connection, handshake and read limits to enforce that stronger guarantee.

**Exhibit D26-02. Partner reply contract**

| Property | Local policy |
| --- | --- |
| Method/purpose | One GET status query; no automatic retry |
| Status | Exactly 200; 3xx explicitly refused |
| Content-Type | One unambiguous `application/json` media type, parameters allowed |
| Content-Encoding | Absent or exactly identity; no automatic decompression |
| Actual body | At most 128 bytes; request at most 129 to detect overflow |
| Claimed length | Not authority for the actual byte limit |
| JSON | UTF-8 object; duplicate keys and non-JSON numeric constants refused |
| Fields | Exactly `account_ref`, `status` |
| Binding | Returned account reference must match the requested stored binding |
| Status values | `ok` or `degraded` |
| Local update | Recheck current membership/binding, then commit the validated status and refresh count |
| Failure | Do not change local integration state or return a fabricated successful status |

A Content-Length header cannot substitute for counting bytes actually read. Likewise, automatic decompression can move the resource boundary before application validation. This model accepts no compressed response; a future compressed protocol would need limits on actual decompressed output too. Header parsing and buffering require separate transport limits.

### Release response resources on every branch

The fake reply is a context manager whose exit closes the stream. The service enters that context before checking status, type, size or schema. The refused redirect is closed without reading its body; an oversized reply is closed after the bounded read.

A real adapter needs equivalent cleanup for exceptions during acquisition, headers or reads. Fake cleanup assertions cover the supplied reply object, not every possible socket-acquisition failure. No database write transaction is held open during the external request.

## 4. Webhook authenticity, timestamp windows, duplicate delivery and secret rotation

A **webhook** is a provider-initiated delivery to an application endpoint. A successful incoming TCP/TLS connection does not establish that the payload is authorized for a workspace. Verify the provider's authentication protocol, then resolve trusted integration bindings and validate the event schema.

This laboratory uses HMAC-SHA-256 through Python's maintained `hmac` module. An **HMAC** is a message authentication code created with a shared secret. It authenticates exact bytes under that secret; it does not encrypt them. Chapter 27 develops the primitive and key-custody choices in more detail.

The signature envelope here is an explicitly synthetic Casebook protocol, not a Stripe-compatible signature format or a new general-purpose recommendation. For a real provider, use its maintained verifier/SDK and exact signing specification.

### Verify the bytes that arrived

The local signed message is a fixed purpose prefix, partner ID, timestamp text, a separator and the raw body. The partner ID comes from the configured route context. The key ID selects only among configured keys for that partner. Neither field may supply a URL to a new key source.

Verify the bounded raw bytes **before** parsing or reserializing JSON. Whitespace, a final newline or key-order changes produce different bytes even if the parsed object seems equivalent. `hmac.compare_digest` performs the tag comparison. A plain digest without the secret would not authenticate the sender.

**Exhibit D26-03. Webhook protocol decisions**

| Decision | Local rule |
| --- | --- |
| Expected route context | Partner `reports`; fixture header file records this context, not an authoritative caller-selected partner header |
| Raw event cap | 512 bytes before authentication/parsing; real ingestion must bound buffering too |
| Timestamp | Canonical decimal text; authenticated with the raw body |
| Window | Absolute difference from trusted `now` at most 300 seconds, inclusive; both stale and excessive future skew refused |
| Keys | Trusted per-partner key-ID mapping; dummy old/new keys only in the lab |
| Event shape | Exactly `id`, `type`, `account_ref`, `report_ref` |
| Supported type | `report.ready` only |
| Identifiers | 1–64 ASCII letters, digits, underscore or hyphen |
| Tenant mapping | Resolve `(partner_id, account_ref)` in stored bindings; no event-supplied workspace/role authority |
| Receipt identity | `(partner_id, event_id)`; the partner contract requires that event ID be unique in that scope |
| Repeated ID | Same raw-body digest returns the same acknowledgement; different bytes conflict |
| Business identity | `(partner_id, report_ref)`; a second event ID cannot create the same report again |
| Commit | Receipt and local report effect are one SQLite transaction |

The time window limits replay opportunities but is not deduplication. An authenticated duplicate within the window can still arrive. A delivery timestamp is also different from the event's business creation time. A provider that retries old events may sign each delivery with a fresh timestamp; follow its documented protocol rather than refusing legitimate events solely because their business date is old.

Our window accepts exactly 300 seconds and refuses 301 seconds in either direction. The fixed exercise time is `2026-11-26 09:00:00 UTC`, not the current wall clock. A caller cannot choose the receiver's real current time. Tests inject it to make the comparison repeatable.

### Keep authenticity, authority and business validity separate

A valid signature means the configured key authenticates the bytes. It does not let an event select a new workspace, become a manager, read private notes or overwrite another account's report. The code accepts only the narrow report-ready effect and resolves the workspace through the stored account binding.

The business effect creates a local report reference, not a private report download or an export-ready artifact. It releases no note bytes. Any later report/detail/export read still needs Casebook's current user and workspace policy. A partner webhook is not a browser session.

A real webhook HTTP route needs method/content-type/body/header checks, duplicate-header handling, abuse controls and safe responses. If a machine-authenticated webhook is exempted from browser CSRF, scope that exemption to the fully authenticated webhook route; do not disable chapter 24's form protection globally. No HTTP route is implemented here.

### Worked example 2: repeated delivery, one committed effect

A receipt records which authenticated event was applied. A **business key** identifies the effect independent of delivery identity. The database enforces both unique scopes.

Predict two calls with the same stored raw event and signature: each acknowledges with `200 {"received":true}`, but the final database has one receipt and one report. Then predict a different event ID referring to the same report: two receipts can exist, but the business-key constraint still leaves one report.

If the same event ID arrives with different authenticated bytes, refuse it as a conflict rather than silently applying a new operation under an old receipt. This local rule uses exact body equality; a real provider's semantic-equivalence and event-ID contracts may differ and must be documented.

A failure writing the receipt must also undo a report inserted earlier in that transaction. Marking the receipt first and committing before the effect would risk losing the effect on retry; committing the effect first would risk applying it twice. The local transaction solves the single-database unit only. It does not make an external email, HTTP call or queue publication exactly-once. Such effects need a durable outbox/idempotency strategy and later operational evidence.

### Prepare the executable contracts

**Listing L26-01. Registry, reply checks and authenticated event application**

Filename: `examples/ch26/integrations.py`.

```python
"""Local integration contracts. No live HTTP adapter, queue or secret store."""
import hashlib
import hmac
import json
import re
import time
from types import MappingProxyType
from urllib.parse import urlencode, urlsplit

from examples.ch23.authorization_service import require_member, seed, unit

ENDPOINTS = MappingProxyType({"reports": "https://reports.partner.example/v1/status"})
MAX_REPLY = 128
MAX_EVENT = 512
WINDOW = 300
FIXTURE_NOW = 1795683600
# Public dummy keys. Real keys come from protected configuration, scoped to a partner.
FIXTURE_KEYS = {"reports": {"old": b"public-old-fixture-key-26", "new": b"public-new-fixture-key-26"}}


class Refused(ValueError):
    pass


def object_json(raw):
    def pairs(items):
        result = {}
        for key, value in items:
            if key in result:
                raise Refused("invalid_json")
            result[key] = value
        return result
    def constant(value):
        raise Refused("invalid_json")
    try:
        result = json.loads(raw.decode("utf-8"), object_pairs_hook=pairs, parse_constant=constant)
    except (ValueError, UnicodeDecodeError, RecursionError) as exc:
        raise Refused("invalid_json") from exc
    if not isinstance(result, dict):
        raise Refused("object_required")
    return result


def initialize(database):
    seed(database)
    with unit(database, write=True) as db:
        db.execute("""CREATE TABLE partner_bindings (
            workspace_id INTEGER NOT NULL REFERENCES workspaces(id), partner_id TEXT NOT NULL,
            account_ref TEXT NOT NULL, status TEXT NOT NULL, refresh_count INTEGER NOT NULL,
            PRIMARY KEY(workspace_id,partner_id), UNIQUE(partner_id,account_ref))""")
        db.execute("""CREATE TABLE webhook_receipts (
            partner_id TEXT NOT NULL, event_id TEXT NOT NULL, body_sha256 TEXT NOT NULL,
            PRIMARY KEY(partner_id,event_id))""")
        db.execute("""CREATE TABLE reports (
            partner_id TEXT NOT NULL, report_ref TEXT NOT NULL,
            workspace_id INTEGER NOT NULL REFERENCES workspaces(id),
            PRIMARY KEY(partner_id,report_ref))""")
        db.executemany("INSERT INTO partner_bindings VALUES (?,'reports',?,'unknown',0)",
                       [(1,"alpha-remote"), (2,"beta-remote")])


def endpoint(partner_id):
    if not isinstance(partner_id,str) or partner_id not in ENDPOINTS:
        raise Refused("unknown_partner")
    url = ENDPOINTS[partner_id]
    parsed = urlsplit(url)
    if (parsed.scheme != "https" or parsed.hostname != "reports.partner.example"
            or parsed.port not in (None,443) or parsed.username is not None
            or parsed.password is not None or parsed.path != "/v1/status"
            or parsed.query or parsed.fragment):
        raise Refused("invalid_registry")
    return url


def refresh_status(database, *, user_id, workspace_id, partner_id, transport, clock=time.monotonic):
    url = endpoint(partner_id)
    with unit(database) as db:
        require_member(db, user_id, workspace_id)
        binding = db.execute("SELECT account_ref FROM partner_bindings WHERE workspace_id=? AND partner_id=?",
                             (workspace_id,partner_id)).fetchone()
        if binding is None:
            raise Refused("missing_binding")
        account_ref = binding["account_ref"]
    target = url + "?" + urlencode({"account_ref": account_ref})
    started = clock()
    # Contract: adapter verifies TLS, refuses redirects, requests identity encoding,
    # applies timeout/body/header limits and controls proxy use. The fake proves none of TLS/DNS.
    with transport.get(target, timeout=2.0, max_bytes=MAX_REPLY) as reply:
        if 300 <= reply.status < 400:
            raise Refused("redirect_refused")
        if reply.status != 200:
            raise Refused("unexpected_status")
        types = [v for k,v in reply.headers if k.lower() == "content-type"]
        encodings = [v for k,v in reply.headers if k.lower() == "content-encoding"]
        if len(types) != 1 or types[0].partition(';')[0].strip().lower() != "application/json":
            raise Refused("unexpected_media_type")
        if encodings not in ([], ["identity"]):
            raise Refused("unsupported_encoding")
        body = reply.read(MAX_REPLY + 1)
        if len(body) > MAX_REPLY:
            raise Refused("reply_too_large")
        if clock() - started >= 3.0:
            raise Refused("deadline_exceeded")
        payload = object_json(body)
        if (set(payload) != {"account_ref","status"} or payload["account_ref"] != account_ref
                or payload["status"] not in ("ok","degraded")):
            raise Refused("invalid_partner_schema")
    # Never hold the application write transaction open during a network operation.
    with unit(database, write=True) as db:
        require_member(db, user_id, workspace_id)
        changed = db.execute("""UPDATE partner_bindings SET status=?, refresh_count=refresh_count+1
            WHERE workspace_id=? AND partner_id=? AND account_ref=?""",
            (payload["status"],workspace_id,partner_id,account_ref)).rowcount
        if changed != 1:
            raise Refused("binding_changed")
    return payload["status"]


def signature(secret, partner_id, timestamp, raw):
    message = b"casebook-webhook-v1\n" + partner_id.encode("ascii") + b"\n" + timestamp.encode("ascii") + b"." + raw
    return hmac.new(secret, message, hashlib.sha256).hexdigest()


def handle_webhook(database, *, partner_id, raw, timestamp, key_id, supplied_signature,
                   keyrings, now):
    if len(raw) > MAX_EVENT:
        raise Refused("event_too_large")
    keys = keyrings.get(partner_id, {})
    if (not isinstance(key_id,str) or key_id not in keys or not isinstance(timestamp,str)
            or re.fullmatch(r"0|[1-9][0-9]{0,11}",timestamp) is None
            or abs(now - int(timestamp)) > WINDOW
            or not isinstance(supplied_signature,str)
            or re.fullmatch(r"[0-9a-f]{64}",supplied_signature) is None):
        raise Refused("invalid_webhook")
    expected = signature(keys[key_id], partner_id, timestamp, raw)
    if not hmac.compare_digest(expected, supplied_signature):
        raise Refused("invalid_webhook")
    payload = object_json(raw)  # Verify exact bytes BEFORE deserialization.
    if (set(payload) != {"id","type","account_ref","report_ref"}
            or payload["type"] != "report.ready"
            or any(not isinstance(payload[field],str) or re.fullmatch(r"[A-Za-z0-9_-]{1,64}",payload[field]) is None
                   for field in ("id","account_ref","report_ref"))):
        raise Refused("invalid_event_schema")
    digest = hashlib.sha256(raw).hexdigest()
    with unit(database, write=True) as db:
        binding = db.execute("SELECT workspace_id FROM partner_bindings WHERE partner_id=? AND account_ref=?",
                             (partner_id,payload["account_ref"])).fetchone()
        if binding is None:
            raise Refused("unknown_binding")
        prior = db.execute("SELECT body_sha256 FROM webhook_receipts WHERE partner_id=? AND event_id=?",
                           (partner_id,payload["id"])).fetchone()
        if prior is not None:
            if prior["body_sha256"] != digest:
                raise Refused("event_id_conflict")
            return 200, {"received": True}
        report = db.execute("SELECT workspace_id FROM reports WHERE partner_id=? AND report_ref=?",
                            (partner_id,payload["report_ref"])).fetchone()
        if report is not None and report["workspace_id"] != binding["workspace_id"]:
            raise Refused("report_binding_conflict")
        if report is None:
            db.execute("INSERT INTO reports VALUES (?,?,?)",
                       (partner_id,payload["report_ref"],binding["workspace_id"]))
        db.execute("INSERT INTO webhook_receipts VALUES (?,?,?)",(partner_id,payload["id"],digest))
    return 200, {"received": True}


def inventory(database):
    # Privileged local evidence. Not a private-report retrieval endpoint.
    with unit(database) as db:
        return {table:[dict(row) for row in db.execute(f"SELECT * FROM {table} ORDER BY 1,2")]
                for table in ("partner_bindings","webhook_receipts","reports")}
```

`refresh_status` derives the account reference from storage, validates the partner result, closes the response and then opens a short write transaction. It rechecks current membership and updates only the binding that still matches the requested account. It does not send private note fields or forward the caller's cookies/authorization headers.

`handle_webhook` authenticates before looking up event authority. `BEGIN IMMEDIATE`, supplied by chapter 23's helper, serializes the local write unit. The receipt lookup, report creation and receipt insert commit together. A committed duplicate returns without changing stored rows. The result is atomic application of a supported event within this local database, not universal exactly-once message delivery.

The inventory helper is privileged evidence and must not become a public report/metadata endpoint. Public dummy keys in this source are intentionally unusable as production secrets.

**Listing L26-02. Fake transport and explicit response closure**

Filename: `examples/ch26/fake_partner.py`.

```python
from io import BytesIO


class Reply:
    def __init__(self, status=200, body=b'', headers=(("Content-Type","application/json"),)):
        self.status, self.headers = status, headers
        self.stream = BytesIO(body)
        self.read_requests = []
        self.closed = False

    def read(self, size):
        self.read_requests.append(size)
        return self.stream.read(size)

    def __enter__(self):
        return self

    def __exit__(self, *exc):
        self.stream.close()
        self.closed = True


class FakeTransport:
    def __init__(self, result):
        self.result = result
        self.calls = []

    def get(self, target, *, timeout, max_bytes):
        self.calls.append((target,timeout,max_bytes))
        if isinstance(self.result, Exception):
            raise self.result
        return self.result
```

The fake records exactly what the application asked for. It does not prove that a real client verified a certificate, bounded a DNS lookup or refused a proxy redirect. Its in-memory body is already present; the application read budget tests how much the consumer requests, not network memory behavior.

```python
from tempfile import TemporaryDirectory

from examples.ch26.fake_partner import FakeTransport, Reply
from examples.ch26.integrations import (
    FIXTURE_KEYS,FIXTURE_NOW,Refused,handle_webhook,initialize,inventory,refresh_status,
)

FIXTURES = Path(__file__).parent / "fixtures"

with TemporaryDirectory(prefix="casebook-integration-") as folder:
    database = Path(folder) / "casebook.sqlite3"
    initialize(database)
    for label,reply in (
        ("redirect",Reply(302,headers=(("Location","http://127.0.0.1/internal"),))),
        ("oversized",Reply(body=b"x"*129)),
    ):
        transport=FakeTransport(reply)
        before=inventory(database)
        try:
            refresh_status(database,user_id=1,workspace_id=1,partner_id="reports",transport=transport,clock=lambda:0)
        except Refused as exc:
            print(label+":",str(exc))
        print("calls, closed, unchanged:",len(transport.calls),reply.closed,inventory(database)==before)
    reply=Reply(body=b'{"account_ref":"alpha-remote","status":"ok"}')
    print("accepted status:",refresh_status(database,user_id=1,workspace_id=1,partner_id="reports",
                                           transport=FakeTransport(reply),clock=lambda:0))
    headers=json.loads((FIXTURES/"report-ready.headers.json").read_text())
    raw=(FIXTURES/"report-ready.json").read_bytes()
    def deliver():
        return handle_webhook(database,raw=raw,partner_id=headers["partner_id"],timestamp=headers["timestamp"],
                              key_id=headers["key_id"],supplied_signature=headers["signature"],
                              keyrings=FIXTURE_KEYS,now=FIXTURE_NOW)
    print("first delivery:",deliver())
    saved=inventory(database)
    print("duplicate delivery:",deliver())
    print("same final state:",inventory(database)==saved)
    print("receipt rows, report rows:",len(saved["webhook_receipts"]),len(saved["reports"]))
    print("Alpha and Beta statuses:",[(r["workspace_id"],r["status"],r["refresh_count"]) for r in saved["partner_bindings"]])
```

### Rotate a secret without widening trust

Secret rotation can retain both old and new verification keys during an approved overlap, then remove the old key. Key ID is an untrusted selector into that preconfigured set. Unknown or retired IDs must fail; do not fetch a secret based on a supplied path or identifier.

The tests accept a new-key signature after old-key retirement and refuse the old key in the new-only configuration. No real secrets are changed. Production rotation needs protected custody, authorized configuration changes, delivery/retry overlap, audit records and a compromise procedure. Keep keys separate by partner/environment/purpose.

Receipts also need a retention contract. The lab keeps them for its temporary database lifetime. Before release, align deduplication retention with the provider's retry/replay horizon and chapter 18's minimization policy. Deleting a receipt while promising its duplicate protection is a contract change. The business key protects the modeled report effect even for different event IDs, but does not solve every future event type.

If verification is moved to webhook ingress and application work runs later, persist verified intent durably before acknowledgement. Do not require a queued worker to reapply the original delivery timestamp window after an arbitrary queue delay as though it were a new network delivery. Authenticate the queue boundary and recheck the business/current-permission rules appropriate to execution. Chapter 28 introduces that machinery.

## Repeatable tests and what they prove

**Listing L26-04. Local refusal, replay, rotation and rollback evidence**

Filename: `examples/ch26/test_integrations.py`.

```python
import json
from pathlib import Path
import sqlite3
from tempfile import TemporaryDirectory
import unittest

from examples.ch23.authorization_service import AccessDenied
from examples.ch26.fake_partner import FakeTransport,Reply
from examples.ch26.integrations import (
    FIXTURE_KEYS,FIXTURE_NOW,MAX_REPLY,Refused,handle_webhook,initialize,inventory,refresh_status,signature,
)

FIXTURES=Path(__file__).parent/"fixtures"


class IntegrationTests(unittest.TestCase):
    def setUp(self):
        self.folder=TemporaryDirectory(prefix="casebook-integration-test-")
        self.addCleanup(self.folder.cleanup)
        self.db=Path(self.folder.name)/"casebook.sqlite3"
        initialize(self.db)
        self.raw=(FIXTURES/"report-ready.json").read_bytes()
        self.headers=json.loads((FIXTURES/"report-ready.headers.json").read_text())

    def refresh(self,reply,user=1,clock=lambda:0):
        fake=FakeTransport(reply)
        result=refresh_status(self.db,user_id=user,workspace_id=1,partner_id="reports",transport=fake,clock=clock)
        return result,fake

    def deliver(self,raw=None,kid="old",keys=FIXTURE_KEYS,timestamp=None,tag=None):
        raw=self.raw if raw is None else raw
        timestamp=str(FIXTURE_NOW) if timestamp is None else timestamp
        if tag is None:
            tag=signature(FIXTURE_KEYS["reports"][kid],"reports",timestamp,raw)
        return handle_webhook(self.db,partner_id="reports",raw=raw,timestamp=timestamp,key_id=kid,
                              supplied_signature=tag,keyrings=keys,now=FIXTURE_NOW)

    def test_redirect_and_oversize_close_and_preserve_state(self):
        for reply,reason in ((Reply(307,headers=(("Location","http://127.0.0.1/"),)),"redirect_refused"),
                             (Reply(body=b"x"*129),"reply_too_large")):
            before=inventory(self.db)
            fake=FakeTransport(reply)
            with self.assertRaisesRegex(Refused,reason):
                refresh_status(self.db,user_id=1,workspace_id=1,partner_id="reports",transport=fake,clock=lambda:0)
            self.assertEqual(len(fake.calls),1)
            self.assertTrue(reply.closed)
            self.assertEqual(inventory(self.db),before)
        self.assertEqual(reply.read_requests,[MAX_REPLY+1])

    def test_valid_partner_and_permission_prevent_cross_workspace_call(self):
        result,fake=self.refresh(Reply(body=b'{"account_ref":"alpha-remote","status":"ok"}'))
        self.assertEqual(result,"ok")
        self.assertEqual(fake.calls,[("https://reports.partner.example/v1/status?account_ref=alpha-remote",2.0,128)])
        denied=FakeTransport(Reply())
        with self.assertRaises(AccessDenied):
            refresh_status(self.db,user_id=2,workspace_id=1,partner_id="reports",transport=denied)
        self.assertEqual(denied.calls,[])

    def test_schema_deadline_timeout_and_unknown_partner_do_not_write(self):
        before=inventory(self.db)
        for body in (b'{"account_ref":"beta-remote","status":"ok"}',b'{"account_ref":"alpha-remote","status":"ok","role":"manager"}'):
            with self.assertRaises(Refused): self.refresh(Reply(body=body))
        ticks=iter((0.0,3.0))
        with self.assertRaisesRegex(Refused,"deadline_exceeded"):
            self.refresh(Reply(body=b'{"account_ref":"alpha-remote","status":"ok"}'),clock=lambda:next(ticks))
        with self.assertRaises(TimeoutError): self.refresh(TimeoutError("synthetic timeout"))
        fake=FakeTransport(Reply())
        with self.assertRaises(Refused):
            refresh_status(self.db,user_id=1,workspace_id=1,partner_id="http://127.0.0.1",transport=fake)
        self.assertEqual(fake.calls,[])
        self.assertEqual(inventory(self.db),before)
        body=b'{"account_ref":"alpha-remote","status":"ok"}'
        self.assertEqual(self.refresh(Reply(body=body+b" "*(MAX_REPLY-len(body))))[0],"ok")

    def test_stored_signed_fixture_and_duplicate_have_one_effect(self):
        self.assertEqual(self.deliver(tag=self.headers["signature"]),(200,{"received":True}))
        before=inventory(self.db)
        self.assertEqual(self.deliver(),(200,{"received":True}))
        self.assertEqual(inventory(self.db),before)
        self.assertEqual((len(before["reports"]),len(before["webhook_receipts"])),(1,1))

    def test_authenticity_window_and_rotation(self):
        before=inventory(self.db)
        for timestamp in (str(FIXTURE_NOW-301),str(FIXTURE_NOW+301)):
            with self.assertRaises(Refused): self.deliver(timestamp=timestamp)
        with self.assertRaises(Refused): self.deliver(tag="0"*64)
        with self.assertRaises(Refused): self.deliver(raw=self.raw+b" ",tag=self.headers["signature"])
        only_new={"reports":{"new":FIXTURE_KEYS["reports"]["new"]}}
        with self.assertRaises(Refused): self.deliver(keys=only_new)
        self.assertEqual(inventory(self.db),before)
        self.assertEqual(self.deliver(kid="new",keys=only_new)[0],200)
        self.assertEqual(self.deliver(timestamp=str(FIXTURE_NOW-300),kid="new",keys=only_new)[0],200)

    def test_event_collision_and_unknown_binding_leave_state_unchanged(self):
        self.deliver()
        before=inventory(self.db)
        payload=json.loads(self.raw)
        payload["report_ref"]="different-report"
        with self.assertRaisesRegex(Refused,"event_id_conflict"):
            self.deliver(raw=json.dumps(payload).encode())
        payload["account_ref"]="unregistered"
        with self.assertRaises(Refused): self.deliver(raw=json.dumps(payload).encode())
        self.assertEqual(inventory(self.db),before)

    def test_business_key_prevents_same_report_under_new_event_id(self):
        self.deliver()
        payload=json.loads(self.raw)
        payload["id"]="evt-alpha-002"
        self.deliver(raw=json.dumps(payload).encode())
        saved=inventory(self.db)
        self.assertEqual((len(saved["webhook_receipts"]),len(saved["reports"])),(2,1))

    def test_receipt_failure_rolls_back_business_effect(self):
        with sqlite3.connect(self.db) as db:
            db.execute("""CREATE TRIGGER fail_receipt BEFORE INSERT ON webhook_receipts
                          BEGIN SELECT RAISE(ABORT,'synthetic receipt failure'); END""")
        before=inventory(self.db)
        with self.assertRaises(sqlite3.IntegrityError): self.deliver()
        self.assertEqual(inventory(self.db),before)


if __name__=="__main__":
    unittest.main()
```

## Hints

## Worked answers

### Exercise 1

An automatically followed Location can change the host, scheme or port after the original validation. DNS can also change between checking an address and the client establishing its connection. The registry should constrain intent, the adapter must obey redirect/TLS/proxy rules, and connection-time egress enforcement must constrain the actual address and port. A fake transport does not exercise that last boundary.

### Exercise 2

Count actual received bytes rather than trusting the declared length; the local consumer refuses 129 bytes. This profile also refuses Content-Encoding other than absent/identity and requires the real adapter not to decompress first. A compressed protocol would need compressed-input, actual decompressed-output and time/resource bounds. The fake already holds its body in memory, so its bounded read is evidence about the consumer request, not a live parser or decompressor's memory behavior.

### Exercise 3

The first event has a valid tag but fails the exact supported schema; neither field is a client-settable authority value. The actual workspace comes from the registered partner/account binding, and no supported event changes roles. The second event fails authenticity because its raw bytes no longer match the supplied tag, even if parsing would yield the same object. Neither signature checking nor parsing replaces the narrow business-operation contract.

### Exercise 4

After the first and duplicate deliveries: one receipt and one report. After a fresh event ID for the same report: two receipts but still one report. If receipt insertion fails during the first event, the local transaction must leave neither its report nor its receipt committed. Reopen storage and compare all integration rows with the before snapshot. An exception or a log message alone does not prove rollback or that a later retry is safe.

### Exercise 5

Retiring an old key requires an approved overlap/retry policy unless compromise demands immediate refusal. A known legitimate old-key delivery can fail if configuration changes do not match that contract. A queued, already authenticated event is a different boundary: durable verified intent and trusted queue delivery must preserve its ingress decision, while later application/current-permission checks still apply. Do not confuse queue delay with a new untrusted network delivery timestamp. Neither rotation nor a receipt automatically authorizes later private-data release.

## What you can now explain

An integration needs controls over destination, disclosure, response resources and meaning. A fixed registry and strict schema constrain application behavior, while actual network egress still needs enforcement. A webhook must authenticate its original bytes and resolve trusted business bindings; a timestamp window does not replace a durable receipt. Final stored state makes refusal, rollback and duplicate handling reviewable.

Keep the registry/binding contract, fake transport, stored webhook fixtures and atomic receipt/effect tests.
