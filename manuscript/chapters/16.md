A client receives `200 OK`, but its body is an HTML error page. Should it try to read announcements from it? If the next request times out, should it return a partial list, retry forever or report a controlled failure?

This chapter starts with a recorded request and response. You will annotate their meaning before writing a small client. Then you will replace network communication with a fake transport so success, empty results and timeout have repeatable outcomes.

Start in `casebook-learning` with the virtual environment from chapter 02. You need text and bytes from chapter 07, exceptions from chapter 09, dataclasses from chapter 10 and pytest from chapter 12. Chapter 14's distinction between stdout, stderr and exit codes will help with the demonstration command. These examples import no earlier Casebook module and require no persistent database or credential.

By the end, you will be able to:

- Explain how a hostname, IP address, port and connection relate.
- Annotate an HTTP request and distinguish status, media type and body.
- Explain what TLS certificate and hostname checks establish.
- Implement a client with fixed destinations, finite pagination, response limits and explicit failure handling.

The endpoint is a fictional **public announcements** feed. These records contain no private notes, workspace memberships or authentication tokens. A public feed cannot establish permission to read an Alpha or Beta note. The service must still check current workspace membership whenever private note data is read.

The edition targets CPython 3.12.14. The verification record identifies the runtime actually used. All exercise runs use local synthetic recordings. They make no live network requests.

## 1. Hosts, IP addresses, DNS, ports and TCP connections

A **host** is a network participant. An **IP address** identifies a network interface or destination within an IP network. A **hostname** is a human-readable name, such as `announcements.casebook.example`.

**DNS**, the Domain Name System, lets a client look up addresses for a hostname. A lookup can yield several IPv4 or IPv6 addresses. It can also fail or take time. A hostname is not a permanent promise that one particular IP address will serve it.

A **port** identifies a service endpoint on a host. Our client uses TCP port `443`, the usual HTTPS port. **TCP** provides an ordered byte stream between endpoints. It does not define HTTP requests, provide encryption or decide which Casebook user may read a note.

For the HTTP/1.1 exchange in this chapter, the client resolves the hostname, opens a TCP connection, negotiates TLS and sends HTTP messages over that protected connection. Those steps can fail independently.

**Table T16-01. Questions at each layer**

| Layer or operation | Question | Example failure |
| --- | --- | --- |
| DNS | Which addresses can be used for this hostname? | Name lookup fails |
| TCP | Can the client connect to an address and port? | Connection refused or connection timeout |
| TLS | Does the peer meet the client's certificate and hostname checks? | Untrusted certificate or wrong hostname |
| HTTP | What response did the server send for this request? | `404`, `429` or `503` |
| Application parsing | Does the representation meet the expected schema? | HTML instead of JSON, or an invalid item |

HTTP/2 also commonly uses TLS over TCP. HTTP/3 uses QUIC over UDP. We use HTTP/1.1 here because its text representation makes the message boundaries easy to inspect. A TCP read is not necessarily one HTTP message: a message can arrive in several reads, and a read can contain bytes from more than one part of a message. The HTTP library handles framing.

The `.example` domain is reserved for examples. This hostname is not a deployed Casebook service. Do not expect running a real request against it to produce the recordings below.

## 2. HTTP methods, URLs, headers, status codes, bodies and media types

A **URL** identifies a resource and how to reach it. Our fixed destination is:

```text
https://announcements.casebook.example/v1/public/announcements?limit=2
```

**Table T16-02. The URL components**

| Component | Value | Meaning |
| --- | --- | --- |
| Scheme | `https` | Use HTTP over TLS |
| Hostname | `announcements.casebook.example` | Fixed server name |
| Port | `443`, implicit in this URL | Fixed HTTPS port |
| Path | `/v1/public/announcements` | Fixed resource |
| Query | `limit=2` | Ask for at most two items per page |

The query changes a request's parameters. It does not change this client's server or resource path. The client will accept a restricted continuation cursor, rather than an arbitrary next-page URL.

### Worked example 1: annotate the recording first

The text blocks show HTTP header lines as ordinary Markdown lines. An actual HTTP/1.1 message uses CRLF line endings. The success body's byte count excludes any display newline after its final `}`.

**Exhibit R16-01. Recorded request**

```http

Host: announcements.casebook.example
Accept: application/json
Accept-Encoding: identity
Cache-Control: no-store
Connection: close

```

Before reading the annotation, identify the method, target, requested representation and end of headers.

**Table T16-03. Request annotations**

| Part | Meaning | Client decision |
| --- | --- | --- |
| `GET` | Retrieve a representation | Send no request body or mutation command |
| `/v1/public/announcements?limit=2` | Path and query in the request target | Keep the path fixed and build query values separately |
| `HTTP/1.1` | Message protocol version | Use the standard library's HTTP/1.1 client |
| `Host` | Server authority requested by HTTP | Keep it aligned with the configured TLS hostname |
| `Accept: application/json` | Preferred response media type | Still verify the actual response's `Content-Type` |
| `Accept-Encoding: identity` | Request an uncompressed representation | Reject unexpected content encoding |
| `Cache-Control: no-store` | Ask caches not to store this exchange under HTTP caching rules | Keep no client-side response cache |
| `Connection: close` | Do not keep this connection for another request | Close resources on success and failure |
| Blank line | End of headers | No request body follows in this fixture |

A **header field** carries metadata. A **body** carries representation bytes. A **media type** describes the representation format. Requesting JSON does not force a server, proxy or error page to return JSON.

**Exhibit R16-02. Recorded successful response**

Filename: `recorded-success.http`.

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 75
Cache-Control: no-store
Connection: close

{"items":[{"id":1,"title":"برنامه انتشار"}],"next_cursor":null}
```

**Table T16-04. Response annotations**

| Part | Meaning | Required interpretation |
| --- | --- | --- |
| `200` | HTTP success status | Continue validation; success status alone is insufficient |
| `OK` | Human-readable reason phrase | Do not use it as the application decision |
| `Content-Type: application/json` | JSON representation | Decode UTF-8 and then parse JSON |
| `Content-Length: 75` | Advertised body size in bytes | Enforce our own actual-read limit too |
| Blank line | Body starts after this boundary | Keep header text separate from body bytes |
| `items` | Announcement records under this endpoint's contract | Validate every record before returning any result |
| `next_cursor: null` | No next page | Stop pagination |

The body has 63 Unicode characters and 75 UTF-8 bytes. Its Persian title makes the difference observable. `Content-Length` counts bytes, not Python string characters. A library handles the message framing; the application still limits the bytes it accepts.

Now predict what happens with this response.

**Exhibit R16-03. Recorded empty response**

Filename: `recorded-empty.http`.

```http
HTTP/1.1 204 No Content
Cache-Control: no-store
Connection: close

```

A `204` response has no content. It must not carry a `Content-Length` field. There is no JSON document to decode and no `Content-Type` requirement for our empty-result case. Under this endpoint's local contract, `204` ends the feed and contributes zero items. That interpretation comes from our API contract; it is not a rule that every `204` anywhere means “an empty announcement list.”

An empty `200` body is different. This client requires JSON for a `200`, so zero body bytes cause a parsing failure. A valid `200` page containing `{"items":[],"next_cursor":null}` is another permitted empty result.

### Status codes are decisions, not body parsers

A **status code** reports an HTTP result. `2xx` codes describe successful outcomes, `3xx` redirection or related outcomes, `4xx` request-related failures and `5xx` server-related failures. Our endpoint accepts exactly `200` and `204`.

A `302` does not authorize a request to a new destination. A `401` does not mean “try an empty credential.” A `429` or `503` does not justify an unlimited retry loop. We reject these results and let the caller decide what to do under a separate policy.

## 3. TLS certificate trust, hostnames and the client/server boundary

**TLS**, Transport Layer Security, protects communication and authenticates the server under the client's trust configuration. A server presents a **certificate**, which associates public-key information with an identity. The client checks a chain to a trusted authority and checks that the certificate covers the requested hostname, along with other required validation.

The IP address used for the connection and the hostname being verified have different jobs. Connecting to an address does not by itself establish the server's name. Our adapter supplies the fixed hostname to `HTTPSConnection`, which performs TLS server-name handling and certificate checks through the configured context.

Use `ssl.create_default_context()` for the client context. Do not fix a certificate failure by setting `check_hostname=False`, using `CERT_NONE` or switching to plain HTTP. Fix the hostname, certificate chain, clock or trust configuration that caused the failure.

TLS does not prove the response follows the announcement schema. It also does not authenticate Mina, prove an active Alpha membership or make a remote server honest. The application must validate what it receives even over a verified TLS connection.

A **transport** is the component that exchanges request and response bytes. We will give the parser the same small transport interface whether the response comes from a saved fixture or an HTTPS connection:

```text
get(target, timeout=..., max_bytes=...) -> Response
```

Here, `target` is a path plus query, not a complete user-selected URL. The real adapter fixes the scheme, hostname and port in code. This separation lets us test application decisions without DNS, a certificate or a running server.

## 4. Time budgets, pagination, caching and error handling in Python clients

Write the endpoint contract before implementing the client.

**Table T16-05. Accepted data and resource budgets**

| Concern | Local policy |
| --- | --- |
| Destination | HTTPS, `announcements.casebook.example`, port `443` |
| Operation | `GET` on `/v1/public/announcements` only |
| Success statuses | `200` JSON page or `204` empty result |
| Body | At most 4,096 bytes per response; no compression |
| JSON page | Exactly `items` and `next_cursor` |
| Item | Exactly positive integer `id` and nonblank `title` of at most 200 characters |
| Page size | At most two items |
| Cursor | `null`, or 1–40 ASCII letters, digits, underscores or hyphens |
| Pagination | At most three responses, hence at most six items; reject repeated cursors and item IDs |
| Time | At most two seconds passed as each transport operation's timeout; five-second elapsed budget checked between calls |
| Redirects and retries | Neither is automatic |
| Cache | No stored response or conditional request |

**Pagination** divides a collection into pages. A **cursor** identifies a continuation position. It is data supplied to this one endpoint. It is not an instruction to contact another URL. The client returns its collected list only after every required page passes validation. A timeout on page two must not look like a complete one-page result.

A **cache** stores a response for later reuse. This client has none. It sends no `If-None-Match` validator and rejects `304`, because it has no stored representation to combine with that status. `no-store` differs from `no-cache`: the latter can permit storage while requiring validation before reuse. A cache directive also does not erase earlier logs or prove that every intermediary complied.

### Parse the response and bound pagination

`@dataclass(frozen=True)` gives us small result objects whose attributes cannot be reassigned normally. `Response.body` remains bytes until the parser checks the status and media type. The items returned to a caller are validated `Announcement` objects.

**Listing L16-01. A bounded client for one fixed resource**

Filename: `announcement_client.py`.

```python
from dataclasses import dataclass
import http.client
import json
import re
import ssl
import time
from urllib.parse import urlencode


HOST = "announcements.casebook.example"
PORT = 443
PATH = "/v1/public/announcements"
PAGE_SIZE = 2
MAX_PAGES = 3
MAX_BODY_BYTES = 4096
IO_TIMEOUT = 2.0
ELAPSED_BUDGET = 5.0


@dataclass(frozen=True)
class Response:
    status: int
    headers: tuple[tuple[str, str], ...]
    body: bytes


@dataclass(frozen=True)
class Announcement:
    id: int
    title: str


class ClientError(Exception):
    pass


class ClientTimeout(ClientError):
    pass


def parse_page(response: Response) -> tuple[list[Announcement], str | None]:
    if len(response.body) > MAX_BODY_BYTES:
        raise ClientError("response exceeds byte limit")
    if response.status == 204:
        if response.body:
            raise ClientError("204 response must be empty")
        return [], None
    if response.status != 200:
        raise ClientError(f"unexpected HTTP status {response.status}")

    types = [value for name, value in response.headers if name.lower() == "content-type"]
    if len(types) != 1 or types[0].split(";", 1)[0].strip().lower() != "application/json":
        raise ClientError("expected application/json")
    encodings = [
        value.strip().lower()
        for name, value in response.headers if name.lower() == "content-encoding"
    ]
    if encodings and encodings != ["identity"]:
        raise ClientError("unexpected content encoding")
    try:
        page = json.loads(response.body.decode("utf-8"))
    except (UnicodeDecodeError, json.JSONDecodeError, RecursionError):
        raise ClientError("invalid UTF-8 JSON") from None
    if type(page) is not dict or set(page) != {"items", "next_cursor"}:
        raise ClientError("invalid announcement page")
    items = page["items"]
    if type(items) is not list or len(items) > PAGE_SIZE:
        raise ClientError("invalid announcement items")

    parsed = []
    for item in items:
        if type(item) is not dict or set(item) != {"id", "title"}:
            raise ClientError("invalid announcement item")
        item_id, title = item["id"], item["title"]
        if (
            type(item_id) is not int or not 1 <= item_id <= 999999
            or type(title) is not str or not title.strip() or len(title) > 200
        ):
            raise ClientError("invalid announcement item")
        parsed.append(Announcement(item_id, title))
    cursor = page["next_cursor"]
    if cursor is not None and (
        type(cursor) is not str or re.fullmatch(r"[A-Za-z0-9_-]{1,40}", cursor) is None
    ):
        raise ClientError("invalid continuation cursor")
    return parsed, cursor


def fetch_announcements(transport, *, clock=time.monotonic) -> list[Announcement]:
    deadline = clock() + ELAPSED_BUDGET
    cursor = None
    seen_cursors = set()
    seen_ids = set()
    collected = []
    for _ in range(MAX_PAGES):
        remaining = deadline - clock()
        if remaining <= 0:
            raise ClientTimeout("elapsed time budget exceeded")
        query = {"limit": PAGE_SIZE}
        if cursor is not None:
            query["cursor"] = cursor
        target = PATH + "?" + urlencode(query)
        try:
            response = transport.get(
                target, timeout=min(IO_TIMEOUT, remaining), max_bytes=MAX_BODY_BYTES
            )
        except TimeoutError:
            raise ClientTimeout("request timed out") from None
        except ssl.SSLCertVerificationError:
            raise ClientError("TLS verification failed") from None
        except (OSError, http.client.HTTPException):
            raise ClientError("request failed") from None
        if clock() >= deadline:
            raise ClientTimeout("elapsed time budget exceeded")
        items, cursor = parse_page(response)
        for item in items:
            if item.id in seen_ids:
                raise ClientError("repeated announcement id")
            seen_ids.add(item.id)
            collected.append(item)
        if cursor is None:
            return collected
        if cursor in seen_cursors:
            raise ClientError("repeated continuation cursor")
        seen_cursors.add(cursor)
    raise ClientError("response exceeds page limit")
```

Header names are case-insensitive. This endpoint accepts the `application/json` media type, including parameters after a semicolon. JSON is still decoded as UTF-8; a parameter cannot make this client switch to another encoding. A different JSON-based media type, such as `application/problem+json`, is not a successful announcement page under this contract.

The client checks actual body length even if the response advertises a smaller `Content-Length`. It rejects unknown fields and invalid cursors rather than treating them as instructions. `urlencode()` constructs query values; the fixed `PATH` is never replaced by response data.

`time.monotonic()` measures elapsed time without depending on wall-clock adjustments. Tests can supply a different clock through the keyword argument. We do not catch arbitrary programming errors such as a missing transport method: those should remain visible during development.

### Replay the recordings and inject a timeout

A **fake transport** implements the transport interface with known local outcomes. This fake records calls and either returns a `Response` or raises a supplied exception. No real sleep is needed to model a timeout.

**Listing L16-02. Recorded data and a deterministic transport**

Filename: `recorded_http.py`.

```python
from announcement_client import Response


BODY_TEXT = '{"items":[{"id":1,"title":"برنامه انتشار"}],"next_cursor":null}'
RECORDED_SUCCESS = Response(
    200,
    (
        ("Content-Type", "application/json"),
        ("Content-Length", "75"),
        ("Cache-Control", "no-store"),
        ("Connection", "close"),
    ),
    BODY_TEXT.encode("utf-8"),
)
RECORDED_EMPTY = Response(
    204, (("Cache-Control", "no-store"), ("Connection", "close")), b""
)
RECORDED_HTML = Response(
    200, (("Content-Type", "text/html"),), b"<html>synthetic error</html>"
)


class FakeTransport:
    def __init__(self, *events):
        self.events = list(events)
        self.calls = []

    def get(self, target, *, timeout, max_bytes):
        self.calls.append((target, timeout, max_bytes))
        if not self.events:
            raise AssertionError("unexpected additional request")
        event = self.events.pop(0)
        if isinstance(event, Exception):
            raise event
        return event
```

Predict whether `RECORDED_EMPTY` reaches the JSON decoder. It should not. Predict whether `RECORDED_HTML` is accepted merely because its status is `200`. It should be rejected before its body is interpreted as JSON.

**Listing L16-03. A local replay command**

Filename: `client_demo.py`.

```python
import argparse
import sys

from announcement_client import ClientError, ClientTimeout, fetch_announcements
from recorded_http import (
    FakeTransport, RECORDED_EMPTY, RECORDED_HTML, RECORDED_SUCCESS,
)


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description="Replay a synthetic HTTP exchange.")
    parser.add_argument("case", choices=("success", "empty", "timeout", "html"))
    args = parser.parse_args(argv)
    events = {
        "success": RECORDED_SUCCESS,
        "empty": RECORDED_EMPTY,
        "timeout": TimeoutError("synthetic transport detail"),
        "html": RECORDED_HTML,
    }
    try:
        items = fetch_announcements(FakeTransport(events[args.case]))
    except ClientTimeout as error:
        print(f"client error: {error}", file=sys.stderr)
        return 3
    except ClientError as error:
        print(f"client error: {error}", file=sys.stderr)
        return 2
    if not items:
        print("(no announcements)")
    for item in items:
        print(f"{item.id} | {item.title}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

### A real HTTPS adapter, with the same fixed destination

The adapter below shows how the transport contract maps to the standard library. Its network operations are not invoked by the replay command. Importing it does not open a connection.

**Listing L16-04. A fixed HTTPS transport**

Filename: `https_transport.py`.

```python
import http.client
import ssl

from announcement_client import HOST, PORT, Response


class HTTPSTransport:
    def get(self, target, *, timeout, max_bytes):
        context = ssl.create_default_context()
        context.set_alpn_protocols(["http/1.1"])
        connection = http.client.HTTPSConnection(
            HOST, PORT, timeout=timeout, context=context
        )
        try:
            connection.request(
                "GET", target,
                headers={
                    "Host": HOST,
                    "Accept": "application/json",
                    "Accept-Encoding": "identity",
                    "Cache-Control": "no-store",
                    "Connection": "close",
                },
            )
            response = connection.getresponse()
            try:
                return Response(
                    response.status,
                    tuple(response.getheaders()),
                    response.read(max_bytes + 1),
                )
            finally:
                response.close()
        finally:
            connection.close()
```

`HTTPSConnection` opens the TCP/TLS connection when needed. `getresponse()` obtains the HTTP response. Reading the limit plus one byte lets the parser detect overflow without reading an unbounded response body. The adapter closes both response and connection, including when a read fails.

The custom TLS context explicitly advertises `http/1.1` through **ALPN**, the TLS protocol-selection mechanism. It retains default certificate and hostname verification. `http.client` does not automatically follow redirects. This adapter also supplies no cookies, credentials or environment-proxy handling.

The adapter has no user-selectable hostname, port or scheme. The application passes only targets built by `fetch_announcements`; do not turn `target` into an arbitrary command-line URL option. A fixed host is one destination-policy control. It is not IP-level isolation: DNS, routing and the deployment's network policy still matter. Chapter 26 examines outbound requests more fully.

### State the limits of the time and memory controls

A transport timeout is not automatically a total deadline. With this standard-library adapter it applies to blocking socket operations, not the complete DNS lookup and multi-page workflow. A slow peer can make progress between operations and consume more elapsed time than one timeout value suggests.

Our client checks the five-second elapsed budget before and after each transport call and reduces the supplied timeout to the remaining budget. That prevents another page from starting after the budget and rejects a late result. It cannot interrupt every operation exactly at five seconds. A strict whole-operation deadline needs cancellation or supervision covering resolution, connection, handshake and body reads.

The body budget applies to each uncompressed response. The adapter requests at most 4,097 bytes, and the client rejects the extra byte. It does not decompress responses. The library parses headers before application validation; this body limit is not a complete header or process-memory budget. The fake transport likewise tests application decisions, not TCP timing, TLS handshakes or a live peer's framing behavior.

A timeout also does not prove that a server did nothing. For a future state-changing request, retry decisions need an idempotency contract. This chapter sends only `GET` and performs no automatic retries.

## Worked answers

### Exercise 1

The JSON punctuation and field names contribute ASCII bytes, and most letters in the Persian title need more than one UTF-8 byte. The complete body has 63 characters and 75 bytes. An empty `200` fails with `invalid UTF-8 JSON`; it does not contain the required representation. A `204` follows the endpoint's explicit no-content branch and does not reach the JSON decoder.

### Exercise 4

A URL alone does not identify the authorized recipient or establish that membership remains active. Reusing a representation across users or after revocation can expose private note data. Conditional validation with an ETag does not replace current authorization. This client has no private-note access or cache implementation, so its passing tests establish nothing about that proposed cache's isolation. A future design needs an explicit caching and authorization contract and tests across users and revocation.

## What you can now explain

An HTTP status describes one result, while media type, encoding and schema determine whether the client can use its body. A fixed destination, bounded pagination and explicit error contract make each decision reviewable. TLS protects a connection under its trust configuration; it does not replace application validation or Casebook authorization.
