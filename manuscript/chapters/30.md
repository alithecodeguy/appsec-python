# 30. Verify controls in running code

Every note in Mina's Alpha list should belong to Alpha. How can you test that rule across many different collections? If a passive report says a security header is present, what does that tell you about the list's access control?

This chapter answers both questions by separating a requirement, a test and an observation. We will generate workspace fixtures with Hypothesis, exercise a Django list response and compare the result with supplied response metadata. We will also name the behavior neither kind of evidence covers.

Keep chapter 29's authorization correction: lists use `visible_rows` through `list_for_user`, and workers retain `selected_rows` plus an independent download check.

- Write an integration test that checks status, response shape, identity and stored state.
- Define a tenant-isolation property and generate valid two-workspace fixtures for it.
- Explain shrinking and retain a small failing case without treating it as a universal proof.
- Distinguish DAST, IAST and passive inspection by what each actually exercises or observes.
- Compare a supplied header observation with an explicit response policy.
- Build a verification matrix with test results, passive evidence and uncovered behavior.

## 1. Integration and contract tests with Django's test client

An **integration test** exercises several real components together. Here the path includes Django routing, middleware, a session-backed user, the view, the existing authorization service, SQLite and response serialization.

A **contract test** checks the behavior callers rely on: permitted methods, status codes, fields and other declared response rules. One test can be both an integration test and a contract test. Those names describe its purpose and boundary; they are not guarantees of complete coverage.

### State three requirements precisely

**Table T30-02. Requirements for this laboratory**

| ID | Requirement | A checkable consequence |
| --- | --- | --- |
| R30-ISO | A permitted list contains only notes in the requested workspace. | Every returned note has that workspace ID, and the full ordered result equals the authorized fixture subset. |
| R30-MEMBER | Private reads require identity and current active workspace membership. | An anonymous request is refused; Ravi cannot list Alpha; Mina's existing session loses Alpha access after membership revocation. |
| R30-HEADERS | Private and denied responses carry `Cache-Control: no-store` and the laboratory's enforced CSP. | A response with only `Content-Security-Policy-Report-Only` fails the enforcement requirement. |

The fixture's list response is a JSON object containing exactly `workspace_id` and `notes`. Each note contains exactly `id`, `workspace_id` and `title`; bodies are omitted. IDs are ordered ascending. There is no pagination in this exercise: at most eight notes exist, and the adapter requests a limit of 50.

We check exact results as well as the isolation condition. Otherwise an implementation that always returns an empty list would satisfy “every returned note is in the requested workspace.” A successful permitted read is part of the contract too.

The denial choices continue the established service policy: an anonymous private read returns 403; an authenticated reader without the requested workspace permission gets 404. The list supports GET. These choices are explicit exercise contracts, not universal status-code rules.

### Add the HTTP boundary without replacing authorization

The previous chapter's `list_view` returned a status/body tuple. It was useful service evidence but not a Django response. The adapter below introduces an actual URL and `JsonResponse` while calling the same `list_for_user` function.

**Listing L30-01. JSON list adapter for the existing browser laboratory**

Filename: `examples/ch30/verification_lab.py`.

```python
from django.http import Http404, JsonResponse
from django.urls import path
from django.views.decorators.http import require_GET

from examples.ch24 import browser_lab as browser
from examples.ch23.authorization_service import AccessDenied, list_for_user


@require_GET
def note_list(request, workspace_id):
    user_id = browser.identity(request)
    try:
        rows = list_for_user(browser.DATABASE, user_id=user_id,
                             workspace_id=workspace_id, limit=50)
    except AccessDenied as exc:
        raise Http404 from exc
    return JsonResponse({"workspace_id": workspace_id, "notes": rows},
                        json_dumps_params={"ensure_ascii": False})


urlpatterns = [
    path("workspaces/<int:workspace_id>/notes/", note_list, name="note-list"),
    *browser.urlpatterns,
]
```

`browser.identity(request)` obtains the authenticated active Django user's ID. The caller cannot select a user by adding a query parameter. The route supplies a workspace ID; that selection remains subject to the service's trusted membership lookup. `AccessDenied` becomes a generic 404 for authenticated workspace denial. The browser lab already supplies middleware that adds the response headers.

The `*browser.urlpatterns` syntax adds the existing routes to the new URL list. It does not change their implementations. The test suite selects this module as its URL configuration with `override_settings` and restores the setting afterwards.

### Know what the client exercises

Django's [test-client reference](https://docs.djangoproject.com/en/6.1/topics/testing/tools/#the-test-client) documents an in-process client. Requests pass through the configured Django request handling without a listening HTTP server. `secure=True` simulates a secure request; it does not perform a TLS handshake. The client does not execute JavaScript or enforce browser CSP and CORS behavior.

The suite uses `force_login` to create a test session for a known user. That intentionally isolates session identity and workspace authorization from password verification. Chapter 24's real-login checks remain separate. `Client(enforce_csrf_checks=True)` keeps CSRF checking enabled, but these new GET and OPTIONS tests do not establish a state-changing form's CSRF protection.

The OPTIONS request checks the GET-only view's 405/`Allow: GET` contract. OPTIONS is not a state-changing CSRF probe. A POST refused by CSRF middleware would answer a different question from whether the view itself supports that method.

## 2. Property-based checks with Hypothesis, generators and shrinking

A **property** is a rule expected to hold across a defined set of inputs. **Property-based testing** generates many inputs and checks that rule on each one. For R30-ISO:

> Given valid stored workspace relationships and a currently permitted reader, every returned note belongs to the requested workspace. For this bounded list, the returned rows also equal the complete expected subset.

This is a statement about the service's output, not the spelling of its SQL or the name of its helper. The same assertion can check a direct service call or the notes inside an HTTP response. Their surrounding coverage differs.

### Define fixture records and an independent oracle

An **oracle** is the rule used to decide whether an observed result is correct. Derive it from the generated input, not by calling the same production query a second time. Repeating a faulty query can produce matching results while preserving the fault.

Predict the expected Alpha list for two notes: `101` in Alpha and `202` in Beta. Now predict Alpha's list when only a Beta note exists. The second result must be empty even though a private note exists elsewhere.

**Listing L30-02. Fixture records, trusted relationships and expected rows**

Filename: `examples/ch30/fixtures.py`.

```python
from dataclasses import dataclass

from examples.ch23.authorization_service import unit


@dataclass(frozen=True)
class NoteRecord:
    id: int
    workspace_id: int
    title: str


@dataclass(frozen=True)
class WorkspaceCase:
    alpha: int
    beta: int
    notes: tuple[NoteRecord, ...]


BASE_CASE = WorkspaceCase(1, 2, (
    NoteRecord(101, 1, "برنامه انتشار"),
    NoteRecord(202, 2, "Pricing review"),
))


def install_case(database, case):
    # Privileged fixture replacement, only in the disposable database created by the tests.
    assert case.alpha != case.beta
    assert len(case.notes) <= 8
    assert len({note.id for note in case.notes}) == len(case.notes)
    assert all(note.workspace_id in (case.alpha, case.beta) for note in case.notes)
    with unit(database, write=True) as db:
        for table in ("notes", "memberships", "users", "workspaces"):
            db.execute(f"DELETE FROM {table}")
        db.executemany("INSERT INTO workspaces VALUES (?,?)",
                       [(case.alpha, "Alpha"), (case.beta, "Beta")])
        db.executemany("INSERT INTO users VALUES (?,?,1)",
                       [(1, "Mina"), (2, "Ravi"), (3, "Lee")])
        db.executemany("INSERT INTO memberships VALUES (?,?,?,1)",
                       [(case.alpha, 1, "member"), (case.beta, 2, "member"),
                        (case.alpha, 3, "manager")])
        values = []
        for note in case.notes:
            owner = 1 if note.workspace_id == case.alpha else 2
            values.append((note.id, note.workspace_id, owner, note.title,
                           f"private body {note.id}", "open", 1, owner))
        db.executemany("INSERT INTO notes VALUES (?,?,?,?,?,?,?,?)", values)


def assert_note_rows(case, workspace_id, rows):
    # Independent oracle: derive expected records from the input, not the production query.
    expected = [
        {"id": note.id, "workspace_id": note.workspace_id, "title": note.title}
        for note in sorted(case.notes, key=lambda note: note.id)
        if note.workspace_id == workspace_id
    ]
    assert isinstance(rows, list)
    assert all(isinstance(row, dict) and set(row) == {"id", "workspace_id", "title"}
               for row in rows), "unexpected response fields"
    assert all(row["workspace_id"] == workspace_id for row in rows), "foreign workspace"
    assert rows == expected, (rows, expected)
```

`NoteRecord` and `WorkspaceCase` are frozen dataclasses, as introduced in chapter 10. The tuple holds the case's note records. Fixture assertions check assumptions about these test inputs; they are not production request validation.

`install_case` performs a privileged replacement of the domain fixture rows in one transaction. It deletes child rows before parent rows, then inserts workspaces, users, memberships and notes. The user IDs and logical relationships stay consistent while workspace IDs vary. Note IDs are independent of workspace IDs: no permission can be inferred from a note's numeric range.

The four domain tables are the raw SQLite tables from chapter 23. They are distinct from Django's `auth_user` and session tables. Do not point this helper at a development or production database. Both supplied suites create their own temporary database before calling it.

`assert_note_rows` rejects foreign workspace IDs, unexpected fields, missing authorized notes, duplicates, wrong ordering and altered titles. It therefore catches both a foreign metadata leak and an implementation that avoids all leaks by returning no results. The eight-note bound lets the expected subset be complete without modeling pagination.

### Describe the input domain with strategies

A Hypothesis **strategy** describes values to generate. This differs from a Python iterator or the `yield`-based generators from chapter 11. Hypothesis controls sampling and simplification according to the strategy.

**Listing L30-03. Generate two workspace records and a note collection**

Filename: `examples/ch30/strategies.py`.

```python
from hypothesis import strategies as st

from examples.ch30.fixtures import NoteRecord, WorkspaceCase


@st.composite
def workspace_cases(draw):
    alpha, beta = draw(st.lists(st.integers(min_value=1, max_value=20),
                                min_size=2, max_size=2, unique=True))
    rows = draw(st.lists(
        st.tuples(
            st.integers(min_value=1, max_value=10_000),
            st.sampled_from((alpha, beta)),
            st.text(alphabet="abcABC<&>برنامهانتشار", min_size=1, max_size=24),
        ),
        unique_by=lambda row: row[0],
        min_size=0,
        max_size=8,
    ))
    return WorkspaceCase(alpha, beta, tuple(NoteRecord(*row) for row in rows))
```

Read the construction in order:

1. `st.lists(..., unique=True)` generates two distinct positive workspace keys. The first is Alpha's key; the second is Beta's.
2. `st.sampled_from((alpha, beta))` puts each note into one of those actual workspaces.
3. `st.tuples` builds the ID/workspace/title fields for one note.
4. The outer note list uses `unique_by` to keep note IDs unique. Empty collections and one-workspace-only collections remain possible.
5. `NoteRecord(*row)` unpacks each tuple into the dataclass constructor.

`@st.composite` lets the strategy draw values and use earlier draws to define later ones. Constructing valid relationships this way avoids repeatedly generating invalid workspace references and discarding them. Hypothesis' [strategies reference](https://hypothesis.readthedocs.io/en/latest/reference/strategies.html) documents these building blocks.

The title alphabet includes ASCII, Persian characters and markup characters. This gives useful JSON text cases while keeping this exercise bounded. It is not full Unicode or malformed-input coverage. Names, user activity and membership roles are fixed; this property does not explore every authorization policy state.

**Listing L30-04. HTTP contracts and the generated tenant-isolation property**

Filename: `examples/ch30/test_http.py`.

```python
import atexit
import os
from pathlib import Path
from tempfile import TemporaryDirectory
import unittest

from hypothesis import example, given, settings

# A dedicated process owns this settings module and this disposable database.
folder = TemporaryDirectory(prefix="casebook-ch30-http-")
atexit.register(folder.cleanup)
os.environ["CASEBOOK_CH24_DB"] = str(Path(folder.name) / "http.sqlite3")
os.environ.pop("CASEBOOK_LOCAL_HTTP", None)
from examples.ch24 import browser_lab as lab
from django.contrib.auth import get_user_model
from django.contrib.sessions.models import Session
from django.db import connections
from django.test import Client, override_settings

from examples.ch23.authorization_service import revoke_member, snapshot
from examples.ch30.fixtures import BASE_CASE, NoteRecord, WorkspaceCase, assert_note_rows, install_case
from examples.ch30.response_policy import response_policy_failures
from examples.ch30.strategies import workspace_cases


def signed_client(user_id):
    client = Client(enforce_csrf_checks=True)
    client.force_login(get_user_model().objects.get(pk=user_id))
    return client


class HttpVerificationTests(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        lab.initialize()
        override = override_settings(ROOT_URLCONF="examples.ch30.verification_lab")
        override.enable()
        cls.addClassCleanup(override.disable)
        cls.addClassCleanup(connections.close_all)

    def reset_example(self, case):
        install_case(lab.DATABASE, case)
        Session.objects.all().delete()

    def setUp(self):
        self.reset_example(BASE_CASE)

    def test_status_json_fields_unicode_and_method_contract(self):
        client = signed_client(1)
        path = "/workspaces/1/notes/"
        before = snapshot(lab.DATABASE)
        response = client.get(path, secure=True)
        self.assertEqual(response.status_code, 200)
        self.assertEqual(response["Content-Type"], "application/json")
        document = response.json()
        self.assertEqual(set(document), {"workspace_id", "notes"})
        self.assertEqual(document["workspace_id"], 1)
        assert_note_rows(BASE_CASE, 1, document["notes"])
        self.assertEqual(document["notes"][0]["title"], "برنامه انتشار")
        refused = client.options(path, secure=True)
        self.assertEqual(refused.status_code, 405)
        self.assertEqual(refused["Allow"], "GET")
        self.assertEqual(snapshot(lab.DATABASE), before)

    def test_other_workspace_anonymous_and_revoked_session(self):
        mina = signed_client(1)
        ravi = signed_client(2)
        before = snapshot(lab.DATABASE)
        self.assertEqual(ravi.get("/workspaces/1/notes/", secure=True).status_code, 404)
        self.assertEqual(Client().get("/workspaces/1/notes/", secure=True).status_code, 403)
        self.assertEqual(snapshot(lab.DATABASE), before)
        self.assertEqual(mina.get("/workspaces/1/notes/", secure=True).status_code, 200)
        revoke_member(lab.DATABASE, actor_id=3, workspace_id=1, target_user_id=1)
        after_revocation = snapshot(lab.DATABASE)
        self.assertEqual(mina.session["_auth_user_id"], "1")
        self.assertEqual(mina.get("/workspaces/1/notes/", secure=True).status_code, 404)
        self.assertEqual(snapshot(lab.DATABASE), after_revocation)

    @settings(max_examples=60, deadline=None, database=None, derandomize=True)
    @example(case=BASE_CASE)
    @example(case=WorkspaceCase(1, 2, ()))
    @example(case=WorkspaceCase(9, 3, (NoteRecord(1, 3, "Beta only"),)))
    @given(case=workspace_cases())
    def test_generated_lists_match_current_workspace(self, case):
        # unittest.setUp runs once for this method, not once per generated input.
        self.reset_example(case)
        before = snapshot(lab.DATABASE)
        for user, workspace in ((1, case.alpha), (2, case.beta), (3, case.alpha)):
            response = signed_client(user).get(f"/workspaces/{workspace}/notes/", secure=True)
            self.assertEqual(response.status_code, 200)
            document = response.json()
            self.assertEqual(set(document), {"workspace_id", "notes"})
            self.assertEqual(document["workspace_id"], workspace)
            assert_note_rows(case, workspace, document["notes"])
        for user, workspace in ((1, case.beta), (2, case.alpha), (3, case.beta)):
            response = signed_client(user).get(f"/workspaces/{workspace}/notes/", secure=True)
            self.assertEqual(response.status_code, 404)
        self.assertEqual(snapshot(lab.DATABASE), before)

    def test_response_policy_on_success_and_denials(self):
        mina = signed_client(1)
        responses = (
            (mina.get("/workspaces/1/notes/", secure=True), 200),
            (mina.get("/workspaces/2/notes/", secure=True), 404),
            (Client().get("/workspaces/1/notes/", secure=True), 403),
        )
        for response, expected_status in responses:
            self.assertEqual(response.status_code, expected_status)
            self.assertEqual(response_policy_failures(response.headers), [])


if __name__ == "__main__":
    unittest.main()
```

`@given` supplies each generated case. `@example` retains named boundaries regardless of what generation chooses. The settings cap the generated search budget, remove timing deadlines for this local database exercise, and disable persistent example storage for this disposable run. `derandomize=True` makes a run more reproducible under the same code and Hypothesis version; it is not a promise of identical generated cases across library versions.

Most importantly, `reset_example(case)` runs **inside** the property method. An ordinary `unittest.setUp` runs once for that test method, not for every generated invocation. The explicit reset replaces all domain fixture rows and clears prior session rows before the next case creates fresh clients. Otherwise old notes or memberships could make outcomes depend on the previously generated case.

The existing service uses its own raw SQLite connections. An ORM transaction wrapper alone would not automatically roll those independent connections back. This is why the example uses an explicitly owned temporary database and resets the actual state it changes. When using Django ORM-backed properties, consider Hypothesis' documented Django integration and its per-example isolation; match that mechanism to the real connection boundary.

The property checks Mina, Ravi and Lee on their permitted workspace, then checks each against the other workspace. The fixed revocation test uses Mina's **same session** before and after Lee revokes her membership. It compares the domain snapshot taken after revocation with the state after the refused read. The session remains valid while the business permission changes.

### Shrink a failure without shrinking away the relationship

**Shrinking** is Hypothesis' search for a simpler input that still fails the check. A **counterexample** is an input that violates the property. A small counterexample helps explain a defect, but is not necessarily the globally smallest possible input.

Suppose a candidate checks Mina's Alpha membership, then globally reads every note. A collection containing only one Beta note is sufficient to expose the bug. Mina does not need an Alpha note for the request itself to be permitted. Workspaces and memberships remain present even as the note collection becomes small.

The local negative-control reader in `test_local.py` below deliberately models that candidate. The following script uses Hypothesis `find`: it searches for a generated case for which the reader leaks a foreign row, then simplifies that case.

**Listing L30-05. Find a small counterexample against the broken reader**

Filename: `examples/ch30/shrink_demo.py`.

```python
from pathlib import Path
from tempfile import TemporaryDirectory

from hypothesis import find, settings

from examples.ch23.authorization_service import seed
from examples.ch30.fixtures import install_case
from examples.ch30.strategies import workspace_cases
from examples.ch30.test_local import global_list


def leaks(case):
    with TemporaryDirectory(prefix="casebook-ch30-shrink-") as folder:
        database = Path(folder) / "notes.sqlite3"
        seed(database)
        install_case(database, case)
        rows = global_list(database, user_id=1, workspace_id=case.alpha)
        return any(row["workspace_id"] != case.alpha for row in rows)


if __name__ == "__main__":
    counterexample = find(workspace_cases(), leaks,
        settings=settings(max_examples=500, deadline=None, database=None, derandomize=True))
    print(counterexample)
    assert leaks(counterexample)
```

Run after saving `test_local.py`:

```shell
python -m examples.ch30.shrink_demo
```

**Expected behavior, not recorded here:** it prints a `WorkspaceCase` containing a foreign note that Mina's global list would expose. A one-note Beta case can be sufficient; exact IDs, title text, formatting and the resulting simplified case can vary. The final `assert` rechecks the printed counterexample. No Hypothesis-generated counterexample or shrinking result was observed in this writing environment.

The explicit `@example(BASE_CASE)` in the HTTP suite is already a known failing case for a global loader. Explicit examples are not themselves shrunk. The separate `find` demonstration lets generated input drive the simplification. Hypothesis' [API reference](https://hypothesis.readthedocs.io/en/latest/reference/api.html) documents `find`, settings and examples; its [failure replay guide](https://hypothesis.readthedocs.io/en/latest/tutorial/replaying-failures.html) explains retaining discovered failures.

In a maintained test suite, keep the useful counterexample as a named regression or an `@example`, alongside generation. The demonstration disables the example database; a normal project can retain Hypothesis' failure cache under an intentional policy. A copied seed alone is weaker than a saved meaningful regression case when code and tool versions change.

### Test the same assertion at a smaller executable boundary

The bounded suite later in this chapter does not use Hypothesis. It enumerates note distributions of sizes zero through four, across three workspace-key pairs: `(1, 2)`, `(2, 1)` and `(9, 3)`. That gives `3 × (1 + 2 + 4 + 8 + 16) = 93` layouts.

For each layout it exercises permitted Mina, Ravi and Lee service reads, cross-workspace denials, an anonymous denial and unchanged domain state. It shares the input model and expected-result assertion with the HTTP property. Its passing result is useful **service-boundary** evidence. It does not substitute for an unexecuted HTTP or Hypothesis run.

This distinction is practical. If generation fails because a strategy is invalid, or an HTTP adapter mishandles a denial, the bounded service suite may still pass. Record which path a result actually exercised.

## 3. DAST, IAST, coverage and limits

**Dynamic application security testing**, or **DAST**, usually examines a running application from outside its implementation. It can send requests, vary inputs and inspect responses. A scanner needs working routes, usable identities and meaningful scenarios to reach the relevant behavior. An anonymous crawl of a login page does not establish tenant isolation inside an authenticated list.

**Interactive application security testing**, or **IAST**, uses runtime instrumentation inside the application to observe executed paths and selected security-relevant operations. **Instrumentation** means hooks or agents that collect internal execution evidence. Its visibility depends on the runtime, framework, rules and paths actually exercised. An unexecuted worker or unsupported library remains outside that observation.

OWASP describes external application scanners in its [DAST overview](https://community.owasp.org/Vulnerability_Scanning_Tools) and runtime instrumentation in its [IAST guidance](https://owasp.github.io/DevSecOpsGuideline/2-Process/2-4-Test/2-4-1-Interactive-Application-Security-Testing/). Tool labels do not remove the need for a defined question and coverage record.

**Passive inspection** analyzes messages that are already available without changing them to probe a hypothesis. ZAP's [passive scanner documentation](https://www.zaproxy.org/docs/desktop/addons/passive-scanner/) describes inspection that does not alter the messages. A passive rule can examine a header in a captured response. The traffic still has to come from somewhere; an active crawler or test that generated it is a separate activity.

**Table T30-03. Evidence methods and their boundaries**

| Method | Useful evidence | What it cannot establish by its name alone |
| --- | --- | --- |
| Direct service test | Actual permission lookup, SQLite selection and return values for known fixture state | Correct HTTP routing, session binding, serialization or deployed middleware |
| Django client integration | In-process route, middleware, session identity and response contract | TLS, reverse-proxy behavior or browser execution |

## 4. Read supplied passive reports and connect observations to requirements

### Worked example: present does not mean enforced

R30-HEADERS requires two separate things: a no-store response directive and the fixture's enforced Content Security Policy, or **CSP**. The intended CSP denies scripts, objects and framing; restricts the base URL; and permits form submission only to the same origin. Chapter 24 already configured the corresponding Django middleware and settings.

A response can contain a policy under `Content-Security-Policy-Report-Only`. That header requests monitoring of violations; it does not enforce that policy. A violation is not guaranteed to be delivered to a reporting service merely because the header exists. W3C's [CSP specification](https://www.w3.org/TR/CSP3/#header-content-security-policy-report-only) distinguishes report-only delivery from enforcement, and Django's [CSP reference](https://docs.djangoproject.com/en/6.1/ref/csp/) maps the two modes to separate settings.

Predict the decision for the supplied fixture. It has status 200 and `Cache-Control: no-store`. It also has a report-only policy containing `script-src 'none'`. Does that meet the enforced-CSP requirement?

**Listing L30-07. Compare normalized headers with the required policy**

Filename: `examples/ch30/response_policy.py`.

```python
import json
from pathlib import Path


EXPECTED_CSP = {
    "default-src": frozenset({"'none'"}),
    "script-src": frozenset({"'none'"}),
    "object-src": frozenset({"'none'"}),
    "base-uri": frozenset({"'none'"}),
    "form-action": frozenset({"'self'"}),
    "frame-ancestors": frozenset({"'none'"}),
}
ENFORCED_CSP = "; ".join(name + " " + " ".join(sorted(values))
                         for name, values in EXPECTED_CSP.items())


def response_policy_failures(headers):
    # A strict contract for one normalized header mapping, not a general CSP parser.
    headers = {name.lower(): value for name, value in headers.items()}
    failures = []
    cache = {part.strip().lower() for part in headers.get("cache-control", "").split(",")}
    if "no-store" not in cache:
        failures.append("missing Cache-Control no-store")
    enforced = headers.get("content-security-policy")
    if not enforced:
        failures.append("missing enforced Content-Security-Policy")
        return failures
    directives = {}
    for part in enforced.split(";"):
        words = part.split()
        if not words:
            continue
        name = words[0].lower()
        if name in directives:
            failures.append("duplicate CSP directive")
            return failures
        directives[name] = frozenset(words[1:])
    if directives != EXPECTED_CSP:
        failures.append("enforced CSP differs from the fixture contract")
    return failures


def main():
    report = json.loads(Path(__file__).with_name("passive-report.json").read_text())
    assert report["provenance"] == "authored teaching fixture"
    failures = response_policy_failures(report["response"]["headers"])
    print("Observation:", report["capture_id"], report["response"]["status"])
    print("Header contract:", "PASS" if not failures else "FAIL")
    for failure in failures:
        print("-", failure)


if __name__ == "__main__":
    main()
```

This is deliberately a strict checker for **one normalized header mapping and one exact fixture policy**. Directive order and whitespace can vary, but duplicate directives, missing directives and additional directives fail the contract. For example, an extra permissive `script-src-elem` cannot pass by leaving `script-src 'none'` present.

It is not a general parser or a browser policy evaluator. A normalized dictionary cannot represent every raw duplicate-header arrangement. A real deployment may have multiple CSP policies, different page requirements or intermediary changes. Review those semantics separately instead of extending this small checker into an undocumented universal CSP validator.

The fixture has no enforced header, so the checker does not treat the report-only value as a substitute. The no-store check is independent. A response can satisfy one requirement and fail the other.

**Listing L30-08. Local executable checks and an intentionally leaking reader**

```python
from itertools import product
import json
from pathlib import Path
from tempfile import TemporaryDirectory
import unittest

from examples.ch23.authorization_service import (
    AccessDenied, list_for_user, note_fields, require_member, revoke_member, seed, snapshot, unit,
)
from examples.ch30.fixtures import BASE_CASE, NoteRecord, WorkspaceCase, assert_note_rows, install_case
from examples.ch30.response_policy import ENFORCED_CSP, response_policy_failures


def global_list(database, *, user_id, workspace_id, limit=50):
    # Deliberately broken local candidate, never a route or a replacement production helper.
    with unit(database) as db:
        require_member(db, user_id, workspace_id)
        rows = db.execute("SELECT id, workspace_id, title, body FROM notes ORDER BY id LIMIT ?",
                          (limit,)).fetchall()
        return [note_fields(row) for row in rows]


class LocalVerificationTests(unittest.TestCase):
    def setUp(self):
        self.folder = TemporaryDirectory(prefix="casebook-ch30-local-")
        self.addCleanup(self.folder.cleanup)
        self.database = Path(self.folder.name) / "local.sqlite3"
        seed(self.database)
        install_case(self.database, BASE_CASE)

    def test_bounded_layouts_at_the_service_boundary(self):
        layouts = 0
        for alpha, beta in ((1, 2), (2, 1), (9, 3)):
            for size in range(5):
                for owners in product((alpha, beta), repeat=size):
                    case = WorkspaceCase(alpha, beta, tuple(
                        NoteRecord(101 + index, workspace, "برنامه انتشار")
                        for index, workspace in enumerate(owners)))
                    install_case(self.database, case)
                    before = snapshot(self.database)
                    for user, workspace in ((1, alpha), (2, beta), (3, alpha)):
                        rows = list_for_user(self.database, user_id=user,
                                             workspace_id=workspace, limit=50)
                        assert_note_rows(case, workspace, rows)
                    for user, workspace in ((1, beta), (2, alpha), (3, beta), (None, alpha)):
                        with self.assertRaises(AccessDenied):
                            list_for_user(self.database, user_id=user, workspace_id=workspace)
                    self.assertEqual(snapshot(self.database), before)
                    layouts += 1
        self.assertEqual(layouts, 93)

    def test_negative_control_leaks_despite_conforming_header_values(self):
        rows = global_list(self.database, user_id=1, workspace_id=1)
        self.assertEqual([row["id"] for row in rows], [101, 202])
        with self.assertRaises(AssertionError):
            assert_note_rows(BASE_CASE, 1, rows)
        headers = {"Cache-Control": "no-store", "Content-Security-Policy": ENFORCED_CSP}
        self.assertEqual(response_policy_failures(headers), [])

    def test_current_membership_changes_the_next_service_read(self):
        assert_note_rows(BASE_CASE, 1, list_for_user(self.database, user_id=1, workspace_id=1))
        revoke_member(self.database, actor_id=3, workspace_id=1, target_user_id=1)
        after_revocation = snapshot(self.database)
        with self.assertRaises(AccessDenied):
            list_for_user(self.database, user_id=1, workspace_id=1)
        self.assertEqual(snapshot(self.database), after_revocation)

    def test_supplied_report_only_observation_fails_enforcement_requirement(self):
        report = json.loads(Path(__file__).with_name("passive-report.json").read_text())
        self.assertEqual(report["provenance"], "authored teaching fixture")
        self.assertEqual(response_policy_failures(report["response"]["headers"]),
                         ["missing enforced Content-Security-Policy"])

    def test_exact_enforced_header_and_weaker_variants(self):
        headers = {"Cache-Control": "no-store", "Content-Security-Policy": ENFORCED_CSP}
        self.assertEqual(response_policy_failures(headers), [])
        for bad in (ENFORCED_CSP.replace("script-src 'none'", "script-src *"),
                    ENFORCED_CSP + "; script-src 'none'",
                    ENFORCED_CSP + "; script-src-elem *"):
            self.assertTrue(response_policy_failures(headers | {"Content-Security-Policy": bad}))

    def test_csp_does_not_replace_no_store(self):
        self.assertEqual(response_policy_failures({"Content-Security-Policy": ENFORCED_CSP}),
                         ["missing Cache-Control no-store"])


if __name__ == "__main__":
    unittest.main()
```
