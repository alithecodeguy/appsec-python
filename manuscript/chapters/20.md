# 20. API contracts and business rules

Mina sends a new note title. What may she change, which values must the service choose, and what should remain stored if the request is invalid or arrives twice?

This chapter specifies Casebook's first write contracts. You will separate a client's proposed values from the service's authority, make note transitions explicit, and apply an export request twice without creating a second job. A successful response is only part of the evidence. We will reopen the database and inspect stored state after acceptance, refusal and replay.

You need chapter 15's parameter binding and transactions, chapter 16's HTTP exchanges, and chapter 19's distinction between stored notes and published routes. Keep chapter 17's `CB-DESIGN-17` and chapter 18's `CB-READ-01` requirement. The smallest starting data is Alpha workspace `1`, Beta workspace `2`, Alpha note `101` and Beta note `202`, with their established titles and synthetic bodies.

By the end, you will be able to:

- Define JSON request and response shapes, methods and failure statuses.
- Separate required, optional, forbidden and server-owned fields.
- Check a state transition, reject a stale write and recognize a safe retry.
- Bound collection operations and maintain an API version and route inventory.

The edition targets CPython **3.15.2** and Django **6.1.3** for web examples. This chapter's runnable contract laboratory uses only Python's standard library and requires Python 3.12 or later for explicit SQLite `autocommit` configuration. The verification record names the actual runtime.

## 1. JSON request and response schemas, methods and status codes

An **application programming interface**, or **API**, is an agreed way for one program to request behavior from another. An **API contract** states the accepted inputs, observable results and state changes. It includes what happens when the caller is wrong or the response is lost.

A **schema** describes the shape of data: field names, types and restrictions. A **business rule** describes a permitted operation in its context. A string named `state` can match a schema while requesting a forbidden transition. A well-formed workspace ID can still identify another customer's data.

### Begin with one update

**Exhibit D20-01. Proposed update request**

```http
PATCH /api/v1/workspaces/1/notes/101/ HTTP/1.1
Host: casebook.example
Content-Type: application/json
Accept: application/json

{"title":"Release plan v2","expected_version":1}
```

This is a contract exhibit, not a runnable curl command. The trusted identity for the first permitted case is Mina, an active Alpha member. The fixture identity is outside the JSON document.

**PATCH** requests a partial modification. Here the patch document is our own JSON command format, identified as `application/json`. It is neither JSON Patch nor JSON Merge Patch. In particular, `null` does not mean deletion. PUT describes replacement semantics; we do not offer it on this route. A future adapter must reject unsupported methods with `405` and an appropriate `Allow` header.

`expected_version` states which stored revision the client intends to change. If the current version differs, the server refuses the write. This is **optimistic concurrency control**: a client works from a version it observed, and the server detects that another accepted write has made that version stale. It is not a permission check.

A permitted request returns a JSON object with status `200`:

```json
{
  "id": 101,
  "workspace_id": 1,
  "owner_id": 1,
  "title": "Release plan v2",
  "state": "open",
  "version": 2,
  "updated_by": 1
}
```

This is the exact successful note representation for these contracts. All seven fields are required; no note body, membership list or credential is included. IDs and versions are positive integers. `state` is `open` or `archived`. These identifiers and the title are still private metadata. Omitting the body does not make the response public.

**Table T20-01. Proposed operations and representations**

| Operation | Accepted request | Successful response | Mutation |
| --- | --- | --- | --- |
| POST `/api/v1/workspaces/{workspace_id}/notes/` | Object containing only a valid `title` | 201, the seven-field note object; future HTTP adapter supplies the new note's `Location` | Create one open note, owner from trusted requester, empty body, version 1 |
| PATCH `/api/v1/workspaces/{workspace_id}/notes/{note_id}/` | `expected_version` plus `title`, `state`, or both | 200, the seven-field stored note object | One permitted update; increment version once |
| POST `/api/v1/workspaces/{workspace_id}/exports/` | Object containing only `note_ids`, plus the project-defined `Idempotency-Key` header | 202, exactly `job_id`, `workspace_id`, `state` | Create or replay one acceptance receipt for one queued job |
| GET `/api/v1/workspaces/{workspace_id}/notes/` | Bounded `limit` and optional `after_id` query parameters | 200, bounded `items` and `next_after_id` | None; design only in this chapter |

The first creation contract is intentionally narrow. It cannot accept a body or transfer ownership. The JSON title policy is shared with updates. Path selectors are positive integers within SQLite's signed 64-bit range. A future route adapter must reject an invalid path selector without querying a private object; this contract uses a generic 404 for an invalid or unmatched resource path.

The local laboratory implements the first three operations as functions. It does not implement HTTP header handling, method selection, `Location`, response caching or the proposed list route.

### Define failures before writing a view

**Table T20-02. Contract failures**

| Condition | Status and stable error code | Stored business state |
| --- | --- | --- |
| Unsupported request media type | 415 `unsupported_media_type` | Unchanged |
| JSON body exceeds 4,096 bytes | 413 `body_too_large` | Unchanged |
| Invalid UTF-8/JSON, duplicate object key or nonstandard numeric constant | 400 `invalid_json` | Unchanged |
| Parsed JSON is not an object | 400 `object_required` | Unchanged |
| Unknown/forbidden field, missing required field or bad version input | 422 `invalid_fields` | Unchanged |
| Invalid title, state vocabulary, export selection or idempotency key | 422 with the relevant `invalid_*` code | Unchanged |
| Visitor has no trusted fixture identity | 403 `access_denied` | Unchanged |
| No active workspace membership, or no note within the scoped workspace | 404 `not_found` | Unchanged |
| Member attempts manager-only archive | 403 `action_denied` | Unchanged |
| Stored version differs from `expected_version` | 409 `stale_version` | Unchanged |
| Accepted version counter would exceed the signed-64-bit range | 409 `version_exhausted` | Unchanged |
| Transition is not permitted in the current state | 409 `invalid_transition` | Unchanged |
| Same scoped export key with a different valid selection | 409 `idempotency_conflict` | Unchanged |

These are Casebook choices within the meanings of HTTP statuses. They are not a claim that every API must select these exact error codes. The proposed anonymous refusal uses 403 without choosing an HTTP authentication challenge scheme. Chapters 21–22 must settle the real identity mechanism before any public adapter is enabled. A 401 response, if chosen there, would need the appropriate authentication challenge rather than a copied status number alone.

The future HTTP error body is exactly:

```json
{"error":{"code":"invalid_fields"}}
```

Do not echo the submitted title, rejected owner or a database error. The local `ContractError` exposes the proposed status and safe code to the caller; it does not itself produce an HTTP response. Unexpected storage failures must remain failures, with no private data released. Do not turn a database outage into a successful empty result or label every exception a client error.

Validation order is part of observable behavior. Check transport shape and field types first. Inside the transaction, check current membership, then select the scoped note, compare its version, and check the state transition and role before writing. A caller outside Alpha must not learn Alpha's current version from a `stale_version` response. Shape errors may be returned before identity checks because they disclose the public schema rather than an object's state.

### Treat JSON parsing as a boundary

JSON objects map to Python dictionaries. JSON strings map to `str`; `null` maps to `None`; `true` maps to `True`. A quoted number, `"1"`, is a string. Do not silently convert it into a version. Python also treats `bool` as a subclass of `int`; the laboratory uses `type(value) is int` so `True` cannot become version `1`.

The parser below accepts UTF-8 bytes, limits their size before decoding, requires an object, and rejects duplicate keys. It also rejects `NaN` and infinities, which Python's JSON decoder can otherwise accept as extensions. A future web server must bound body ingestion too; checking `len(request.body)` after an unlimited upload has already been buffered is insufficient.

In Django, JSON bytes come from `request.body`, not from assuming `request.POST` contains a decoded JSON document. An HTTP adapter would first bound and parse the body, then call the contract operation with a trusted identity. Do not add that adapter until identity and browser protections are in place.

## 2. Required, optional, unknown and server-owned fields

A **client-owned field** is a value the client may propose under the contract. The server still validates it and decides whether the actor may change it. A **server-owned field** is selected or derived from trusted service state. Client ownership of a field is not ownership of the whole database row.

Here, `owner_id` means the note's original creator. It does not grant global permissions. Creation sets it from the trusted actor; an update preserves it even if Lee makes the edit. `updated_by` records the actor of the latest accepted write. These are different facts.

**Table T20-03. Field ownership for note creation and update**

| Field | Create request | Update request | Service rule |
| --- | --- | --- | --- |
| `title` | Required | Optional if `state` is present | String, 1–200 Unicode code points; not whitespace-only; reject C0/C1 controls and surrogate code points; preserve accepted text unchanged |
| `state` | Forbidden | Optional if `title` is present | Service starts at `open`; only the allowed transition may be requested |
| `expected_version` | Forbidden | Required | Positive JSON integer token, at most `9223372036854775807`; compare to stored version |
| `id` | Forbidden | Forbidden | Generated by the service/database |
| `workspace_id` | Forbidden in body | Forbidden in body | Requested through the path and authorized against current stored membership; cannot move a note |
| `owner_id` | Forbidden | Forbidden | Trusted creator at insertion; immutable in this contract |
| `body` | Forbidden | Forbidden | Empty on creation; existing bodies preserved on update; no body-edit contract yet |
| `version` | Forbidden | Forbidden | Start at 1; increment for each accepted update |
| `updated_by` | Forbidden | Forbidden | Set from trusted actor, never from client data |
| Any other field | Forbidden | Forbidden | Reject the entire request; do not silently ignore it |

`expected_version` is a client-supplied precondition, not permission to choose the next stored version. An omitted title preserves the current title; `"title": null` is invalid. Omission, null and an empty string are three different inputs. A request with only `expected_version` has no operation and is invalid.

Sending `owner_id` is rejected even when it equals the stored owner. This prevents a client from treating a forbidden field as writable by accident. Do not implement updates by copying every request key into a model or passing the entire dictionary to an ORM update. This unsafe pattern is commonly called **mass assignment**: external field names gain access to fields the API did not intend to expose.

### A machine-readable shape, with explicit limits

**Listing L20-01. Update request schema**

Filename: `update-request.schema.json` in the chapter 20 laboratory folder.

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "Casebook v1 note update request",
  "type": "object",
  "additionalProperties": false,
  "required": ["expected_version"],
  "properties": {
    "title": {"type": "string", "minLength": 1, "maxLength": 200},
    "state": {"enum": ["open", "archived"]},
    "expected_version": {"type": "integer", "minimum": 1, "maximum": 9223372036854775807}
  },
  "anyOf": [{"required": ["title"]}, {"required": ["state"]}],
  "$comment": "Server checks also reject blank-only titles, control characters and surrogate code points, require an integer JSON token for expected_version, and enforce membership, versions and transitions."
}
```

`required` names fields that must appear. `additionalProperties: false` rejects unlisted names. `anyOf` requires at least one of the title/state alternatives. It permits both together; the operation must then validate them together and commit them together.

This JSON Schema documents structural rules. It cannot establish current membership, a matching version or a valid transition. The title's additional text policy is enforced by `title_value` below. JSON Schema's integer concept can accept mathematically integral JSON numbers such as `1.0`; this particular wire contract is stricter and requires an integer token. Our parser leaves `1.0` as a float, and `positive_int` rejects it. Document that extra rule instead of claiming the schema alone describes every accepted byte sequence. No separate JSON Schema validator is required or executed by this laboratory.

### Define who may update

**Table T20-04. Update authorization and state policy**

| Actor | Action on an open note | Result |
| --- | --- | --- |
| Mina, active Alpha member | Change Alpha title with current version | Permit; preserve owner and body |
| Ravi, active Beta member | Change Alpha title | Generic 404; no Alpha representation |
| Ravi, active Beta member | Change Beta title with current version | Permit |
| Lee, active Alpha manager | Change Alpha title or archive Alpha note | Permit; ownership does not become Lee's |
| Lee, Alpha manager only | Change or archive Beta note | Generic 404; management is workspace-local |
| Mina, Alpha member | Archive Alpha note | 403; this action requires manager role |
| Anonymous visitor | Update either workspace's note | 403; no private representation |
| Mina after committed Alpha revocation | Next Alpha update or replayed export acceptance | Generic 404; an old successful request grants no continuing authority |

Membership is loaded from trusted stored records for each operation. The local actor IDs select test cases; the JSON payload cannot add a role or membership. A private update response is also a **read** of its returned fields, so chapter 18's privacy rule applies even when the main operation is a write.

### Worked example 1: client title, service owner

Predict a new note created by Mina with only `{"title":"برنامه انتشار"}`. The service should choose Alpha `1`, owner Mina `1`, state `open`, version `1`, and the new ID. Mina does not submit ownership.

Then let Lee update Alpha note `101` with `{"title":"Release plan v2","expected_version":1}`. Predict owner and editor separately: owner stays Mina `1`; `updated_by` becomes Lee `3`. Title changes, body stays `Alpha private fixture`, version becomes `2`.

## 3. State machines, idempotency and replayed business operations

A **state machine** defines named states and the transitions between them. Our note can be open or archived. Archiving makes it read-only under this contract; it does not delete the note, change its workspace or make it public. Current members still need authorization to read an archived note or select it for an export.

**Table T20-05. Note transitions**

| Stored state | Requested change | Required actor | Result |
| --- | --- | --- | --- |
| `open` | Title only | Active workspace member or manager | Accept; state remains open; increment version |
| `open` | `state=archived`, optionally with a title | Active workspace manager | Accept both changes atomically; increment version once |
| `open` | Explicit `state=open` | Any actor with workspace access | 409 `invalid_transition`; this is not an archive command |
| `archived` | Any title or state change | Any actor with workspace access | 409 `invalid_transition`; no reopening in v1 |

The state vocabulary and the transition policy are different checks. `open` is a known state, so it passes the vocabulary check, but requesting it as a transition from `open` is forbidden. An unknown value such as `published` receives 422 before a transition is considered. A stale version receives 409 before transition handling. A counter already at the maximum signed-64-bit value receives `version_exhausted` instead of overflowing on its next increment. Validating all fields before the update prevents a good title from slipping through alongside an invalid transition.

### Repeated note updates are not export replays

An **idempotent** operation has the same intended stored effect when repeated as when applied once. It need not return identical status codes on every attempt. PATCH is not inherently idempotent; the patch format and business behavior determine what a retry does.

Our note command is conditional on `expected_version`. The first accepted command changes version 1 to 2. Repeating the exact document with version 1 receives `409 stale_version`. The title, owner, body, version and editor remain exactly as after the first accepted command. It prevents a second mutation, but it does **not** replay a recorded success response. After losing the response, the client must obtain an authorized current representation and resolve the uncertainty. Do not blindly replace the version and resubmit the operation.

We use a body precondition here to keep the exercise small. HTTP also has conditional requests such as `If-Match` with an entity tag. A real adapter could use that standard mechanism; an `If-Match` failure uses HTTP's precondition semantics, including 412 where appropriate. Do not call our body field an ETag or translate every conflict into the same status without a contract decision.

### Worked example 2: submit one export twice

Mina wants an export of Alpha note `101`. Accepting a job does not mean exporting bytes immediately. The request is:

```http
POST /api/v1/workspaces/1/exports/ HTTP/1.1
Host: casebook.example
Content-Type: application/json
Idempotency-Key: export-001

{"note_ids":[101]}
```

Predict two arrivals with the same trusted requester, workspace, key and selection. There should be **one** stored job and the same acceptance receipt returned twice:

```json
{"job_id":1,"workspace_id":1,"state":"queued"}
```

A **request receipt** is a durable record of the accepted operation and the response that identifies it. An **idempotency key** is a client-chosen identifier used to recognize another delivery of that intended operation. It is not a password or an authorization grant.

**Exhibit D20-02. Export acceptance contract**

| Decision | Casebook rule |
| --- | --- |
| Request shape | Exactly `note_ids`; list of 1–10 distinct positive signed-64-bit integers; no booleans |
| Key shape | 1–64 ASCII letters, digits, `_` or `-` |
| Scope | Requester + workspace + export-creation operation + key; the dedicated export table supplies the operation scope |
| Equality | Sort the distinct note IDs and serialize deterministically; order is not meaningful in this v1 request |
| Authorization | Recheck current active membership and every selected note's stored workspace before accepting or returning a replayed receipt |
| First acceptance | Store one job row, canonical selection and response in the same transaction; return 202 |
| Same scoped key and same selection | Return the stored 202 receipt; create no row and perform no new job acceptance |
| Same scoped key and different valid authorized selection | 409 `idempotency_conflict`; preserve the original row |
| Same key used by Ravi in Beta | Independent operation in a different authorized scope |
| Response loss after commit | Retrying can recover the stored acceptance without a duplicate job |
| Failure before commit | Roll back both job and receipt; a later valid retry may create the first committed acceptance |
| Laboratory key lifetime | Retained for the lifetime of the temporary database; no expiry code |
| Future retention decision | Set a bounded, documented retry window and receipt cleanup policy before release; do not remove a key while promising replay protection for it |

The laboratory stores canonical request JSON directly rather than a hash, so equality does not depend on a hash choice. Equivalent object whitespace does not matter after parsing. Duplicate note IDs are invalid rather than silently removed. A different valid subset conflicts; a selection outside the workspace is refused without revealing a previous receipt. Omitting `Idempotency-Key` is invalid for this proposed export operation.

The acceptance receipt describes acceptance time. In a future system where a worker has already changed the job's state, replaying that historical receipt must not enqueue another job or falsely promise that the current job is still queued. A separately authorized status operation would return current state. This chapter stores only `queued` rows and runs no worker.

A future job could transition from queued to running, then ready or failed, or be cancelled before it starts. Those are worker-owned transitions, not accepted fields in the export request. An archive/title contract must not accidentally let a client submit `state=ready` for a job. Chapter 28 develops the worker model, and chapters 41–44 verify current permission again before private release. Request-time authorization and idempotent acceptance do not authorize eventual export delivery.

### Run the contract laboratory

Create a fresh folder named `contract-lab` inside your learning workbench, or use `examples/ch20/` in the repository. Save all following filenames in that folder. No Django dependency is required. Run with the Python environment from chapter 02; Python 3.12 or later is required.

The main module below uses chapter 15's bound SQL values. `@contextmanager` lets a generator define a `with` block: work before `yield` opens the transaction; work after it commits; an exception rolls it back. `closing` ensures the connection closes separately. With `autocommit=True`, explicit SQL `BEGIN IMMEDIATE`, `COMMIT` and `ROLLBACK` control this transaction; Python connection `commit()` is not substituted for that SQL.

`BEGIN IMMEDIATE` obtains SQLite's write transaction before the authorization and version reads. The laboratory therefore serializes these writers while it checks and mutates the row. The unique export scope is an additional database invariant. Do not copy this locking strategy unchanged to a different database or claim that it implements a distributed queue.

The response functions select fields explicitly. `snapshot` is deliberately different: it opens a fresh connection and reads full local rows for evidence. It is privileged test code and must never become a web endpoint.

**Listing L20-02. Executable contracts and trusted fixture records**

Filename: `contract_store.py`.

```python
"""Local contract model, not an HTTP endpoint or authentication mechanism."""
from contextlib import closing, contextmanager
import json
import re
import sqlite3


class ContractError(Exception):
    def __init__(self, status, code):
        self.status = status
        self.code = code
        super().__init__(code)


def reject(status, code):
    raise ContractError(status, code)


def parse_object(body, content_type):
    if content_type.partition(";")[0].strip().lower() != "application/json":
        reject(415, "unsupported_media_type")
    if len(body) > 4096:
        reject(413, "body_too_large")

    def pairs(items):
        result = {}
        for key, value in items:
            if key in result:
                reject(400, "invalid_json")
            result[key] = value
        return result

    def constant(value):
        reject(400, "invalid_json")

    try:
        payload = json.loads(body.decode("utf-8"), object_pairs_hook=pairs,
                             parse_constant=constant)
    except (UnicodeDecodeError, ValueError, RecursionError):
        reject(400, "invalid_json")
    if not isinstance(payload, dict):
        reject(400, "object_required")
    return payload


def positive_int(value):
    return type(value) is int and 1 <= value <= 2**63 - 1


def title_value(value):
    if (not isinstance(value, str) or not 1 <= len(value) <= 200
            or not value.strip() or any(ord(char) < 32 or 127 <= ord(char) <= 159
                                        or 0xD800 <= ord(char) <= 0xDFFF for char in value)):
        reject(422, "invalid_title")
    return value


@contextmanager
def write_transaction(path):
    with closing(sqlite3.connect(path, autocommit=True, timeout=2)) as db:
        db.row_factory = sqlite3.Row
        db.execute("PRAGMA foreign_keys = ON")
        db.execute("BEGIN IMMEDIATE")
        try:
            yield db
        except BaseException:
            db.execute("ROLLBACK")
            raise
        else:
            db.execute("COMMIT")


def seed(path):
    # Fresh synthetic database only: repeated setup fails instead of overwriting.
    statements = (
        "CREATE TABLE workspaces (id INTEGER PRIMARY KEY, name TEXT UNIQUE NOT NULL)",
        "CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT UNIQUE NOT NULL)",
        """CREATE TABLE memberships (
            workspace_id INTEGER REFERENCES workspaces(id),
            user_id INTEGER REFERENCES users(id),
            role TEXT NOT NULL CHECK(role IN ('member', 'manager')),
            active INTEGER NOT NULL CHECK(active IN (0, 1)),
            PRIMARY KEY(workspace_id, user_id))""",
        """CREATE TABLE notes (
            id INTEGER PRIMARY KEY, workspace_id INTEGER NOT NULL REFERENCES workspaces(id),
            owner_id INTEGER NOT NULL REFERENCES users(id), title TEXT NOT NULL,
            body TEXT NOT NULL, state TEXT NOT NULL CHECK(state IN ('open', 'archived')),
            version INTEGER NOT NULL CHECK(version > 0),
            updated_by INTEGER NOT NULL REFERENCES users(id))""",
        """CREATE TABLE export_requests (
            id INTEGER PRIMARY KEY, workspace_id INTEGER NOT NULL REFERENCES workspaces(id),
            requester_id INTEGER NOT NULL REFERENCES users(id), idem_key TEXT NOT NULL,
            request_json TEXT NOT NULL, response_json TEXT NOT NULL,
            state TEXT NOT NULL CHECK(state = 'queued'),
            UNIQUE(workspace_id, requester_id, idem_key))""",
    )
    with write_transaction(path) as db:
        for statement in statements:
            db.execute(statement)
        db.executemany("INSERT INTO workspaces VALUES (?, ?)", [(1, "Alpha"), (2, "Beta")])
        db.executemany("INSERT INTO users VALUES (?, ?)", [(1, "Mina"), (2, "Ravi"), (3, "Lee")])
        db.executemany("INSERT INTO memberships VALUES (?, ?, ?, ?)",
                       [(1, 1, "member", 1), (2, 2, "member", 1), (1, 3, "manager", 1)])
        db.executemany("INSERT INTO notes VALUES (?, ?, ?, ?, ?, ?, ?, ?)", [
            (101, 1, 1, "Release plan", "Alpha private fixture", "open", 1, 1),
            (202, 2, 2, "Pricing review", "Beta private fixture", "open", 1, 2),
        ])


def member(db, actor_id, workspace_id):
    # actor_id comes from the local test caller, never from a JSON field/header.
    if actor_id is None:
        reject(403, "access_denied")
    row = db.execute("""SELECT role FROM memberships
                        WHERE workspace_id = ? AND user_id = ? AND active = 1""",
                     (workspace_id, actor_id)).fetchone()
    if row is None:
        reject(404, "not_found")
    return row["role"]


def scoped_note(db, workspace_id, note_id):
    row = db.execute("SELECT * FROM notes WHERE workspace_id = ? AND id = ?",
                     (workspace_id, note_id)).fetchone()
    if row is None:
        reject(404, "not_found")
    return row


def note_response(row):
    fields = ("id", "workspace_id", "owner_id", "title", "state", "version", "updated_by")
    return {key: row[key] for key in fields}


def create_note(path, *, actor_id, workspace_id, payload):
    if not isinstance(payload, dict) or set(payload) != {"title"}:
        reject(422, "invalid_fields")
    title = title_value(payload["title"])
    with write_transaction(path) as db:
        member(db, actor_id, workspace_id)
        cursor = db.execute("""INSERT INTO notes
            (workspace_id, owner_id, title, body, state, version, updated_by)
            VALUES (?, ?, ?, '', 'open', 1, ?)""", (workspace_id, actor_id, title, actor_id))
        result = note_response(scoped_note(db, workspace_id, cursor.lastrowid))
    return 201, result


def update_note(path, *, actor_id, workspace_id, note_id, payload):
    if not isinstance(payload, dict):
        reject(422, "invalid_fields")
    if set(payload) - {"title", "state", "expected_version"}:
        reject(422, "invalid_fields")
    if not positive_int(payload.get("expected_version")) or not ({"title", "state"} & set(payload)):
        reject(422, "invalid_fields")
    if "title" in payload:
        title_value(payload["title"])
    if "state" in payload and payload["state"] not in ("open", "archived"):
        reject(422, "invalid_state")
    with write_transaction(path) as db:
        role = member(db, actor_id, workspace_id)
        row = scoped_note(db, workspace_id, note_id)
        if row["version"] != payload["expected_version"]:
            reject(409, "stale_version")
        if row["version"] == 2**63 - 1:
            reject(409, "version_exhausted")
        target = payload.get("state", row["state"])
        if row["state"] != "open" or ("state" in payload and target != "archived"):
            reject(409, "invalid_transition")
        if target == "archived" and role != "manager":
            reject(403, "action_denied")
        title = payload.get("title", row["title"])
        db.execute("""UPDATE notes SET title = ?, state = ?, version = version + 1,
                      updated_by = ? WHERE workspace_id = ? AND id = ?""",
                   (title, target, actor_id, workspace_id, note_id))
        result = note_response(scoped_note(db, workspace_id, note_id))
    return 200, result


def request_export(path, *, actor_id, workspace_id, key, payload):
    if not isinstance(key, str) or re.fullmatch(r"[A-Za-z0-9_-]{1,64}", key) is None:
        reject(422, "invalid_idempotency_key")
    if not isinstance(payload, dict) or set(payload) != {"note_ids"}:
        reject(422, "invalid_fields")
    ids = payload["note_ids"]
    if (not isinstance(ids, list) or not 1 <= len(ids) <= 10
            or not all(positive_int(item) for item in ids) or len(set(ids)) != len(ids)):
        reject(422, "invalid_note_ids")
    canonical = json.dumps({"note_ids": sorted(ids)}, separators=(",", ":"))
    with write_transaction(path) as db:
        member(db, actor_id, workspace_id)
        for note_id in ids:
            scoped_note(db, workspace_id, note_id)
        previous = db.execute("""SELECT request_json, response_json FROM export_requests
            WHERE workspace_id = ? AND requester_id = ? AND idem_key = ?""",
            (workspace_id, actor_id, key)).fetchone()
        if previous is not None:
            if previous["request_json"] != canonical:
                reject(409, "idempotency_conflict")
            result = json.loads(previous["response_json"])
        else:
            cursor = db.execute("""INSERT INTO export_requests
                (workspace_id, requester_id, idem_key, request_json, response_json, state)
                VALUES (?, ?, ?, ?, '{}', 'queued')""", (workspace_id, actor_id, key, canonical))
            result = {"job_id": cursor.lastrowid, "workspace_id": workspace_id, "state": "queued"}
            db.execute("UPDATE export_requests SET response_json = ? WHERE id = ?",
                       (json.dumps(result, separators=(",", ":")), cursor.lastrowid))
    return 202, result


def snapshot(path):
    # Privileged local evidence only; never return this from a public endpoint.
    with closing(sqlite3.connect(path, autocommit=True)) as db:
        db.row_factory = sqlite3.Row
        return {
            "notes": [dict(row) for row in db.execute("SELECT * FROM notes ORDER BY id")],
            "exports": [dict(row) for row in db.execute("SELECT * FROM export_requests ORDER BY id")],
        }
```

`seed` accepts only a fresh synthetic database. Calling it twice on the same file fails at table creation instead of overwriting records. Its note bodies, titles and IDs match chapter 19. Ownership, state and version are laboratory additions. They do not alter the signature or schema of chapter 15's repository.

`member` loads current membership inside each write transaction. The owner field is absent from the update statement, so accepted title edits cannot transfer ownership. `note_response` excludes the private body; `snapshot` includes it so state comparisons can detect an unintended body edit too.

For export acceptance, the placeholder response and final receipt are committed together. An exception between insertion and completion rolls back the row. If the database lock cannot be acquired or storage fails, an operational error escapes rather than pretending the operation succeeded. Retrying such errors needs a bounded policy in a later service integration.

```python
from pathlib import Path
from tempfile import TemporaryDirectory

from contract_store import ContractError, create_note, request_export, seed, snapshot, update_note


def show_note(path, label):
    row = snapshot(path)["notes"][0]
    print(label, (row["id"], row["workspace_id"], row["owner_id"], row["title"],
                  row["state"], row["version"], row["updated_by"]))


def denied(label, operation):
    try:
        operation()
    except ContractError as exc:
        print(label, exc.status, exc.code)
    else:
        raise AssertionError("Expected contract refusal")


def main():
    with TemporaryDirectory(prefix="casebook-contract-") as folder:
        path = Path(folder) / "contract.sqlite3"
        seed(path)
        show_note(path, "initial:")
        before = snapshot(path)
        denied("unknown:", lambda: update_note(path, actor_id=1, workspace_id=1, note_id=101,
                payload={"title": "Wrong", "titel": "typo", "expected_version": 1}))
        print("unchanged after unknown:", snapshot(path) == before)
        denied("server field:", lambda: update_note(path, actor_id=1, workspace_id=1, note_id=101,
                payload={"owner_id": 2, "title": "Wrong", "expected_version": 1}))
        print("unchanged after server field:", snapshot(path) == before)
        status, created = create_note(path, actor_id=1, workspace_id=1,
                                      payload={"title": "برنامه انتشار"})
        print("created:", status, created["id"], created["owner_id"], created["title"])
        patch = {"title": "Release plan v2", "expected_version": 1}
        print("update:", update_note(path, actor_id=3, workspace_id=1, note_id=101, payload=patch)[0])
        show_note(path, "stored:")
        accepted = snapshot(path)
        denied("repeat patch:", lambda: update_note(path, actor_id=3, workspace_id=1,
                                                    note_id=101, payload=patch))
        print("unchanged after repeat:", snapshot(path) == accepted)
        denied("transition:", lambda: update_note(path, actor_id=3, workspace_id=1, note_id=101,
                                                 payload={"state": "open", "expected_version": 2}))
        show_note(path, "after invalid transition:")
        print("unchanged after transition:", snapshot(path) == accepted)
        denied("Ravi to Alpha:", lambda: update_note(path, actor_id=2, workspace_id=1,
                                                    note_id=101, payload=patch))
        first = request_export(path, actor_id=1, workspace_id=1, key="export-001",
                               payload={"note_ids": [101]})
        stored = snapshot(path)
        second = request_export(path, actor_id=1, workspace_id=1, key="export-001",
                                payload={"note_ids": [101]})
        print("export:", first)
        print("same reply:", second == first)
        print("same stored rows:", snapshot(path) == stored)
        print("job rows:", len(snapshot(path)["exports"]))
        denied("changed replay:", lambda: request_export(path, actor_id=1, workspace_id=1,
                key="export-001", payload={"note_ids": [101, created["id"]]}))
        print("unchanged after conflict:", snapshot(path) == stored)
```

### Repeatable tests, including rollback

The following tests use standard-library `unittest`, so a package download is not required. Chapter 12's testing principles still apply: each case has isolated setup, an observable operation and a specific expected result.

`assert_refused` takes a full snapshot, checks the status and safe code, then reopens storage and compares the full business state. The permission cases include successful Alpha and Beta updates, cross-workspace refusal, Lee outside Alpha and committed revocation. The injected SQLite trigger is a synthetic failure: it raises an error while completing the receipt, after insertion has begun. The test verifies that no orphan job or consumed key remains.

**Listing L20-04. Contract regression checks**

Filename: `test_contract.py`.

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import sqlite3
import unittest

from contract_store import (
    ContractError, create_note, parse_object, request_export, seed, snapshot, update_note,
)


class ContractTests(unittest.TestCase):
    def setUp(self):
        self.folder = TemporaryDirectory(prefix="casebook-contract-test-")
        self.addCleanup(self.folder.cleanup)
        self.path = Path(self.folder.name) / "contract.sqlite3"
        seed(self.path)

    def patch(self, payload, actor=1, workspace=1, note=101):
        return update_note(self.path, actor_id=actor, workspace_id=workspace,
                           note_id=note, payload=payload)

    def export(self, payload, actor=1, workspace=1, key="export-001"):
        return request_export(self.path, actor_id=actor, workspace_id=workspace,
                              key=key, payload=payload)

    def assert_refused(self, status, code, operation):
        before = snapshot(self.path)
        with self.assertRaises(ContractError) as caught:
            operation()
        self.assertEqual((caught.exception.status, caught.exception.code), (status, code))
        self.assertEqual(snapshot(self.path), before)

    def test_json_boundary(self):
        self.assertEqual(parse_object('{"title":"برنامه"}'.encode(), "application/json"),
                         {"title": "برنامه"})
        for body, media, status, code in (
            (b"{}", "text/plain", 415, "unsupported_media_type"),
            (b" " * 4097, "application/json", 413, "body_too_large"),
            (b'{"title":"A","title":"B"}', "application/json", 400, "invalid_json"),
            (b'{"x":NaN}', "application/json", 400, "invalid_json"),
            (b"\xff", "application/json", 400, "invalid_json"),
            (b"[", "application/json", 400, "invalid_json"),
            (b"[]", "application/json", 400, "object_required"),
        ):
            with self.subTest(body=body[:30]):
                self.assert_refused(status, code, lambda: parse_object(body, media))

    def test_create_derives_owner_and_update_preserves_it(self):
        status, created = create_note(self.path, actor_id=1, workspace_id=1,
                                      payload={"title": "برنامه انتشار"})
        self.assertEqual((status, created["owner_id"]), (201, 1))
        status, edited = self.patch({"title": "Edited by Lee", "expected_version": 1},
                                    actor=3, note=created["id"])
        self.assertEqual((status, edited["owner_id"], edited["updated_by"]), (200, 1, 3))
        stored = next(row for row in snapshot(self.path)["notes"] if row["id"] == created["id"])
        self.assertEqual((stored["title"], stored["body"], stored["version"]), ("Edited by Lee", "", 2))

    def test_fields_and_types_are_strict(self):
        for payload in (
            {}, {"expected_version": 1}, {"title": "A"},
            {"title": "A", "expected_version": True},
            {"title": "A", "expected_version": 1.0},
            {"title": "A", "expected_version": 2**63},
            {"title": "A", "expected_version": 1, "titel": "B"},
            {"title": "A", "expected_version": 1, "owner_id": 2},
            {"title": "A", "expected_version": 1, "workspace_id": 2},
        ):
            with self.subTest(payload=payload):
                self.assert_refused(422, "invalid_fields", lambda: self.patch(payload))
        for title in (None, "", " ", "A" * 201, "line\nbreak", "\ud800"):
            with self.subTest(title=repr(title)):
                self.assert_refused(422, "invalid_title",
                                    lambda: self.patch({"title": title, "expected_version": 1}))

    def test_permission_matrix_and_current_membership(self):
        for actor, workspace, note, status in ((None, 1, 101, 403), (2, 1, 101, 404),
                                              (3, 2, 202, 404), (1, 1, 202, 404)):
            code = "access_denied" if actor is None else "not_found"
            self.assert_refused(status, code, lambda: self.patch(
                {"title": "Denied", "expected_version": 1}, actor, workspace, note))
        self.assertEqual(self.patch({"title": "Alpha allowed", "expected_version": 1})[0], 200)
        self.assertEqual(self.patch({"title": "Beta allowed", "expected_version": 1}, 2, 2, 202)[0], 200)
        with sqlite3.connect(self.path) as db:
            db.execute("UPDATE memberships SET active = 0 WHERE user_id = 1 AND workspace_id = 1")
        self.assert_refused(404, "not_found", lambda: self.patch(
            {"title": "After revocation", "expected_version": 2}))

    def test_stale_repeat_and_invalid_transition_leave_full_state_unchanged(self):
        patch = {"title": "Release plan v2", "expected_version": 1}
        self.patch(patch)
        self.assert_refused(409, "stale_version", lambda: self.patch(patch))
        self.assert_refused(409, "invalid_transition", lambda: self.patch(
            {"title": "Must not leak through", "state": "open", "expected_version": 2}, actor=3))
        self.assertEqual(snapshot(self.path)["notes"][0]["title"], "Release plan v2")
        with sqlite3.connect(self.path) as db:
            db.execute("UPDATE notes SET version = ? WHERE id = 101", (2**63 - 1,))
        self.assert_refused(409, "version_exhausted", lambda: self.patch(
            {"title": "Beyond the version range", "expected_version": 2**63 - 1}))

    def test_archive_is_manager_only_and_terminal(self):
        self.assert_refused(403, "action_denied", lambda: self.patch(
            {"state": "archived", "expected_version": 1}))
        self.patch({"state": "archived", "expected_version": 1}, actor=3)
        for payload in ({"state": "open", "expected_version": 2},
                        {"title": "Late edit", "expected_version": 2}):
            self.assert_refused(409, "invalid_transition", lambda: self.patch(payload, actor=3))
        self.assertEqual(snapshot(self.path)["notes"][0]["state"], "archived")

    def test_export_replay_conflict_and_key_scope(self):
        first = self.export({"note_ids": [101]})
        before = snapshot(self.path)
        self.assertEqual(self.export({"note_ids": [101]}), first)
        self.assertEqual(snapshot(self.path), before)
        extra = create_note(self.path, actor_id=1, workspace_id=1, payload={"title": "Extra"})[1]
        self.assert_refused(409, "idempotency_conflict", lambda: self.export(
            {"note_ids": [101, extra["id"]]}))
        beta = self.export({"note_ids": [202]}, actor=2, workspace=2)
        self.assertNotEqual(first[1]["job_id"], beta[1]["job_id"])
        self.assertEqual(len(snapshot(self.path)["exports"]), 2)

    def test_export_canonical_order_and_bounds(self):
        extra = create_note(self.path, actor_id=1, workspace_id=1, payload={"title": "Extra"})[1]
        first = self.export({"note_ids": [101, extra["id"]]})
        self.assertEqual(self.export({"note_ids": [extra["id"], 101]}), first)
        for ids in ([], [True], [101, 101], list(range(1, 12)), [2**63]):
            self.assert_refused(422, "invalid_note_ids", lambda: self.export({"note_ids": ids}))
        self.assert_refused(422, "invalid_idempotency_key", lambda: self.export(
            {"note_ids": [101]}, key="bad key"))
        self.assert_refused(404, "not_found", lambda: self.export({"note_ids": [202]}))

    def test_replay_rechecks_permission(self):
        self.export({"note_ids": [101]})
        with sqlite3.connect(self.path) as db:
            db.execute("UPDATE memberships SET active = 0 WHERE user_id = 1 AND workspace_id = 1")
        self.assert_refused(404, "not_found", lambda: self.export({"note_ids": [101]}))

    def test_failure_before_receipt_completion_rolls_back_job_and_key(self):
        with sqlite3.connect(self.path) as db:
            db.execute("""CREATE TRIGGER fail_reply BEFORE UPDATE OF response_json ON export_requests
                          BEGIN SELECT RAISE(ABORT, 'synthetic receipt failure'); END""")
        before = snapshot(self.path)
        with self.assertRaises(sqlite3.IntegrityError):
            self.export({"note_ids": [101]})
        self.assertEqual(snapshot(self.path), before)


if __name__ == "__main__":
    unittest.main()
```

## 4. Pagination caps, API versioning, deprecation and inventory

A contract also describes how much work a caller may request and which deployed surfaces still exist. A correct detail endpoint does not protect an unbounded list or a forgotten earlier version.

### Bound collection requests

**Pagination** divides a collection into bounded responses. The proposed note-list contract uses a default `limit` of 20 and a maximum of 50. These values are local design choices, not limits imposed by HTTP or OWASP.

**Exhibit D20-03. Proposed list contract; not implemented by the laboratory**

| Decision | Contract |
| --- | --- |
| Path | GET `/api/v1/workspaces/{workspace_id}/notes/` |
| Authority | Validated identity and current active membership in the requested workspace, checked on every page |
| `limit` | Optional decimal integer from 1 to 50; default 20; out-of-range or malformed value returns 400 `invalid_query` |
| `after_id` | Optional positive signed-64-bit decimal integer; absent means the first page |
| Unknown or repeated query names | 400 `invalid_query`; do not choose silently between duplicate values |
| Selection | Only this authorized workspace; IDs greater than `after_id`; ascending ID order |
| Database bound | Fetch at most `limit + 1` authorized rows to decide whether another page exists |
| `items` | At most `limit` objects, each with exactly `id`, `title`, `state`, `version`; no bodies |
| `next_after_id` | Last returned ID when an additional row exists, otherwise null |
| Totals | No cross-workspace counts or unbounded total-count work |
| Concurrent changes | Not a frozen snapshot; later inserts may appear and deleted rows may disappear between pages |
| Response handling | Private representation with an explicit no-store policy in the future HTTP adapter |

`after_id` is a position, not an access token. Modifying it cannot grant membership. A page limit is also not a rate limit: many bounded requests can still exhaust a service. Resource and queue controls follow in chapter 28.

For the seeded Alpha workspace, a future request with `limit=1` would return the following before note `203` is created:

```json
{"items":[{"id":101,"title":"Release plan","state":"open","version":1}],"next_after_id":null}
```

Ravi requesting that Alpha page must receive the same generic access refusal as other unauthorized Alpha operations, not this title, a total count or a helpful next-page hint. After adding Alpha note `203`, the first page can return `next_after_id=101`; the next page must check current membership again. Revocation between pages must affect the next check.

### Version behavior, not only URLs

**API versioning** identifies a contract a client can depend on. This proposal uses `/api/v1/` for private API routes while keeping chapter 19's health path outside the private API version. The prefix does not authorize a caller, and keeping `/api/v0/` around would not excuse weaker checks there.

Changing a title limit, making an optional field required, altering ownership, allowing archived edits, changing a retry window or changing the meaning of a state can break a client even if the route stays the same. Review a new response field too: the response schema here is explicit, and a strict consumer may reject an addition. Never expose an internal model column just because it seems like an additive API change.

A **deprecation** notice tells consumers that a contract is planned for removal or replacement. A **sunset** is the planned end of availability. Before retiring a version, record the replacement, affected consumers, owner, migration instructions, announced deadline and observed use. An old route remains an attack surface until routing, deployment and tests show that it is gone or intentionally gated.

For a concrete planning exercise, suppose a future v2 replaces body `expected_version` with `If-Match`. The migration record must explain the new tag format, conflict statuses and client retry procedure. It must test both versions during overlap and verify v1 removal after its approved deadline. This is a hypothetical change, not an existing v2 implementation or a scheduled removal.

### Keep an honest inventory

An **API inventory** is a record of entry points, owners, data and status. It must distinguish deployed routes from designed operations and local test interfaces.

**Exhibit D20-04. Casebook inventory after this chapter**

| Entry point | Status | Data and authority | Owner and evidence |
| --- | --- | --- | --- |
| GET `/health/` | Implemented in chapter 19 source; its recorded runtime gap remains | Public fixed status; no note fields | Web maintainer; chapter 19 test and verification record |
| POST v1 note collection | Contract plus local `create_note` model only | Private title; active workspace membership; owner derived from requester | Web maintainer; creation and ownership test |
| PATCH v1 note detail | Contract plus local `update_note` model only | Title/state mutation and private response; current membership, role and version | Web maintainer; permit/deny, stale-write and transition tests |
| POST v1 exports | Contract plus local `request_export` model only | Scoped note selectors and job receipt; current membership and durable replay binding | Job maintainer; replay, conflict, revocation and rollback tests |

Review this inventory whenever a route, method, fixture bypass or export path is added. A function that exists only in a local model is not proof that a deployed API has the same checks.

- A current version does not grant a role, and an idempotency key does not grant membership.
- Check every stored field after a refusal, not only the status or row count.
- A replay window and a worker's delivery guarantee are separate design decisions.

### Exercise 2

The open-to-open command receives 409 `invalid_transition`; the valid title does not partially apply. Save this optional answer program in the laboratory folder as `transition_answer.py`:

```python
from pathlib import Path
from tempfile import TemporaryDirectory
from contract_store import ContractError, seed, snapshot, update_note

with TemporaryDirectory() as folder:
    path = Path(folder) / 'answer.sqlite3'
    seed(path)
    before = snapshot(path)
    try:
        update_note(path, actor_id=3, workspace_id=1, note_id=101,
                    payload={'title': 'Unexpected title', 'state': 'open', 'expected_version': 1})
    except ContractError as exc:
        print(exc.status, exc.code)
    else:
        raise AssertionError('Expected invalid transition')
    print('same complete state:', snapshot(path) == before)
    update_note(path, actor_id=3, workspace_id=1, note_id=101,
                payload={'state': 'archived', 'expected_version': 1})
    archived = snapshot(path)
    try:
        update_note(path, actor_id=3, workspace_id=1, note_id=101,
                    payload={'title': 'Late title', 'expected_version': 2})
    except ContractError as exc:
        print(exc.status, exc.code)
    else:
        raise AssertionError('Expected archived-note refusal')
    print('same archived state:', snapshot(path) == archived)
```

Run `python transition_answer.py`. Expected, and observed during verification:

```text

same complete state: True
409 invalid_transition
same archived state: True
```

The second write uses the new version 2, so its refusal demonstrates the archived-state rule rather than merely a stale-version conflict.

### Exercise 5 and the Part V checkpoint

`CB-READ-01` requires current active membership in the note's stored workspace for private data release. At TB1, a browser supplies a note/workspace selector and proposed JSON fields. The service must establish the requester independently; this laboratory substitutes a trusted fixture caller for that future identity mechanism.

Inside the transaction, `member` reads current stored membership and `scoped_note` binds the selected note to the authorized workspace. Only then may `note_response` release its allowed private fields. Ravi cannot obtain Alpha's title or current version through this path. Export receipt replay checks membership and selected-note scope again before returning even the private job metadata.

The local tests prove these decisions for synthetic stored records, including revocation. They do not prove real authentication, HTTP parsing integration, CSRF protection, cache handling, route coverage or a worker's later check. Chapters 21–24 add identity and browser integration; chapters 28 and 41–44 must recheck current authorization for background source reads and release. The API contract is now connected to the requirement, while those integration claims remain explicit future evidence.

## What you can now explain

A useful API contract distinguishes a valid shape from a permitted change. A client may propose a title while the service derives ownership, checks current membership and preserves immutable associations. Invalid input, forbidden transitions and stale retries must leave observable stored state intact. Export acceptance needs its own durable replay binding so repeated delivery does not create another job.

Keep chapter 19's service unchanged and retain this chapter's contract tables, schema and local checks. Chapter 21 starts from the two-workspace fixture and private-default service to add account behavior. The contract laboratory's integer actor IDs remain test fixtures; they are not a shortcut for authenticating a browser. Ownership/state/version additions still need an explicit Django migration and HTTP integration when that feature is implemented.
