## 1. Media types, file signatures and separate display and storage names

An **attachment** is a stored file associated with a protected object. An attachment to Alpha note `101` remains private Alpha data even if it has a long random storage name.

A **display name** is a label shown to the user, such as `report.txt`. A **storage key** is the service-selected internal identity used to locate bytes. Two attachments may have the same display name and different keys. Neither a filename nor a key proves permission to retrieve the bytes.

A **media type** describes a representation, for example `text/plain` or `application/pdf`. A browser's upload Content-Type and filename are untrusted declarations. The suffix `.pdf` does not establish that a file is a valid PDF. A **file signature** is a recognizable byte pattern, such as a format header. Matching it is useful evidence but not proof that the complete file is valid, harmless or free of another interpretable payload.

### Choose a small content policy before accepting bytes

Our lesson accepts UTF-8 text reports only. Plain UTF-8 text has no single universal magic signature. The implementation therefore validates the full bounded text rather than pretending an extension or a made-up magic prefix proves the format. It does not parse PDF, Office documents, images or uploaded archives.

**Exhibit D25-01. Attachment policy `CB-ATTACH-25`**

| Decision | Local rule |
| --- | --- |
| Protected object | An existing note in the requested workspace |
| Upload authority | Current active account and recognized active membership in the note's workspace; checked before ingestion and again before publication |
| Display name | 1–80 characters, exact `.txt` suffix; no slash, backslash, colon, C0/C1 controls or surrogate code points; Unicode names allowed |
| Storage identity | Service-generated 32-character lowercase hexadecimal key, unrelated to the display name |
| Declared type | Exactly `text/plain` for this local interface |
| Actual content | Valid UTF-8; no C0/C1 controls except tab, CR and LF |
| Size | At least one byte and at most 64 bytes, inclusive; a deliberately small teaching limit |
| Ingestion | Binary stream, reads of at most 16 bytes, with at most one byte beyond the remaining allowance requested to detect overflow |
| Rejected state | No new metadata row, object or staging file after handled rejection and successful cleanup |
| Retrieval | Current note authorization through trusted stored workspace/note binding; no direct public path |
| Delivery contract for a future HTTP adapter | Approved media type, safe attachment disposition, no-store and nosniff; never concatenate a raw display name into headers |

The limit is measured in **bytes**, not text characters. A non-English character can use several UTF-8 bytes. A valid display name or claimed Content-Length does not exempt the stream from actual byte counting.

A text attachment can contain the literal string `<script>`. This policy does not certify that string as safe HTML or execute it. A web adapter must use the approved download/escaping boundary from chapter 24 rather than rendering uploaded text as trusted HTML. Content validation and safe serving are separate controls.

For richer formats, choose maintained parsers and required content checks under resource limits. Malware scanning or content disarm, when required, belongs before a file becomes available and needs its own failure and availability policy. A scan-passed flag must not replace authorization.

## 2. Path traversal prevention, symlinks, permissions and isolated storage

**Path traversal** occurs when external path syntax changes which filesystem location an operation reaches. Examples include `../report.txt`, an absolute path, Windows separators or a drive-like name. Stripping one leading `../` is not a complete storage policy.

Here the display name never participates in path construction. The service generates a fixed-format key inside a configured private objects directory. The display-name restrictions also protect predictable UI/header behavior, but generated keys are the main separation between label and location.

A **symbolic link**, or **symlink**, redirects pathname resolution. Validating a path string is not enough if an attacker can swap a directory or link before opening it. A **time-of-check/time-of-use race** happens when the object used later is no longer the object that was checked.

### State the storage trust boundary

**Table T25-01. Storage layout and ownership**

| Location | Owner and contents | Rule |
| --- | --- | --- |
| Service-controlled parent | Private exercise directory containing the database and storage root | Uploaders cannot create, replace or rename ancestors |
| `private/` | Service-owned root, mode 0700 | Not under a public static/media server directory |
| `private/staging/` | Random temporary files, created mode 0600 | Never directly retrievable by users |
| `private/objects/` | Accepted generated-key files, mode 0600 | Access through the authorized service only |
| Database | Note bindings, names, types, sizes and digests | Protected storage; filename/key metadata may also be sensitive |

POSIX mode **0700** grants the owner directory access and excludes other ordinary accounts; **0600** grants the owner file read/write access. These do not protect against a privileged operator or a process already running as the same account. Deployment isolation and storage credentials remain separate controls.

The retrieval code uses `O_NOFOLLOW` to refuse a symlink at the final file component and `fstat` to require a regular file. Its parent directories must still be trusted. Calling `resolve()` and checking a prefix once would not by itself remove later directory-swap races. A production backend needing stronger guarantees should use appropriate descriptor-relative or storage-service mechanisms and test its actual platform.

### Stage, validate, publish and record

**Staging** holds bytes before they are approved for use. **Publication** makes the approved object available to the service's private retrieval path. In this lab, a hard link creates the final generated-key directory entry without overwriting an existing name. Staging and final storage are on the same filesystem.

**Table T25-02. Lifecycle and compensating cleanup**

| Point | Filesystem state | Metadata state |
| --- | --- | --- |
| Before reading | No new file | No new row |
| During bounded ingestion | One private staging file, at most 64 written bytes | No new row |
| Size/content rejection | Remove that staging file | No new row |
| Content accepted | Staging complete; recheck current permission | No committed new row yet |
| Publication and metadata write | Create final hard link without overwrite | Insert binding and commit |
| Successful completion | Remove staging name; final object remains | One committed row |
| Handled metadata failure | Remove final object created by this attempt and staging name | Transaction rollback leaves no new row |
| Key collision | Preserve the old object; remove only this attempt's staging file | Preserve the earlier metadata |

The database transaction cannot atomically commit an ordinary filesystem operation. The code compensates for handled errors, but does not provide crash-safe publication. A process killed between linking and metadata commit can leave an orphan object; after commit, a crash can leave an extra staging name. Production reconciliation needs durable operation state, retry-safe cleanup and a carefully defined orphan policy. An uncertain commit result also needs reconciliation rather than assuming rollback.

A cleanup failure must be reported. The code lets unlink failures propagate. If staging cleanup fails after metadata already committed, a caller can see an error even though the accepted object exists. Inspect and reconcile that actual state; do not report “discarded” merely because the function raised an exception.

**Listing L25-01. Bounded private attachment storage**

Filename: `examples/ch25/attachments.py`.

```python
"""POSIX local attachment laboratory; no HTTP endpoint or antivirus claim."""
import hashlib
import os
from pathlib import Path
import re
import secrets
import stat
import tempfile

from examples.ch23.authorization_service import AccessDenied, require_member, seed, unit, visible_rows

MAX_BYTES = 64
CHUNK_BYTES = 16


class Rejected(ValueError):
    pass


def initialize(database, root):
    # Fresh, service-owned paths only. Uploaders must not control these directories.
    root.mkdir(mode=0o700)
    (root / "staging").mkdir(mode=0o700)
    (root / "objects").mkdir(mode=0o700)
    seed(database)
    with unit(database, write=True) as db:
        db.execute("""CREATE TABLE attachments (
            key TEXT PRIMARY KEY, workspace_id INTEGER NOT NULL REFERENCES workspaces(id),
            note_id INTEGER NOT NULL REFERENCES notes(id), uploaded_by INTEGER NOT NULL REFERENCES users(id),
            display_name TEXT NOT NULL, media_type TEXT NOT NULL, size INTEGER NOT NULL,
            sha256 TEXT NOT NULL)""")


def authorize(db, user_id, workspace_id, note_id):
    require_member(db, user_id, workspace_id)
    if not visible_rows(db, user_id=user_id, workspace_id=workspace_id, note_ids=[note_id], limit=1):
        raise AccessDenied()


def upload(database, root, *, user_id, workspace_id, note_id, display_name, media_type, stream):
    with unit(database) as db:
        authorize(db, user_id, workspace_id, note_id)
    if (not isinstance(display_name, str) or not 1 <= len(display_name) <= 80
            or display_name in (".", "..") or any(c in display_name for c in '/\\:')
            or any(ord(c) < 32 or 127 <= ord(c) <= 159 or 0xD800 <= ord(c) <= 0xDFFF for c in display_name)
            or not display_name.endswith(".txt")):
        raise Rejected("invalid_display_name")
    if media_type != "text/plain":
        raise Rejected("unsupported_media_type")
    descriptor, temporary = tempfile.mkstemp(prefix="incoming-", dir=root / "staging")
    temporary = Path(temporary)
    final = None
    published = False
    try:
        size = 0
        with os.fdopen(descriptor, "wb") as destination:
            while True:
                chunk = stream.read(min(CHUNK_BYTES, MAX_BYTES - size + 1))
                if not chunk:
                    break
                if not isinstance(chunk, bytes):
                    raise Rejected("binary_stream_required")
                if size + len(chunk) > MAX_BYTES:
                    raise Rejected("too_large")
                destination.write(chunk)
                size += len(chunk)
        if size == 0:
            raise Rejected("empty_file")
        data = temporary.read_bytes()  # Bounded by MAX_BYTES, not an unbounded upload read.
        try:
            text = data.decode("utf-8")
        except UnicodeDecodeError as exc:
            raise Rejected("invalid_utf8") from exc
        if any(ord(c) < 32 and c not in "\t\r\n" or 127 <= ord(c) <= 159 for c in text):
            raise Rejected("invalid_text")
        key = secrets.token_hex(16)
        final = root / "objects" / key
        # Hard-link publication refuses an existing key, including a pre-existing symlink.
        # Staging and objects are service-owned directories on the same filesystem.
        with unit(database, write=True) as db:
            authorize(db, user_id, workspace_id, note_id)  # Current permission after ingestion.
            os.link(temporary, final)
            published = True
            db.execute("INSERT INTO attachments VALUES (?,?,?,?,?,?,?,?)",
                       (key, workspace_id, note_id, user_id, display_name, "text/plain", size,
                        hashlib.sha256(data).hexdigest()))
        return key
    except BaseException:
        if published:
            final.unlink()  # Compensate for this attempt only; never delete an older collision.
        raise
    finally:
        temporary.unlink()  # Cleanup failures propagate; do not silently claim clean state.


def retrieve(database, root, *, user_id, key):
    if user_id is None:
        raise AccessDenied(403, "access_denied")
    if not isinstance(key, str) or re.fullmatch(r"[0-9a-f]{32}", key) is None:
        raise AccessDenied()
    with unit(database) as db:
        row = db.execute("SELECT * FROM attachments WHERE key=?", (key,)).fetchone()
        if row is None:
            raise AccessDenied()
        authorize(db, user_id, row["workspace_id"], row["note_id"])
        # O_NOFOLLOW protects the final component. Parent directories must remain trusted.
        descriptor = os.open(root / "objects" / key, os.O_RDONLY | os.O_NOFOLLOW)
        with os.fdopen(descriptor, "rb") as source:
            if not stat.S_ISREG(os.fstat(source.fileno()).st_mode):
                raise Rejected("not_regular_file")
            data = source.read(MAX_BYTES + 1)
        if len(data) != row["size"] or hashlib.sha256(data).hexdigest() != row["sha256"]:
            raise Rejected("stored_content_mismatch")
        return row["display_name"], data


def inventory(database, root):
    # Privileged local inspection only, not a list endpoint for arbitrary callers.
    with unit(database) as db:
        rows = [dict(row) for row in db.execute("SELECT * FROM attachments ORDER BY rowid")]
    return {"rows": rows, "objects": sorted(p.name for p in (root / "objects").iterdir()),
            "staging": sorted(p.name for p in (root / "staging").iterdir())}
```

The first authorization gate prevents a denied caller from making this service ingest private attachment work. The second gate checks permission after the potentially slow stream has been read. The revocation-during-ingestion test commits a membership change between those gates and confirms that no object or metadata is published.

The stream belongs to the caller, which must close the incoming upload object under its own framework lifecycle. The service closes the destination descriptor and removes its own staging name. `read(min(...))` assumes a normal binary stream that honors the requested bound; it cannot undo buffering that already happened in an HTTP server or parser.

When 64 bytes have been read, the next read requests only one byte. If that byte exists, `too_large` is raised before it is written. Empty input is refused. Content decoding happens only after the staging file is known to fit the bound, so the later `read_bytes()` is bounded by the accepted-file cap.

The SHA-256 digest detects mismatch between stored metadata and the bytes read during retrieval. It is not malware detection, a permission token or protection against an attacker who can rewrite both metadata and file. Permissions still come from trusted current membership.

### Connect to Django without confusing buffering and limits

A future browser upload form needs `enctype="multipart/form-data"`, and Django supplies incoming files through `request.FILES`. Keep the actual authenticated identity, CSRF enforcement and object scope from chapter 24. Do not accept an uploader/workspace binding from a filename or hidden permission flag.

Django's memory/spooling thresholds are not a complete maximum-upload policy. Configure request-ingestion limits, count file bytes through a bounded handler/service, bound total request/file counts and disk use, and account for timeouts and concurrency. A check performed only after an entire large upload has already been buffered cannot protect that earlier resource consumption. No Django upload handler or proxy was exercised here.

For private download, load the metadata by internal identifier, authorize the associated stored note and use the framework's safe download/header APIs. A framework-generated attachment filename is preferable to raw `Content-Disposition` concatenation. Do not serve the objects directory through an alternate unauthenticated media route. Concurrent revocation/release ordering remains the explicit integration issue from chapter 23.

## 3. Archive entry policy, expansion budgets and cleanup on rejection

An **archive** holds several entries in one container. A **manifest** describes entries, including names, kinds and sizes. A supplied manifest is untrusted input, not proof of what an archive will actually produce.

Compressed input can expand into much more output. An **expansion budget** bounds the uncompressed bytes and other work the service permits. A compressed-size cap alone cannot prevent excessive expansion.

### Worked example 2: review a supplied manifest

The laboratory reviews JSON manifest data only. It does not open a ZIP or TAR file and does not extract any entry. This is a concrete decision exercise before adding an extractor.

**Exhibit D25-02. Archive preflight policy**

| Property | Local rule |
| --- | --- |
| Manifest input | At most 4,096 bytes of UTF-8 JSON; duplicate keys and non-JSON numeric constants rejected |
| Count | 1–5 entries |
| Shape | Exactly `name`, `kind`, `compressed`, `expanded` |
| Name | Relative slash-separated path, at most three segments; conservative ASCII segment allowlist |
| Kinds | Regular file only; no directory entries, symlinks, hard links, device entries or special files |
| Content selection | `.txt` entries only; no nested archive processing |
| Name collisions | Reject case-insensitive duplicates and file/path-prefix conflicts |
| Declared expanded entry size | 1–64 bytes |
| Declared total expanded size | At most 128 bytes |
| Declared expansion ratio | At most 20:1 per entry |
| Archive decision | If any entry fails, refuse the whole proposed archive |
| Extraction | None in this lab; zero extracted files regardless of manifest result |

The narrow ASCII archive-path policy is separate from allowing Unicode attachment display names. Archive names are proposed output structure; display labels are not filesystem paths. The code rejects a `..` component through its segment policy. A harmless pair of dots inside a permitted filename is not the same as a parent-directory component.

For a real extractor, derive metadata from the opened container with a maintained parser, validate every entry and measure actual output during decompression. Reject unexpected metadata, encrypted/unsupported content and nested formats under an explicit policy. Even an accepted manifest must not bypass actual file/content validation. Bound parser CPU/time and entry count, actual per-entry and total bytes, temporary disk and concurrency. A compression ratio is supplementary, not a replacement for an absolute output cap.

Extract only into a fresh private staging tree. Reject archive-controlled links and special entries rather than following them. Publish no partial output if a later entry fails; close handles and remove the private tree, then verify final absence. A library's `extractall()` call is not your complete application policy. This draft implements none of that extraction machinery and makes no claim that manifest arithmetic alone prevents archive attacks.

**Listing L25-02. Manifest parsing and preflight decisions**

Filename: `examples/ch25/archive_policy.py`.

```python
"""Manifest preflight only. No archive is opened or extracted."""
import json
import re


def load_manifest(raw):
    if len(raw) > 4096:
        raise ValueError("manifest_too_large")

    def pairs(items):
        result = {}
        for key, value in items:
            if key in result:
                raise ValueError("duplicate_json_key")
            result[key] = value
        return result

    def constant(value):
        raise ValueError("non_json_number")

    entries = json.loads(raw.decode("utf-8"), object_pairs_hook=pairs, parse_constant=constant)
    if not isinstance(entries, list) or not 1 <= len(entries) <= 5:
        raise ValueError("entry_count")
    return entries


def review_manifest(raw):
    entries = load_manifest(raw)
    seen = set()
    total = 0
    results = []
    for entry in entries:
        if not isinstance(entry, dict) or set(entry) != {"name", "kind", "compressed", "expanded"}:
            raise ValueError("entry_schema")
        name = entry["name"]
        compressed, expanded = entry["compressed"], entry["expanded"]
        if (not isinstance(name, str) or len(name) > 200 or type(compressed) is not int
                or type(expanded) is not int or not 1 <= compressed <= 4096 or expanded < 0):
            raise ValueError("entry_types")
        parts = name.split("/")
        folded = name.casefold()
        reason = "accept"
        if (not 1 <= len(parts) <= 3 or any(re.fullmatch(r"[A-Za-z0-9_-][A-Za-z0-9_.-]{0,63}", p) is None for p in parts)):
            reason = "unsafe_path"
        elif entry["kind"] != "file":
            reason = "not_regular_file"
        elif not name.endswith(".txt"):
            reason = "unsupported_entry"
        elif any(folded == old or folded.startswith(old + "/") or old.startswith(folded + "/") for old in seen):
            reason = "name_collision"
        elif not 1 <= expanded <= 64:
            reason = "entry_size"
        elif expanded > 20 * compressed:
            reason = "expansion_ratio"
        total += expanded
        if reason == "accept" and total > 128:
            reason = "total_expansion"
        seen.add(folded)
        results.append((name, reason))
    return {"entries": results, "declared_total": total,
            "archive_accepted": all(reason == "accept" for _, reason in results)}
```

Declared sizes count toward the reviewed total even for entries already refused for another reason. The entry results explain the policy decisions, while `archive_accepted=False` refuses the whole bundle. No path in the manifest is opened or created. Parser errors propagate as rejection; there is no fallback that reconstructs objects with a more permissive format.

The byte bound and small schema make this exercise manageable. A general-purpose hostile-data parser still needs explicit depth/node/time limits and a supported maintained runtime. These simple checks do not certify arbitrary JSON complexity or actual archive expansion.

## 4. JSON, XML, YAML and pickle trust assumptions when rebuilding objects

**Serialization** represents data as bytes or text. **Deserialization** rebuilds a representation in memory. The security question is not only whether the syntax parses. It is also what the parser may allocate, fetch, instantiate or execute, and which rebuilt values the application treats as authority.

**Table T25-04. Choose the reconstruction boundary**

| Format | Relevant behavior | Casebook decision |
| --- | --- | --- |
| JSON | Rebuilds ordinary values; duplicate keys, large/deep structures and permissive numeric extensions need explicit handling | Use bounded UTF-8 input, strict expected keys/types, duplicate rejection and semantic checks; do not load roles/paths as trusted authority |
| XML | Parser features and dependencies can affect entities, DTDs, expansion, XInclude or external resources | No XML import here; a future importer needs a maintained hardened configuration, disabled unneeded features and resource limits |
| YAML | Some loaders can construct language-specific objects; aliases and inferred types add complexity | No YAML import here; if required, choose a maintained safe loader such as `safe_load`, validate its output and bound alias/depth/resource behavior |
| Pickle | Unpickling can execute arbitrary code while reconstructing objects | Never unpickle attachments, browser data, partner data or untrusted queue messages |

Python's default Expat behavior does not itself imply arbitrary external network fetching. XML security depends on the actual parser, features, versions and integration. Inspect those settings rather than claiming that all XML APIs have the same behavior. “Safe YAML loader” likewise does not mean unlimited input is safe or that every returned value matches the product schema.

The manifest JSON parser rejects duplicate names inside objects before schema validation. It also uses exact integer types so `true` cannot act as the size `1`. Known fields do not become trusted merely because parsing succeeded: `name` remains an untrusted proposed path and `expanded` remains an unverified declaration.

A file can be valid text containing JSON, XML or YAML and still be stored only as text. Accepting it as a text attachment does not authorize importing its contents as configuration. An importer is a different operation with a separate schema, purpose and authority boundary.

A signed or authenticated container also does not automatically make pickle appropriate. Authenticity would need to cover the correct trusted producer, exact bytes, purpose and key custody; it does not make arbitrary object reconstruction necessary. Casebook's boundary here is simpler: attachment and archive inputs never invoke pickle. No executable pickle payload is needed to learn or test that design decision.

### Keep reconstructed data away from executable choices

Do not use deserialized values as Python class names, import targets, shell commands, arbitrary SQL identifiers or storage paths. Use a fixed mapping when a supported operation must be selected, then validate that operation's allowed data.

Chapter 26 will apply the same principle to partner responses and webhooks. A parser returning a dictionary is the start of application validation, not a complete trust decision.

```python
from io import BytesIO
import json
import os
from pathlib import Path
import sqlite3
from tempfile import TemporaryDirectory
import unittest
from unittest.mock import patch

from examples.ch23.authorization_service import AccessDenied
from examples.ch25.attachments import MAX_BYTES, Rejected, initialize, inventory, retrieve, upload
from examples.ch25.archive_policy import review_manifest


class AttachmentTests(unittest.TestCase):
    def setUp(self):
        self.folder = TemporaryDirectory(prefix="casebook-attachment-test-")
        self.addCleanup(self.folder.cleanup)
        self.database = Path(self.folder.name) / "casebook.sqlite3"
        self.root = Path(self.folder.name) / "private"
        initialize(self.database, self.root)

    def send(self, data, name="report.txt", stream=None):
        return upload(self.database, self.root, user_id=1, workspace_id=1, note_id=101,
                      display_name=name, media_type="text/plain",
                      stream=BytesIO(data) if stream is None else stream)

    def test_duplicate_display_names_retain_independent_bytes(self):
        first, second = self.send(b"one"), self.send(b"two")
        self.assertNotEqual(first, second)
        self.assertEqual(retrieve(self.database, self.root, user_id=1, key=first), ("report.txt", b"one"))
        self.assertEqual(retrieve(self.database, self.root, user_id=1, key=second), ("report.txt", b"two"))
        self.assertEqual(len(inventory(self.database, self.root)["objects"]), 2)

    def test_size_and_content_boundaries_leave_no_rejected_state(self):
        for size in (MAX_BYTES - 1, MAX_BYTES):
            key = self.send(b"A" * size)
            self.assertEqual(len(retrieve(self.database, self.root, user_id=1, key=key)[1]), size)
        for data in (b"A" * (MAX_BYTES + 1), b"prefix\x00bad", b"\x89PNG\r\n\x1a\n", b""):
            before = inventory(self.database, self.root)
            with self.assertRaises(Rejected):
                self.send(data)
            self.assertEqual(inventory(self.database, self.root), before)
            self.assertEqual(inventory(self.database, self.root)["staging"], [])

    def test_path_like_display_names_never_reach_storage(self):
        for name in ("../report.txt", "/report.txt", "dir\\report.txt", "C:report.txt", "bad\n.txt", "bad\ud800.txt"):
            before = inventory(self.database, self.root)
            with self.assertRaises(Rejected):
                self.send(b"data", name=name)
            self.assertEqual(inventory(self.database, self.root), before)

    def test_private_retrieval_and_unicode_name(self):
        key = self.send("گزارش".encode(), name="گزارش.txt")
        self.assertEqual(retrieve(self.database, self.root, user_id=1, key=key)[0], "گزارش.txt")
        for user in (None, 2):
            with self.assertRaises(AccessDenied):
                retrieve(self.database, self.root, user_id=user, key=key)

    def test_stream_failure_and_metadata_failure_cleanup(self):
        class BrokenStream:
            calls = 0
            def read(self, limit):
                self.calls += 1
                if self.calls == 1:
                    return b"partial"
                raise OSError("synthetic read failure")
        before = inventory(self.database, self.root)
        with self.assertRaises(OSError):
            self.send(b"", stream=BrokenStream())
        self.assertEqual(inventory(self.database, self.root), before)
        with sqlite3.connect(self.database) as db:
            db.execute("""CREATE TRIGGER fail_metadata BEFORE INSERT ON attachments
                          BEGIN SELECT RAISE(ABORT, 'synthetic metadata failure'); END""")
        with self.assertRaises(sqlite3.IntegrityError):
            self.send(b"valid")
        self.assertEqual(inventory(self.database, self.root), before)

    def test_key_collision_does_not_overwrite_or_remove_existing_file(self):
        with patch("examples.ch25.attachments.secrets.token_hex", return_value="a" * 32):
            key = self.send(b"original")
            before = inventory(self.database, self.root)
            with self.assertRaises(FileExistsError):
                self.send(b"replacement")
        self.assertEqual(inventory(self.database, self.root), before)
        self.assertEqual(retrieve(self.database, self.root, user_id=1, key=key)[1], b"original")

    def test_revocation_during_ingestion_prevents_publication(self):
        class RevokingStream(BytesIO):
            changed = False
            def read(inner, size):
                if not inner.changed:
                    with sqlite3.connect(self.database) as db:
                        db.execute("UPDATE memberships SET active=0 WHERE user_id=1 AND workspace_id=1")
                    inner.changed = True
                return super().read(size)
        with self.assertRaises(AccessDenied):
            self.send(b"", stream=RevokingStream(b"valid"))
        state = inventory(self.database, self.root)
        self.assertEqual((state["rows"], state["objects"], state["staging"]), ([], [], []))

    @unittest.skipUnless(hasattr(os, "O_NOFOLLOW"), "POSIX final-component link protection required")
    def test_final_symlink_is_not_followed_and_permissions_are_private(self):
        key = self.send(b"valid")
        target = Path(self.folder.name) / "outside.txt"
        target.write_bytes(b"outside secret")
        stored = self.root / "objects" / key
        self.assertEqual(stored.stat().st_mode & 0o777, 0o600)
        self.assertEqual(self.root.stat().st_mode & 0o777, 0o700)
        stored.unlink()
        stored.symlink_to(target)
        with self.assertRaises(OSError):
            retrieve(self.database, self.root, user_id=1, key=key)
        self.assertEqual(target.read_bytes(), b"outside secret")

    def test_manifest_policy_and_resource_budgets(self):
        def review(entries):
            return review_manifest(json.dumps(entries).encode())
        def entry(name, size=32, compressed=16, kind="file"):
            return dict(name=name, kind=kind, compressed=compressed, expanded=size)
        self.assertTrue(review([entry("report.txt"), entry("team/notes.txt")])["archive_accepted"])
        for candidate, reason in ((entry("../x.txt"), "unsafe_path"),
                                  (entry("a.txt", kind="symlink"), "not_regular_file"),
                                  (entry("a.zip"), "unsupported_entry"),
                                  (entry("a.txt", size=65), "entry_size"),
                                  (entry("a.txt", size=64, compressed=1), "expansion_ratio")):
            self.assertEqual(review([candidate])["entries"][0][1], reason)
        self.assertFalse(review([entry("a.txt"), entry("A.txt")])["archive_accepted"])
        total = review([entry("a.txt",64), entry("b.txt",64), entry("c.txt",1)])
        self.assertEqual(total["entries"][-1][1], "total_expansion")
        with self.assertRaises(ValueError):
            review([entry("a.txt", size=True)])
        with self.assertRaises(ValueError):
            review_manifest(b'[{"name":"a.txt","name":"b.txt"}]')


if __name__ == "__main__":
    unittest.main()
```

## Worked answers

### Exercise 1

Removing one prefix misses absolute paths, other separators and drive-like syntax. It also leaves duplicate-name overwrite behavior undefined and does not prevent symlink redirection. The implementation rejects unsafe display labels and never uses them for paths. The path component is a service-generated fixed-format key inside trusted private directories. Final-component no-follow handling still relies on protected ancestors and a supported storage backend.

### Exercise 2

The exact-boundary file commits one object and row. The 65-byte stream is rejected based on actual bytes, regardless of the claimed length; its staging file is removed and the earlier object remains unchanged. UTF-8 can encode one character with multiple bytes, so decoded character length measures a different resource. The service checks bytes before decoding and accepts only a bounded complete UTF-8 value.

### Exercise 3

For a handled insertion failure with successful compensation, roll back the new row, remove the final object created by this attempt and remove its staging name. Preserve every earlier object's bytes and metadata. Compare the full inventory and retrieve an older object where relevant. A crash can prevent the handler/finally cleanup from running; it needs a durable reconciliation mechanism and an orphan-state policy. A database transaction alone cannot make the filesystem commit atomic.

### Exercise 4

The extractor must validate actual entry metadata and count actual emitted bytes. Refuse the link/special entry or expansion overflow, close open handles and remove the entire uncommitted private extraction tree, including the earlier entry. Publish no partial archive and inspect final absence. The manifest review here performs no extraction, so it cannot supply that runtime evidence.

### Exercise 5

JSON rebuilt ordinary data, but client fields are trying to become trusted workspace/role authority; they must instead be checked against the authenticated caller and stored policy. An unsafe YAML loader may additionally reconstruct application objects, so the loader itself can cross an execution boundary before ordinary validation. A maintained safe loader and resource/schema checks address different parts of that problem. A `.txt` label changes neither the bytes nor what a later importer does with them. Casebook stores accepted text without automatically treating it as executable configuration.

## What you can now explain

An attachment's label, bytes, internal key and permission are separate facts. A controlled upload stages and bounds actual bytes, validates its narrow content contract and publishes only under current authority. Refusal must leave inspectable final state. Archives add path/type/expansion boundaries, and deserialization adds a separate question about what input may rebuild or execute.
